# 엄격 외부 후보는 현재 313개 위에 사전 고정 사다리로 판정한다

[ADR-0005](0005-strict-external-member-nested-selection.md)는 자체 35개를 필수 시작 구성으로 두고 엄격 외부 후보만 정확 검색으로 고르는 후보 절차 팔을 현재 313개 비교 팔과 견주도록 정했다.
도구를 만들어 예행하자([#486](https://github.com/tmheo/predicting-smartphone-addiction/issues/486)) 그 절차 팔은 비교 팔을 구조적으로 넘을 수 없음이 드러났다.
자체 35개의 nested OOF는 `0.9698106`이고 313개는 `0.9703509`인데, 그 격차 `+0.00054`의 대부분은 검증하지 않은 기존 외부 209개의 기여 `+0.00051`이며, 엄격 후보 19개 가운데 11개는 313 안에 이미 있는 구성원의 재감사 기록이라 새 정보는 8개뿐이다.
자체 35개에서 출발하는 절차 팔은 지도의 목적지인 "현재 두 번째 장을 넓힌 판"과도 어긋난다.
2026-08-28 사용자 결정으로 정확 검색을 접고, 현재 313개 위에 동결 후보를 더한 구성을 [#455](https://github.com/tmheo/predicting-smartphone-addiction/issues/455)식 사전 고정 nested OOF 사다리로 재어 교체 문턱을 판정한다.

## 개정 2026-08-28 (#498): 비교 팔의 결합기와 기준값

같은 날 [#489](https://github.com/tmheo/predicting-smartphone-addiction/issues/489)에서 두 번째 최종 제출이 규제 강도 선택판 `30b6f97c`로 바뀌었다.
구성원 313개와 순서는 그대로이고, 결합기가 C=1.0 고정 `shrunk_rank_logit_logistic`에서 규제 강도 C와 수축 계수 λ를 안쪽 leave-one-fold-out으로 함께 고르는 `CSelectedShrunkRankLogitCombiner`로 바뀌었다(전체 OOF 선택 C=0.03, λ=1.0, nested `0.9703609`).
따라서 이 계약의 고정 결합기는 `CSelectedShrunkRankLogitCombiner`(C 격자 7개, λ 격자 4개, 동률이면 작은 C·작은 λ)이고, 비교 팔 자기 검사의 기준값은 #489 `comparison.json`의 후보 nested `0.9703609`와 분할별 AUC다.
사다리 구성, 문턱, 선택 규칙은 바뀌지 않는다.
분할 하나의 적합이 로지스틱 29회라 작업 시간은 C=1.0판의 약 1.6배(313열 분할당 약 14분)다.
아래 본문의 `0.9703509`, `#455` 기준, `443b3a71`은 이 개정 전의 값이며 개정 뒤에는 위 값으로 읽는다.

## 결정

### 유지하는 것

- 비교 팔은 현재 313개 확장 구성이며 바꾸지 않는다.
- 교체 문턱은 313개 대비 이어붙인 nested OOF AUC `+0.00002` 이상과 바깥 분할 5곳의 AUC 차이 모두 엄격히 양수다.
- 외부 후보 동결 명세(`scripts/freeze_external_candidates.py`)는 그대로 입력이다.
  자격 있는 현행 감사 기록은 전체 OOF 성능이나 근접 중복을 이유로 동결 전에 빼지 않으며, 2026-08-30 증분 후보는 결과 확인 전에 명세 끝에 더한다.
- 결합 전략은 고정 `shrunk_rank_logit_logistic` 하나다.
- nested OOF는 바깥 분할 하나를 봉인하고 나머지 4개 분할의 행으로 결합기를 맞춰 봉인 분할을 예측한 뒤 5개 예측을 원래 행 순서로 이어붙여 채점한다.
  결합기는 원래 행 순서를 지켜 학습한다.
- 동결 명세, folds, 자체 35개 구성, 313개 구성, 후보 배열의 내용 해시, 사다리 구성 목록, 선택 규칙, 문턱과 코드 상태를 결과 확인 전에 `precommit.json`에 고정한다.
- 공개 점수는 어느 단계에도 쓰지 않는다.
- 계산 하나라도 실패하거나 끝나지 않으면 완료한 일부 결과를 쓰지 않고 전체를 판정 불가로 두며, 모든 입력 해시와 코드 상태가 정확히 같을 때만 재개한다.
- 문턱 통과 뒤 조립, Kaggle 업로드와 최종 두 장 수동 고정은 사용자가 다시 승인해야 한다.

### 접는 것

- 자체 35개 필수 시작 구성의 후보 절차 팔, 순방향 추가·단일 원자 교체·후방 제거·쌍 추가의 정확 검색, 검색 풀 점수, 동률 규칙과 정지 규칙을 접는다.
- 후보 풀 중복 불변식을 사다리에 적용하지 않는다.
  스피어만 `0.998` 규칙은 자체 후보 풀 진입(전체 OOF)에서만 적용하며, 사다리는 자체 35개와 313개를 바꾸지 않으므로 자체끼리, 313끼리, 후보와 313 사이의 `0.998` 이상 쌍은 열린 4개 분할의 진단값으로만 기록한다.
  예행에서 드러난 자체 `exp131_lookup_bivariate_plr5`·`exp157_lookup_muon_initavg8` 쌍(분할 0 봉인 시 `0.998102`)은 이 규칙으로 처리된다.
- 절차 통과 뒤 전체 OOF에 검색을 다시 적용해 제안 명단을 만드는 단계와 선택 안정성 기록을 접는다.
  제안 구성은 사다리에서 선택 규칙이 고른 구성 그 자체다.

### 정확 중복과 사다리 후보

- 동결 후보 가운데 예측 쌍 SHA-256이 313개 구성원 하나의 예측 쌍 SHA-256(float64 정규화 배열 기준)과 같으면 정확 중복 후보다.
- 정확 중복 후보는 사다리 후보에서 자동으로 빠지고 `precommit.json`에 대응 구성원과 함께 기록된다.
  현재 19개 가운데 판본 2 재감사 11개(`nb_zhukov` 3, `nb_reda` 2, `nb_yekenot`, `nb_mohan_realmlp`, `nb_lopure` 3, `nb_shaman_baseline`)가 여기에 해당하며 예측 쌍 해시가 313 안의 같은 이름 구성원과 일치함을 확인했다.
- 근접 중복(스피어만 `0.998` 이상)은 정확 중복이 아니므로 사다리 후보에 남고 주의 사항 부류 절제로 기여를 잰다.
- 정확 중복을 뺀 뒤 사다리 후보가 하나도 없으면 사다리를 실행하지 않고 현재 두 장 유지를 완결된 결론으로 기록한다.

### 사다리 구성

사다리는 규칙으로 정하고, 실제 구성 목록은 동결 명세에서 도구가 결정적으로 만들어 `precommit.json`에 고정한다.
구성원 열 순서는 313개 manifest 순서 뒤에 동결 명세 순서다.

- 시작 조건, 비교 팔 자기 검사: 판정 도구가 313개의 봉인 분할 예측 5개를 다시 만들어 이어붙인 AUC와 분할별 AUC가 #455의 `0.9703509`와 분할별 값에 잡음 바닥 `5.7e-06` 안에서 맞아야 한다.
  이것은 사다리 구성이 아니라 도구가 313 행렬을 같은 열 순서·행 순서·정밀도로 읽는지의 검사이며, 맞지 않으면 판정 불가다.
  이 봉인 예측이 분할별 비교의 기준이다.
- 전체 구성 `ext313_strict_all`: 313개에 정확 중복을 뺀 사다리 후보 전부를 더한 구성.
- 출처 절제 `ablate_source_<출처>`: 전체 구성에서 출처 하나의 후보를 모두 뺀 구성을 출처마다 하나씩 둔다.
  출처는 고정 공개 판본의 작성자 단위다.
- 주의 사항 절제 `ablate_caveat_<부류>`: 전체 구성에서 주의 사항 부류 하나를 가진 후보를 모두 뺀 구성을 부류마다 하나씩 둔다.
  사다리 후보 전원이 공통으로 가진 부류(현재 `license_unknown_use_limited`)는 절제하면 313과 같아지므로 두지 않는다.
- 구성원 집합이 앞선 구성과 같은 구성은 하나만 남긴다.
  현재 후보로는 `rehosted_training_data_private_notebook` 절제가 `ablate_source_ravi20076`와 같아 생략된다.
- 현재 8개 후보(beicicc 2, busyaprime 3, ravi20076 3)로는 전체 구성 1, 출처 절제 3, 주의 사항 절제 2(`float32_storage` 5개, `near_duplicate_cluster` 4개)의 6구성이다.
  증분 후보가 더해지면 같은 규칙으로 늘어난다.
- 후보 하나씩 더한 구성은 두지 않는다.

### 판정과 선택 규칙

- 구성마다 nested OOF AUC, 가중 OOF AUC, 313 대비 이어붙인 AUC 차이와 분할별 AUC 차이를 기록한다.
  가중 OOF는 진단값이며 판정에 쓰지 않는다.
- 이어붙인 AUC 차이가 `+0.00002` 이상이고 분할 5곳의 차이가 모두 엄격히 양수인 구성만 문턱을 통과한다.
- 통과 구성이 여럿이면 nested OOF가 가장 높은 구성을 고르되, 최고 구성과의 차이가 잡음 바닥 `5.7e-06` 안이면 그 가운데 구성원 수가 가장 적은 구성을 고른다.
  구성원 수까지 같으면 사다리 순서가 앞선 구성을 고른다.
- 통과 구성이 없으면 현재 두 장(`e88f706e` + `443b3a71`) 유지가 완결된 결론이다.
- 사다리 구성, 선택 규칙과 문턱은 결과 확인 전에 고정하고 결과를 본 뒤 더하거나 빼지 않는다.
- ravi20076 v1의 `rehosted_training_data_private_notebook` 주의 사항을 `확인됨`으로 둘지 `근거 부족`으로 볼지는 자격 판단이므로 동결 전에 사용자가 정한다.
  결과를 본 뒤 그 주의 사항을 이유로 구성을 고르거나 빼지 않는다.

### 제안 구성과 조립

- 선택한 구성이 엄격 외부 제안 구성이다.
- 조립은 [#444](https://github.com/tmheo/predicting-smartphone-addiction/issues/444) 규칙대로 전체 OOF에 결합기를 한 번 맞추며, 자체 35개의 시험 예측은 5:1 혼합판, 후보는 동결 명세의 정규화 시험 배열이다.

### 변경 불가 산출물

- `precommit.json`은 동결 명세 해시, folds·자체 35·313·후보 배열 해시, 정확 중복 후보와 대응 구성원, 사다리 구성 목록과 각 구성의 구성원 열, 결합기, 문턱, 선택 규칙과 코드 상태를 담는다.
- `fold-<k>/baseline-predictions.parquet`과 `fold-<k>/baseline.json`은 비교 팔 자기 검사의 봉인 분할 예측과 AUC다.
- `ladder/<구성>/fold-<k>/predictions.parquet`과 `ladder/<구성>/nested.json`은 구성별 봉인 분할 예측, 이어붙인 AUC, 가중 OOF AUC와 분할별 AUC다.
- `ladder-comparison.json`은 자기 검사 결과, 구성별 313 대비 차이와 분할 부호, 문턱 판정, 선택 규칙 적용과 제안 구성을 담는다.
- `report.md`는 사람이 검토하는 요약이고 `manifest.sha256`은 모든 판정 산출물의 내용 해시를 묶는다.
- ADR-0005의 `fold-<k>/selection.json`, `selection-stability.json`, `full-selection.json`은 만들지 않는다.

## 결과

- 후보 절차 팔이 비교 팔보다 낮은 곳에서 출발하는 구조적 불리함이 사라지고, 판정이 지도 목적지인 "현재 판을 넓힌 판"을 직접 잰다.
- 계산량이 정확 검색보다 작고 예측 가능하다.
  구성 하나가 320열 안팎 shrunk nested 1회(45분에서 1시간)이며 400열대 작업의 동시 상한 3개 규칙을 따른다.
- 후보 하나의 개별 기여는 출처·부류 절제로만 읽히며 후보별 절제는 하지 않는다.
- 근접 중복 후보가 313 구성원과 함께 남을 수 있으나 이는 313 자체가 이미 근접 중복 군집을 포함하는 것과 같은 상태다.
- ADR-0005의 정확 검색 도구(`select`·`full`)는 계약이 되살아날 때를 위해 보존하고 사다리 판정에서는 쓰지 않는다.
- [#478](https://github.com/tmheo/predicting-smartphone-addiction/issues/478)의 결정 가운데 후보 절차 팔, 정확 검색, 중복 불변식, 전체 OOF 제안 명단과 선택 안정성은 이 결정으로 대체되고, 동결 입력·문턱·공개 점수 미사용·판정 불가 규칙은 유지된다.
  [#481](https://github.com/tmheo/predicting-smartphone-addiction/issues/481)의 실행 인계 완결 조건 가운데 "자체 35개를 후보 절차 팔의 제거 불가 시작 구성으로 삼는 입력 명세", "결정적 검색·동률 해소·상관 충돌·중단 규칙", "분할별 선택·선택 안정성·전체 OOF 제안 명단" 항목은 각각 "313개와 사다리 후보의 입력 명세", "사다리 구성 목록·선택 규칙", "비교 팔 자기 검사·구성별 봉인 예측·사다리 비교"로 바뀌며 나머지는 그대로다.

## 기각한 대안

- 313개를 시작 구성으로 두고 ADR-0005의 정확 검색을 그대로 돌리는 안은 적합당 수십 초, 프로세스당 15GB대라 08-30 실행 창에 들어가지 않고, 후보 8개에 대한 검색이 사다리 절제보다 더 알려 주는 것이 없어 기각한다.
- 후보 하나씩 더한 구성을 사다리에 넣는 안은 구성이 후보 수만큼 늘어 시간이 세 시간 이상 더 들고, 개별 기여는 출처·부류 절제로 충분히 읽히므로 기각한다.
- 비교 팔 자기 검사를 생략하고 #455 저장값을 기준으로 쓰는 안은 도구가 313 행렬을 다르게 읽을 때 그 차이가 그대로 가짜 델타가 되므로 기각한다.
  #486에서 행 순서만으로 봉인 예측이 `7.96e-04`까지 달랐다.
- 313 구성원과 근접 중복인 후보를 사다리 전에 빼는 안은 단독 성능이나 중복성으로 미리 제거하지 않는다는 원칙과 충돌하고 대표 선택 규칙을 따로 요구하므로 기각한다.
- `rank_logit_logistic`을 함께 재는 안은 #337·#443·#455 모두 shrunk가 최선이고 λ=1이라 시험 예측이 같으며 작업 수만 두 배가 되므로 기각한다.
