# 후보 풀 재구축과 신규 모델 선택의 평가 경계를 분리한다

현재 후보 풀은 고정된 OOF 예측을 다시 선택하는 절차이고, 신규 모델 선택은 바깥쪽 채점 분할의 목표값이 모델 학습과 학습 상태 선택에도 닿지 않아야 하는 절차다.
두 평가를 모두 선택 편향 없는 nested OOF라고 부르면 현재 풀 재구축의 보증을 과장하고 구현 경계도 흐려진다.
따라서 일회성 후보 풀 재구축, 지속 등록과 신규 모델 선택을 서로 다른 계약으로 운영한다.

## 결정

### 계약 경계

- 현재 풀을 한 번 다시 만드는 계약은 `candidate-pool-rebuild-v1`이다.
- 재구축이 끝난 뒤 후보 하나를 지속 등록하는 계약은 기존 `candidate-pool-v2`다.
- `candidate-pool-v2`는 이미 핵심 결합 전략 3개를 기본값으로 사용하므로 같은 이유로 v3를 만들지 않는다.
- 신규 모델의 설정과 후보 학습 시점 선택은 완전 중첩 절차로 평가한다.
- 현재 풀 재구축의 평가는 동결 OOF 조건부 절차 점수이며 완전 중첩 절차 점수가 아니다.

### 재구축 입력과 검색

- 재구축 후보 집합은 고정 champion `exp156_lookup_bivariate_plr5_initavg8` 실행 `6911a461866b43dc9556553eba6783b7`과 2026-08-25의 현재 32개 풀로 고정한다.
- champion은 필수 시작 구성원이며 나머지 32개는 선택 후보다.
- 현재 32개 풀은 재구축 결과를 채택하지 못할 때 유지할 공식 비교 기준이다.
- 무결성, 채택 자격과 전체 자료 재학습 가능성은 OOF 검색 전의 필수 조건이다.
- 검색이 만든 모든 결과 풀은 모든 구성원 쌍의 스피어만 순위 상관이 `0.998` 미만인 후보 풀 중복 불변식을 만족해야 한다.
- 빠른 다중 후보 검색은 `shrunk_rank_logit_logistic` 하나만 사용한다.
- 전진 추가를 양의 이동이 없을 때까지 반복하고, 역방향 제거를 양의 이동이 없을 때까지 반복한 뒤 전진 추가를 다시 수렴시킨다.
- 그 뒤 남은 후보의 순서 없는 2개 묶음을 한 번 전수 평가한다.
- 가장 좋은 2개 묶음이 양수면 원자적으로 추가하고 전진 추가와 역방향 제거를 다시 수렴시킨 뒤 종료한다.
- 안전성이 증명되지 않은 대리 점수, 상위 일부 선별과 가지치기는 사용하지 않는다.
- 추가, 제거, 원자 교체와 2개 묶음 추가는 전체 AUC 차이가 엄격히 양수일 때만 허용한다.
- 성능 동등 대역과 바깥 분할 승수는 경계 기여와 선택 불안정성 경고로만 기록한다.
- 이동의 AUC 차이가 같으면 동결한 재구축 후보 집합의 순서로 결정한다.

실제 33개 OOF에서 중복 문턱 `0.998`을 넘는 관계는 `exp131_lookup_bivariate_plr5`와 `exp157_lookup_muon_initavg8` 한 쌍뿐이다.
두 실행은 상호 배타 후보군으로 두고 어느 한쪽도 결과 확인 전에 제거하지 않는다.
둘 다 선택되지 않은 상태에서는 각각의 추가를 평가하고, 하나가 선택된 상태에서는 다른 하나로 바꾸는 원자 교체를 평가하며, 두 실행을 동시에 담는 이동만 금지한다.
2개 묶음 검색에서도 둘을 함께 담은 묶음은 제외하되 각각과 다른 후보의 조합은 모두 평가한다.

### 절차 평가와 최종 제안 풀

- 바깥쪽 채점 분할마다 나머지 분할의 동결 OOF에서 재구축 검색 전체를 다시 실행해 동결 OOF 조건부 절차 점수를 만든다.
- 분할별로 선택된 풀은 절차 점수와 선택 안정성 진단에만 사용한다.
- 공식화 후보는 전체 동결 OOF에서 한 번 실행한 단일 재구축 제안 풀이다.
- 분할별 풀을 투표, 교집합 또는 합집합으로 합쳐 공식화 후보를 만들지 않는다.
- 재구축 제안 풀의 조건부 절차 점수가 현재 32개 풀보다 엄격히 높아야 한다.
- 동결한 재구축 제안 풀과 현재 32개 풀을 `candidate-pool-v2` 핵심 결합 전략 3개로 직접 비교한 차이도 엄격히 양수여야 한다.
- 시간 초과나 계산 실패는 판정 불가이며 완료한 일부 결과로 후보 풀을 바꾸지 않는다.
- 각 이동은 현재 풀, 평가한 모든 이동, 점수, 선택 결과와 입력, OOF, fold, 결합 전략, 코드 해시를 변경 불가 산출물로 남긴다.
- 모든 해시가 같을 때만 중단 지점에서 이어서 실행한다.

### 전체 자료 재학습 예행과 공식화

- 재구축 검색은 제안 풀을 만들 뿐 공식 `artifacts/pool.yaml`을 즉시 바꾸지 않는다.
- 제안 풀에 묶인 준비 상태의 재학습 계획을 만들고 계획 전체를 검증한 뒤 이슈 #226의 전체 자료 재학습 스모크 예행을 실행한다.
- 재구축 전용 작업 가지에서 제안 풀과 그 재학습 계획을 공식 경로에 함께 기록한 재구축 제안 커밋을 만든다.
- #226 대상은 제안 풀과 이슈 #66 완주 집합의 `(config, source_run_id)` 차집합이다.
- 같은 신원이어도 재학습 경로를 바꾸는 구현 변경이 있으면 과거 완주 증거를 다시 사용하지 않는다.
- #226은 재구축 제안 커밋에서 실행하고 기본 가지의 현재 풀과 재학습 계획은 바꾸지 않는다.
- #226이 모두 통과한 뒤 재구축 제안 커밋을 기본 가지에 반영해 풀 장부와 재학습 계획을 함께 공식화한다.
- #226 결과는 경로 검증 증거이며 이슈 #69의 최종 제출용 생산 실행을 대신하지 않는다.
- 2026-08-28 UTC까지 재구축과 #226을 모두 마치지 못하면 현재 32개 풀과 기존 재학습 계획을 공식 기록으로 유지한다.

### 신규 모델 선택

- 신규 모델 선택은 #226 뒤에 수행한다.
- 후보 설정과 실제 학습 길이는 결과 확인 전에 고정한다.
- 같은 검증 목표값으로 고른 조기 종료 상태를 후보 학습 시점으로 사용하지 않는다.
- 바깥쪽 5개 분할마다 그 학습 부분 안에서 다시 4개 분할을 구성해 모델 학습, 설정 선택, 후보 학습 시점 선택과 결합 방식 선택을 모두 다시 수행한다.
- 첫 판본은 기존 분류 손실을 유지하고 설정과 후보 학습 시점만 후보 풀 기여로 고른다.
- 현재 풀의 잔여 오차를 학습 목표나 표본 가중치에 직접 반영하는 방법은 후속 계약으로 미룬다.

## 결과

- 즉시 실행 경로는 #409, #410, 재구축 구현과 실행, 제안 풀용 재학습 계획, #226 순서다.
- #412는 현재 풀 재구축 발주와 신규 모델 발주를 분리하고, 신규 모델 계약 #411은 #226 뒤로 옮긴다.
- 현재 풀 재구축은 기존 OOF를 활용해 계산량을 억제하지만 기초 모델 생성과 과거 후보 선택의 편향까지 제거했다고 주장하지 않는다.
- 신규 모델 선택은 계산량이 더 크더라도 바깥쪽 채점 분할의 목표값이 모든 선택에서 격리되는 완전 중첩 보증을 유지한다.

## 기각한 대안

- 핵심 결합 전략 3개 사용을 위해 `candidate-pool-v3`를 만드는 안은 v2가 이미 같은 기본값을 정의하므로 기각한다.
- 재구축 검색에서 등록 결합 전략 19개를 모두 실행하는 안은 과거 선택되지 않은 16개 전략의 비용을 반복하므로 기각한다.
- 단독 AUC나 모델 계열로 후보를 미리 줄이는 안은 풀 한계 기여가 있는 후보를 놓칠 수 있으므로 기각한다.
- 분할별 선택 빈도로 최종 풀을 만드는 안은 평가한 절차와 실제 공식화 절차를 다르게 만들므로 기각한다.
- #226 전에 재구축 풀을 공식 장부에 반영하는 안은 재학습할 수 없는 풀과 계획의 불일치가 공식 상태가 될 수 있으므로 기각한다.
- 제안 풀과 재학습 계획을 별도 임시 경로로 전달하는 안은 기존 검증 경로와 다른 실행 계약을 추가하므로 기각한다.
