# 전체 자료 재학습과 시험 예측 혼합 규약

이슈 #66의 결정이다.

후보 풀 구성원과 후보 풀 재심사에서 선택한 결합 방식을 최종 제출 후보로 옮길 때, 교차 검증 시험 예측만 쓸지 전체 자료로 다시 학습한 예측을 쓸지 재현 가능한 규약이 필요하다.

## 결정

- 재학습 대상은 `artifacts/pool.yaml`의 현재 구성원이며 구성원 순서와 원본 실행 ID를 바꾸지 않는다.
- 현재 기준은 이슈 #346에서 확정한 32개 구성원이다.
  35개 기준에서 `exp107_logreg_onehot_nn10`, `exp108_logreg_onehot_nn10_l1`, `exp033_recon_orig_mean_top3_raw`을 제거했고 전체 자료 재학습은 99회에서 94회로 줄었다.
- 확률적 모델은 확정 재검증 시드 `[42, 43, 44]`를 각각 전체 자료로 재학습하고 확률을 평균한다.
- `lbfgs`로 맞추는 `exp058_logreg_onehot`은 난수 시드가 결과를 바꾸지 않으므로 시드 42 한 번만 재학습한다.
- 반복형 모델의 시드별 재학습 예산은 해당 시드의 관측 학습 길이 중앙값에 `1.25`를 곱한 뒤 사사오입한다.
- 배수 `1.25`는 각 5-fold 모델이 전체 훈련 자료의 80%를 본 데 비해 전체 자료 모델은 100%를 보는 비율이다.
- 학습 길이 개념이 없는 `exp058_logreg_onehot`과 `exp067_tabpfn3`에는 별도 반복 수를 주지 않는다.
- `exp065_tabm`은 별도 재검증에서 바깥쪽 시드별 5개 분할과 내부 구성원 3개가 선택한 학습 길이 15개를 기록했으며, 시드별 중앙값 `13`, `13`, `12`에 같은 `1.25`를 적용해 사사오입한 `16`, `16`, `15` epoch를 사용한다.
- TabM 전체 자료 경로는 `pytabkit 1.7.3`의 전처리와 TabM 모형 구현을 재사용하되, 라이브러리가 구현하지 않은 검증 집합 없는 재학습 제어를 별도로 소유한다.
- fold-fit 피처 제공자는 전체 훈련 자료로 상태를 맞추되, 타깃 인코더가 학습 행에 돌려주는 값은 내부 OOF 표현을 유지한다.
- 구성원별 기존 5-fold 시험 예측 평균과 전체 자료 예측은 모델 수 가중치 `5:1`로 섞는다.
- `5:1` 혼합은 여섯 학습 모델 각각에 같은 가중치를 주며, 전체 자료 모델 하나가 기존 fold 모델 다섯 개를 절반씩 덮어쓰는 것을 피한다.
- 결합 전략은 재학습 계획의 `protocol.combiner`가 가리키는 등록 방식을 사용한다.
  현재 방식은 `shrunk_rank_logit_logistic`이며, 전체 OOF 안의 leave-one-fold-out으로 수축 계수를 고른 다음 전체 OOF로 한 번 맞춰 CV 전용, 전체 자료 전용, `5:1` 혼합 시험 행렬에 각각 적용한다.
  등록부에 없는 이름은 전체 자료 재학습이나 조립 전에 거부한다.
- 최종 제출 후보 검토에는 CV 전용과 `5:1` 혼합 예측을 넘기고, 전체 자료 전용 예측은 차이 진단용으로 보존한다.
- Public 점수는 두 후보 가운데 하나를 다시 선택하거나 재학습 규약을 수정하는 근거로 쓰지 않는다.

## 학습 길이의 의미와 재학습 예산 계산

이슈 #326, #327, #329의 결정을 이슈 #371에서 반영했다.

세 값을 서로 다른 것으로 구분한다.

- 원시 선택값은 모델 연결부가 학습 엔진에서 그대로 읽은 수다.
- 관측 학습 길이는 바깥쪽 분할 하나에서 실제로 돈 반복 횟수이며 1 이상의 정수다.
- 재학습 예산은 전체 자료 재학습 하나에 넘길 시드별 최종 반복 횟수다.

### 원시 의미 변환

원시 선택값은 그대로 쓸 수 없다.
같은 `best_epoch`라는 이름이 계열에 따라 0부터 세는 위치이기도 하고 1부터 세는 횟수이기도 하다.
그래서 각 모델 계열이 자기 원시 선택값에 대해 `zero_based_position`, `one_based_count`, `fixed_count` 가운데 하나를 선언한다.

- `zero_based_position`은 0부터 세는 위치이므로 `+1`해 관측 학습 길이로 바꾼다.
- `one_based_count`는 학습 엔진이 이미 센 실제 횟수이므로 값이 바뀌지 않는다.
- `fixed_count`는 검증으로 고른 값이 아니라 설정이 고정한 실제 횟수이므로 값이 바뀌지 않는다.

현재 `zero_based_position`을 선언하는 계열은 XGBoost, CatBoost, Lookup-Transformer 셋이다.
불리언, 정수가 아닌 값, 음수 위치, 0 이하 횟수, 알 수 없는 원시 의미와 이미 바꾼 값의 중복 변환은 모두 거부한다.

### 재학습 예산 계산

시드마다 그 시드의 관측 학습 길이 전부의 중앙값 `M`을 구하고 `floor(1.25 * M + 0.5)`를 재학습 예산으로 쓴다.
사사오입은 양수에만 정의하며, 파이썬 기본 `round`의 짝수 붙임과 달리 `12.5`는 `13`이 된다.
내부 구성원이 있는 계열은 분할과 내부 구성원 좌표의 관측을 모두 같은 중앙값에 넣는다.
고정 일정 계열도 설정 횟수를 예산으로 바로 쓰지 않고 `fixed_count` 근거로 기록한 뒤 같은 계산을 거친다.
반복 수가 없는 구성원은 관측 없이 예산도 없다.

### 책임 경계

- 모델 계열 연결부가 원시 의미 선언과 원시 근거 기록을 소유한다.
- 공통 계산부가 원시 의미 변환과 재학습 예산 산정을 소유한다.
  공통 계산부는 모델 계열 이름이나 원시 필드 이름을 해석하지 않고, 호출자가 선언한 원시 의미와 원시 값만 검증한다.
  저장, 장부 읽기, 실행 저장소 조회와 모델 실행은 하지 않는다.
- 재학습 계획 장부가 근거 계보 보존과 실행 관문을 소유한다.
  장부를 불러올 때 원시 근거에서 예산을 다시 계산하고 저장값과 정확히 같을 때만 실행한다.
  손으로 바꾼 예산과 예외 필드는 장부 문법에 두지 않는다.

### 장부의 문법과 관문

이슈 #373에서 장부의 문법과 관문을 `pipeline.refit_plan`이 소유하게 했다.
`RefitPlan.load()`는 파일 밖의 무엇도 읽지 않고 문법만 보며, 알 수 없는 필드와 빠진 필드를 그 자리에서 거부한다.
`validate_for_refit()`는 실행 저장소에서 근거 산출물을 읽어 계보를 맞춰 보고, 원시 값을 다시 변환하고, 재학습 예산을 다시 계산해 저장값과 정확히 같을 때만 실행 가능한 계획을 돌려준다.
파생 재학습 예산을 노출하는 자료형은 그 반환형 하나뿐이므로, 검증을 건너뛴 계획으로는 전체 자료 재학습을 시작할 수 없다.
실행 저장소의 산출물은 `RunStore` 계약으로만 읽고 MLflow 내부 경로를 직접 열지 않는다.

구성원마다 `lineage`, `training_length_evidence`, `refit_budget_derivation` 세 묶음을 보존한다.
반복 수가 없는 구성원은 `not_applicable` 상태와 빈 예산만 허용하고, 고정 일정 계열도 `fixed_count` 근거를 같은 계산에 통과시킨다.
손으로 바꾸는 예산과 예외 필드는 문법에 두지 않는다.
현행 `artifacts/full-refit-plan.yaml`은 아직 이전 문법이며, 32개 구성원의 근거 자료 입력과 실행 명령 연결은 후속 이슈에서 수행한다.

### 위 이력 숫자와의 관계

이 문서에 이미 적힌 구성원별 숫자 가운데 일부는 XGBoost, CatBoost, Lookup-Transformer의 원시 위치를 `+1`하지 않고 계산한 값이다.
이슈 #327의 원시 근거 복원으로 `exp111_xgb_depth8_no_te`, `exp071_cat_exact_no_te`, `exp127_lookup_muon`, `exp135_xgb_hpo_trial30`, `exp131_lookup_bivariate_plr5` 다섯 구성원이 확정 계산과 다르다는 것이 드러났다.
장부 자료 교정은 재학습 계획 장부 이슈에서 수행하며, 이 문서의 이력 문장은 당시 기록으로 남긴다.

## 결과 무결성

- 재학습은 깨끗한 git 커밋에서만 실행한다.
- 계획은 후보 풀 파일의 SHA-256과 구성원 순서 및 실행 ID가 현재 장부와 같은지 시작 전에 검증한다.
- 구성원별 manifest에는 설정과 입력 자료 해시, 원본 실행 ID, git 커밋, 시드별 재학습 예산, 예측 배열 SHA-256을 기록한다.
- 시험 예측은 원본 ID 순서, `float64` 정밀도, 유한값을 검증한 뒤 원자적으로 저장한다.
- 최종 조립 manifest에는 세 예측의 배열 SHA-256과 구성원별 CV 대 전체 자료 예측의 스피어만 순위 상관을 기록한다.

## 기각한 대안

- 전체 자료 예측만 사용하면 이미 선택 편향 없이 평가한 다섯 fold 모델의 안정성을 모두 버리므로 기각했다.
- CV와 전체 자료 예측을 `1:1`로 평균하면 전체 자료 모델 하나가 fold 모델 다섯 개를 합친 것과 같은 가중치를 받아 과도하므로 기각했다.
- fold별 최적 길이의 최댓값을 사용하면 일부 긴 꼬리가 전체 자료 학습을 지배하므로 기각했다.
- 평균은 긴 꼬리의 영향을 받으므로 시드별 중앙값을 선택했다.
- Public 점수로 혼합 비율이나 후보를 다시 고르면 공개 평가 자료에 맞춘 선택이 되므로 기각했다.
