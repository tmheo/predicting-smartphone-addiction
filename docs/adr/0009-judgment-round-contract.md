# 판정 회차 계약은 >= fold 승수 게이트, 이슈 기반 회차 id, 명시 자기 검사 등급, 게시 폴더 기준 manifest, 게이트 밖 회차 고유 규칙으로 고정한다

스택 교체 판정 스크립트 5곳(judge_issue508, judge_issue513, judge_issue526, 엄격 외부 사다리, 규제 강도 선택)이 봉인 → 실행 → 비교 → 보고 → 게시의 같은 골격을 이슈마다 약 700~970줄로 재구현했다.
판정 규칙의 정본은 `judgment.judge_stack_replacement`(StackGate·StackVerdict, #551)가, 회차 오케스트레이션은 `pipeline.round`의 JudgmentRound(#552)가 소유하게 됐고, 이슈별로는 RoundSpec을 조립하는 스펙 스크립트 약 80~140줄만 남는다.
이 ADR은 그 판정 회차 계약 가운데, 맥락 없이 보면 의아하지만 실제 절충의 결과이고 되돌리기 어려운 다섯 결정을 남긴다.
용어 정의(판정 회차, 회차 자기 검사)는 CONTEXT.md가 소유한다.

## 결정

### 표준 게이트의 fold 승수 비교는 >=다

- 게이트는 `delta >= 문턱` 그리고 `양수 fold 수 >= 요구 수`의 두 조건이다.
- delta 문턱은 별도 상수(GATE_DELTA)가 아니라 `judgment.AUC_THRESHOLD`를 재사용한다.

기존 스크립트는 fold 승수 비교가 `==`와 `>=`로 갈라져 있었다.
두 형태는 요구 수가 분할 수와 같은 5/5에서만 우연히 같은 답을 냈고, 요구 수를 5 미만으로 낮추는 순간 `==`는 5/5 만점 결과를 미달로 뒤집는 함정이었다.
`>=`만이 "요구 수 이상이면 통과"라는 의도를 문턱 값과 무관하게 보존한다.
GATE_DELTA는 조사 시점에 AUC_THRESHOLD의 여섯 번째 사본이었고, 사본은 문턱 개정 시 갈라질 또 하나의 함정이라 재사용으로 없앤다.

### 회차 id는 내용 해시가 아니라 <주제 슬러그>/<이슈 번호>다

- 회차 id는 `<주제 슬러그>/<이슈 번호>` 두 분절이다(예: `judgment-round-pilot/issue553`).
- id가 작업 산출물(`run-logs/<id>/`)과 커밋 기록(`docs/research/<id>/`)의 두 뿌리 경로를 결정하고, 스펙 스크립트에 수동 경로 상수를 두지 않는다.
- 동결 입력의 내용 해시는 id가 아니라 precommit 봉인 기록에 남는다.

회차는 GitHub 이슈로 발주되고 사람이 이슈 번호로 참조하는 운영 단위다.
같은 동결 입력으로 재판정 회차를 열 수 있는데(파일럿 #553이 이슈 513 입력을 그대로 재판정한 것이 실례다), id가 내용의 함수면 두 회차가 같은 id로 충돌한다.
내용의 동일성 증명은 id의 역할이 아니라 봉인 해시의 역할이다.
기존 기록의 소급 이동은 하지 않는다.

### 자기 검사는 3등급 열거값이고 기본값이 없다

- 등급은 해시 동일성(`hash-identity`) / 봉인 분할 1개 재현(`sealed-fold-replay`) / 전 분할 재현(`all-folds-replay`)의 셋뿐이다.
- 회차가 등급과 기준값 출처(source)를 명시해야 하며, SelfCheckSpec에 기본값이 없다.
- 재현 등급은 분할별 기대값(AUC, 예측 해시)을 요구하고, 실패는 판정 불가다.

세 등급은 기존 스크립트에 실존하던 관행의 열거다: 508/513은 해시 동일성만, 526은 봉인 분할 1개 재현, 엄격 사다리와 489는 전 분할 재현을 썼다.
등급별 비용이 초, 십분, 시간 단위로 다르므로 어느 등급을 쓸지는 비용 절충 판단이고, 자기 검사 강도는 결과 확인 전에 고정할 판정 조건의 일부다.
기본값을 두면 그 판단이 암묵이 되어 회차 기록만 보고는 어떤 강도의 시작 조건을 통과했는지 알 수 없게 된다.

### manifest.sha256은 게시 폴더 기준으로 재생성한다

- publish는 화이트리스트(precommit, selfcheck, fold, comparison, report, 게시 추가 목록)만 `docs/research/<id>/`로 복사한 뒤, 게시 폴더를 다시 훑어 manifest.sha256을 재생성한다.
- 재생성 직후 manifest 목록과 게시 폴더 실제 파일을 대조해, 어긋나면 게시가 실패한다.

run-dir 전체 목록을 그대로 커밋하던 기존 방식(엄격 사다리, 489 회차)은 게시 위치에 없는 파일 수십 줄을 목록에 남겼다.
그 줄들은 커밋된 파일만으로는 검증할 수 없어 manifest가 자기 모순이었다.
게시 폴더 기준 재생성(508/513 방식)만이 "이 폴더의 모든 파일이 이 해시다"라는 자기 완결적 진술을 만든다.

### 회차 고유 선택 규칙은 게이트 밖, 스펙 스크립트 소유다

- 게이트와 StackVerdict는 스택 교체 판정의 보편 규칙(delta 문턱, fold 승수, 판정 불가 승격)만 보증한다.
- 잡음 바닥 동률 처리나 사다리 구성 간 선택 같은 회차 고유 규칙은 스펙 스크립트가 StackVerdict 목록을 소비해 결정하고, 그 결정도 봉인 기록에 남긴다.

회차 고유 규칙을 게이트 옵션으로 넣으면 게이트가 회차별 정책 스위치의 집합으로 비대해지고, 보편 규칙과 일회성 규칙의 경계가 사라진다.
게이트는 모든 회차가 공유하는 최소 계약으로 남기고, 회차마다 다른 부분은 그 회차의 스펙 스크립트가 명시적으로 소유하는 편이 판정 근거를 읽는 쪽에도 정직하다.

## 실전 검증

- 파일럿 회차 `judgment-round-pilot/issue553`(#553, PR #562)이 이슈 513 재조립 판정을 JudgmentRound로 재실행해, 기록된 15개 항목(314 구성 해시, nested AUC 0.9703843058098193, nested·분할별 예측 해시, 분할별 AUC, delta 2.34117693961311e-05, 게이트 통과)을 전부 비트 단위로 재현했다.
- 파일럿 스펙 스크립트는 136줄로, 원 판정 스크립트 972줄을 대체했다.
- run은 workers 3, threads 4의 두 batch로 벽시계 25.2분이 걸렸고, 게시 결과는 `docs/research/judgment-round-pilot/issue553/`에 manifest 자기 대조를 통과한 상태로 커밋됐다(커밋 7a86738).
- `judge_stack_replacement`의 golden 시험이 동결된 이슈 513 comparison 기록을 재현하고, `==` 게이트와의 차이(요구 수 3에서 4/5와 5/5 통과 유지)를 시험으로 고정한다(#551, PR #556).

## 기각한 대안

- fold 승수 비교를 `==`로 두는 안은 요구 수 완화 시 만점 결과를 미달로 뒤집으므로 기각한다.
- 회차 id를 동결 내용 해시로 정하는 안은 같은 동결 입력의 재판정 회차와 충돌하고, 이슈로 발주하고 참조하는 운영 흐름과 어긋나므로 기각한다.
- 자기 검사에 기본 등급을 두는 안은 사전 고정해야 할 판정 조건 하나를 암묵으로 만들므로 기각한다.
- manifest에 run-dir 전체 목록을 커밋하는 안은 게시 위치에서 검증 불가한 줄을 남겨 자기 모순이므로 기각한다.
- 회차 고유 선택 규칙을 게이트 옵션으로 흡수하는 안은 보편 계약과 일회성 정책의 경계를 지우고 게이트를 비대하게 만들므로 기각한다.
- 선언형 스펙 파일과 회차 등록부를 만드는 안은 파이썬 RoundSpec 조립보다 표현력이 낮으면서 해석 계층을 하나 더 만들므로 기각한다(지도 #550 결정 3).
