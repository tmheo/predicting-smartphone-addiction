# 공통 module 3종의 기록 규약은 기존 digest 호환, 통일 봉인 키, 구성원별 검증 수준으로 고정한다

scripts의 judge·assemble·freeze·record 가족 31개 파일 19,114줄이 예측 해시, 자기 해시 기록, 구성원 적재라는 같은 로직을 반복 구현했고, 최근 fix 커밋 4건(4feeb55, 6f2048c, 43045c1, 15e9d1f)이 전부 그 복사본 안에서 터졌다.
공통 module 3종(`pipeline.identity` 예측 신원, `pipeline.sealed` 봉인 기록, `pipeline.members` 구성원 행렬)이 이 로직의 정본을 소유하게 됐다(#529, #530, #531).
이 ADR은 세 module이 고정한 기록 규약 가운데, 맥락 없이 보면 의아하지만 실제 절충의 결과이고 되돌리기 어려운 세 결정을 남긴다.

## 결정

### 예측 신원: 명시적 little-endian 바이트의 SHA-256, 쌍은 구분자 없는 연결

- 배열의 예측 신원은 명시적 little-endian(`<f8`) C 순서 contiguous 바이트의 SHA-256이다.
  정수 배열(id, fold 배정)은 `<i8`로 같은 규약을 따른다.
- OOF·시험 예측 쌍의 신원은 oof 바이트 뒤에 test 바이트를 구분자나 길이 접두사 없이 이어 붙인 SHA-256이다.
- 파일 바이트 해시(`file_identity`)는 예측 신원과 구분되는 계보 기록용으로만 쓴다.

쌍 규약은 자기서술적이지 않다.
그런데도 유지하는 이유는 과거 동결 기록 전체와의 digest 호환이 우선이기 때문이다.
기존 4개 재구현(pool_audit, freeze_external_candidates, freeze_reusable_own_candidates, build_external_member_ledger_v3)은 little-endian 장비에서 전부 같은 digest를 남겼고, golden 시험이 ecf-v3 동결 명세의 기록 해시를 재현해 이를 실증했다.
접두사 이동 충돌은 배열 길이가 N_TRAIN과 N_TEST로 사전 고정돼 있어 실용상 막혀 있다.
identity는 순수 바이트 해시로 남기고 NaN·유한성 검사 같은 정책을 넣지 않는다.
유한성은 구성원 행렬의 무결성 관문 소관이다.

### 봉인 기록: 통일 키 `sealed_sha256`, 과거 파일 읽기 호환 없음

- 봉인 기록은 canonical JSON(sort_keys, 최소 구분자, ensure_ascii=False)의 SHA-256을 `sealed_sha256` 키로 본문에 담는다.
- schema 문자열은 기존 관례 `<계약판>/<종류>/<판>`을 유지하고, 파생 기록은 원본의 자기 해시를 `parent_sealed_sha256` 계보 키로 물려받는다.
- seal은 payload에 예약 키가 선존재하면 거부한다.
  낡은 해시 값이 digest에 섞여 나중에 verify가 실패하는 결함을 봉인 시점에 차단하기 위해서다.

기존 파일에서는 `precommit_sha256`이 101개로 지배적 관례였지만 따르지 않는다.
precommit은 용도의 이름이지 메커니즘의 이름이 아니고, 키 이름을 매개변수로 열어둔 자유가 `spec_sha256`(4개), `record_sha256`(40개) 등 8종 키 난립을 만든 원인이었기 때문이다.
과거 파일의 읽기 호환도 하지 않는다.
봉인 기록 module은 새 기록 전용이고, 과거 파일의 검증 논리는 각 동결 시점의 verify 코드가 그 시점의 관례와 결함까지 포함해 소관한다.
다중 키를 인식하는 호환 계층을 정본에 넣으면 시점별 결함이 정본으로 흡수된다.

### 구성원 행렬: 검증 수준 3단계와 판정 하한

- 검증 수준은 hash-verified(예측 신원 대조 통과), auc-verified(장부 AUC 재채점 대조, 허용 오차 1e-9), identity-only((config, run_id) 신원만)의 3단계다.
- 신원 출처가 최소 수준을 선언하고, 실제 달성 수준을 구성원별로 기록한다.
- 판정 caller는 hash-verified를 요구한다.
  조립이나 진단 같은 비판정 용도만 낮은 수준을 허용한다.
- 열 순서는 출처의 동결 순서와 같아야 하고, 비유한값이 있으면 적재를 거부하며, 무결성 위반은 부분 성공 없이 형식 있는 예외로 끝난다.
  CLI는 공통 뿌리 예외 하나만 잡아 판정 불가로 번역한다.

검증 수준을 interface에 드러낸 이유는 풀 장부의 교훈(4feeb55)이다.
풀 장부는 판정 뒤 원자 교체될 수 있어, 판정 시점에 읽은 값과 나중에 읽은 값이 다를 수 있다.
그래서 풀 장부 출처 adapter는 identity-only 수준까지만 선언할 수 있고, 판정 입력으로는 불변 manifest나 동결 명세처럼 예측 신원을 완비한 출처만 통과한다.
이 하한을 관례가 아니라 타입 있는 요구(require)로 강제해, 판정 스크립트가 실수로 교체 가능한 출처를 읽는 길을 막는다.

## 실전 검증

- #532에서 `judge_extended_stack.load_own`을 #457 불변 manifest의 구성원 행렬 적재(hash-verified)로 교체하고, 사슬 말단 judge_issue526_ext327을 전체 재실행해 기록된 nested 0.9703889677646016, 예측 해시, 분할별 AUC, 판정 결과를 비트 단위로 재현했다(벽시계 약 28분).
- golden 시험이 커밋된 실제 동결 명세를 fixture로 ecf-v3 기록 해시와 AUC를 재현하고, 실전 스모크가 풀 장부 36명 auc-verified와 #457 manifest 313명 hash-verified 적재를 확인했다.

## 기각한 대안

- 쌍 신원에 길이 접두사나 구분자를 넣는 자기서술 규약은 과거 동결 기록 전체와의 digest 호환을 깨고 기록 재작성을 요구하므로 기각한다.
- 봉인 해시 키를 `precommit_sha256`으로 두거나 키 이름을 매개변수로 여는 안은 키 난립의 원인을 그대로 보존하므로 기각한다.
- 과거 봉인 파일의 다중 키 읽기 호환은 시점별 verify 결함을 정본이 흡수하게 만들므로 기각한다.
- 판정 caller가 auc-verified를 허용하는 안은 원자 교체 가능한 출처에서 판정 시점 값과의 동일성을 보장하지 못하므로 기각한다.
- 유한성 검사를 예측 신원에 넣는 안은 순수 바이트 해시라는 단일 책임을 흐리고 기존 digest와의 동작 차이를 만들 수 있으므로 기각한다.
