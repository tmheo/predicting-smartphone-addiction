# 3시드 OOF·Public 회고 노트북 구현 명세

이 문서는 지도 이슈 #208의 최종 산출물이며, 티켓 #209~#213의 결정을 하나의 구현 명세로 통합한다(#214).
구현자는 이 문서만으로 추가 판단 없이 노트북을 만들 수 있어야 한다.
이 문서와 개별 티켓 코멘트가 충돌하면 이 문서가 우선한다.
용어는 `CONTEXT.md`를 따른다(시드 범위, 평균화 이득, 시간순 최고선, 전이 분석, 전이 표시, 다음 실험 권고, 확장 후보권).

## 1. 산출물

- 파일: `notebooks/oof-public-retrospective.ipynb`.
- 본문(markdown 셀)은 한국어, 그림 안 텍스트는 영문만 사용한다(저장소 관행).
- 노트북은 실행 출력(표, 그림)을 포함한 상태로 커밋한다.
  독자가 재실행 없이 결론을 읽을 수 있어야 하기 때문이다.
- 허용 import: 표준 라이브러리(`sqlite3`, `io`, `zoneinfo`, `datetime`, `pathlib`, `itertools`, `importlib.metadata`), `pandas`, `matplotlib`, `yaml`.
- `mlflow` import는 금지한다.
  tracking 클라이언트가 경로 실수 시 새 저장소를 만들 수 있어, 읽기 전용 계약을 코드 수준에서 보장하기 위해서다.
- 새 파일 생성, 기존 파일 수정, 네트워크 접근을 하지 않는다.
  실행 후 `git status`에는 노트북 자신의 출력 변화 외에 어떤 변화도 없어야 한다.

## 2. 입력과 재현성 계약 (§0의 코드 계약)

첫 코드 셀은 아래 상수만 정의한다.

```python
REPO_ROOT      # Path.cwd()에서 위로 올라가며 pyproject.toml이 있는 첫 디렉터리. 못 찾으면 즉시 중단.
MLFLOW_DB_PATH = REPO_ROOT / "mlflow.db"
POOL_PATH      = REPO_ROOT / "artifacts/pool.yaml"
CHAMPION_PATH  = REPO_ROOT / "artifacts/champion.yaml"
AUDIT_CUTOFF   # KST 2026-08-19 00:00:00. start_time이 이 시각 이상인 실행은 분석에서 제외.
EXPERIMENT_NAME = "predicting-smartphone-addiction"
```

계약은 다음과 같다.

1. 세 입력 파일 중 하나라도 없으면 `FileNotFoundError`로 즉시 중단하고, 어떤 경우에도 새 파일이나 새 데이터베이스를 만들지 않는다.
2. MLflow 데이터베이스는 `sqlite3.connect(f"file:{MLFLOW_DB_PATH}?mode=ro", uri=True)` 읽기 전용 연결로만 연다.
   장부 두 파일은 읽기만 하고 절대 쓰지 않는다.
3. 조회 직후 다음을 표로 출력한다: 실행 시각(KST), 세 입력의 절대 경로, `mlflow.db`의 크기와 수정 시각, `AUDIT_CUTOFF` 값, 감사 기준일(2026-08-18) 이후 추가되어 제외된 실행 수.
4. `experiment_id`는 하드코딩하지 않고 `experiments` 표에서 `EXPERIMENT_NAME`으로 조회한다.
5. 조회는 `runs`, `params`, `latest_metrics`, `tags` 네 표의 SELECT만 사용한다.

`AUDIT_CUTOFF`를 두는 이유: 이 노트북은 감사(#209)로 고정한 모집단의 회고이며, 이후 새 실행이 추가돼도 결과가 변하지 않는 재현 가능한 스냅샷이어야 한다.
컷오프 이후 실행은 건수만 한 줄로 보고하고 모든 분석에서 제외한다.

## 3. 원자료와 정제표

### 3.1 원자료(RAW)

컷오프 이전의 모든 실행(P0, 153건)을 실행당 한 행으로 피벗한 표.
어떤 실행도 버리지 않고 이 표에 보존한다.
노트북에는 행 수와 상태 분포(FINISHED 139, KILLED 12, FAILED 2), 상위 몇 행만 표시한다.

### 3.2 파생 열

| 열 | 정의 |
| --- | --- |
| `start` | `start_time`(ms epoch)을 KST datetime으로 변환 |
| `dirty` | tag `git_dirty == "True"` |
| `is_ensemble` | `ensemble.`으로 시작하는 param이 하나라도 존재 |
| `strict` | metric `auc_oof_seed_42/43/44` 모두 존재 |
| `config` | param `experiment`에 별칭 매핑 `{"exp033_lattice_te": "exp035_lattice_te"}`를 적용한 값. 매핑 근거는 감사 문서의 exp033/exp035 동일 구성 판정 |
| `seed_range` | 시드별 OOF AUC의 max − min (strict 실행만) |
| `avg_gain` | `auc_oof` − 시드별 OOF AUC 3개의 평균 (strict 실행만) |
| `series` | param `model.kind` |

### 3.3 모집단 재도출 (#209 판별 규칙)

실행 id 목록이 아니라 규칙으로 재도출한다.

- P1 전체 OOF: `status == "FINISHED"` 이고 param `seeds == "42,43,44"` 인 단일 모델 실행.
- P2 엄격 시드: P1 중 `strict`.
- P3 대표: P1에서 `config`별로 대표 1건.
  대표는 깨끗한(clean) 실행 중 가장 최근 실행이고, 깨끗한 실행이 없으면 가장 최근 dirty 실행을 대표로 삼고 dirty 예외로 표시한다.
- 전이 분석: P1 중 metric `public_auc` 보유.
- 앙상블 구획: `is_ensemble` 이고 완료된 실행.

### 3.4 제외·표시 사유 코드

P0의 각 실행에 다음 코드를 0개 이상 부여하는 열을 만든다.

| 코드 | 부여 규칙 |
| --- | --- |
| NOT_FINISHED | `status != "FINISHED"` |
| SINGLE_SEED | 완료됐고 `seeds == "42"` |
| LEGACY_FORMAT | P1인데 `strict`가 아님 |
| DUPLICATE | P1인데 대표가 아님 |
| DIRTY | `dirty` (제외가 아니라 표시) |
| ENSEMBLE_DERIVED | `is_ensemble` |
| NO_OOF | 완료됐는데 `auc_oof` metric이 없음 |

### 3.5 전이 분석 짝짓기

`public_auc`가 기록된 실행 자체의 `auc_oof`를 짝으로 쓴다.
대표 실행이 따로 있어도(exp006, exp011) 대표의 OOF로 바꿔 짝짓지 않는다.

## 4. 검증 셀

노트북 곳곳에 다음 assert 셀을 두고, 하나라도 실패하면 노트북 실행이 실패해야 한다.

- **V1 모집단 대조(§0)**: 재도출 건수가 감사 기준(P0 153, P1 42, P2 39, P3 32, 전이 10, 앙상블 7)과 정확히 일치함을 assert 하고, 대조 표를 출력한다.
  불일치 시 감사 문서(`docs/research/mlflow-3seed-population-audit.md`)를 먼저 갱신하라는 메시지와 함께 중단한다.
- **V2 champion 대조(§0)**: `champion.yaml`의 `run_id`가 P3 대표에 존재하고, 그 실행의 `auc_oof`가 장부의 `oof_auc`와 1e-9 이내로 일치함을 assert 한다.
- **V3 풀 장부 대조(§0)**: `pool.yaml` 구성원 22건의 `config`가 모두 P3 대표 32개 구성의 부분집합임을 assert 한다.
- **V4 권고 규칙 점검(§7)**: 동결 시점 알려진 결과 4건을 assert 한다.
  exp081_lookup_fold_initialization_avg3 = 확장, exp043_cat_depth6 = 재검증, exp058_logreg_onehot = 보류, 앙상블 대표 행 = 확장.
  확장 후보권 구성 수가 11임도 assert 한다.
- **V5 재출력(§8)**: V1의 대조 표를 §8에서 다시 출력한다(assert는 반복하지 않아도 된다).

## 5. 구획별 명세

노트북은 §0~§8 아홉 구획을 이 순서로 구성한다(#212 확정).
각 구획은 markdown 머리말 셀로 시작한다.

### §0 머리말과 재현성 계약

- 노트북의 목적 한 문단: 완료된 3시드 실험 전체를 회고하고 OOF와 Public AUC의 관계를 검증해 다음 실험 권고까지 잇는다.
- 2절의 코드 계약 구현, 3절의 적재와 재도출, 검증 셀 V1~V3.
- 지도 #208, 감사 문서, ADR 0001 링크.

### §1 모집단 감사 요약

- 모집단 깔때기 표: P0 → P1 → P2 → P3, 전이 분석, 앙상블 구획의 정의와 건수.
- 사유 코드 7종의 건수 표(기대값: NOT_FINISHED 14, SINGLE_SEED 90, LEGACY_FORMAT 3, DUPLICATE 10, DIRTY 8, ENSEMBLE_DERIVED 7, NO_OOF 1).
- 상세는 감사 문서 링크로 대신한다.

### §2 전체 OOF 회고 (단일 모델)

주 그림과 보조 그림을 이 순서로 둘 다 싣는다(서사 → 지형).

- **그림 2A(주)**: 시간순 산점도.
  P1 42건 전체를 x=시작 시각, y=시드 평균본 OOF AUC로 찍는다.
  대표는 진한 색, 비대표 재실행은 회색으로 구분한다.
  시간순 최고선을 계단선으로 겹치고, 범례에 최고선이 이야기 재료(story device)임을 명시한다(#210).
  최고선을 갱신한 구성의 짧은 이름(`exp` 접두 번호)을 점 위에 단다.
- **그림 2B(보조)**: 대표 32건의 순위 점 그림.
  y축은 구성 이름(OOF 오름차순), x축은 시드 평균본 OOF AUC.
  색으로 strict(파랑), LEGACY_FORMAT(주황), dirty 대표 예외(빨강)를 구분하고 범례에 설명한다.
- 본문 서술: 핵심 근거는 시드 평균본 OOF AUC 하나라는 문장(#210)과, champion 계보의 시간 흐름 요약.

### §3 시드 안정성 (엄격 39건)

- **그림 3**: 두 패널.
  왼쪽은 시드 범위 분포 스트립(로그 x축)에 ADR 0001 문턱 두 개(0.00002 동률, 0.0002 실질)를 세로 점선으로 겹친다.
  오른쪽은 평균화 이득 분포 스트립에 ADR #74 가정치 +0.0003 참조선을 겹치고, 이상치(`avg_gain > 0.0008` 또는 `< 0.00005`)에 구성 이름표를 단다.
- 표: 시드 범위의 중앙값·p90·최댓값(동결 기대값 0.000057 / 0.000076 / 0.000137)과 평균화 이득 중앙값(동결 기대값 +0.000334).
- 본문 서술: ADR 눈금 3구간(동률 < 0.00002, 경계 0.00002~0.0002, 실질 ≥ 0.0002)이 실측 시드 잡음 분포와 정합하는지의 검증 문장.
  시드 범위 ≥ 0.0002인 실행 수를 출력한다(동결 기대값 0).
- LEGACY_FORMAT 3건은 이 구획에 참여하지 못함을 표로 표시한다.
- 경계 구간의 같은 시드 승수 보강 증거는 우열을 실제로 주장하는 쌍(인접 순위 쌍, champion 계보 교체 쌍)에서만 계산해 표로 싣는다.
  대표 32건의 전 쌍에는 적용하지 않는다(#210).

### §4 전이 분석 (10건)

구획 앞머리에 아래 경고문을 그대로 싣는다(#211, 자구 고정).

> 이 표본은 유망 실행만 선택적으로 제출된 10건이며, 모든 결론은 이 표본 안의 관찰 서술이다. 미제출 실행이나 미래 실행으로 일반화하지 않는다.

- 요약 통계: 역전 쌍 수(45쌍 중, 동결 기대값 0), Kendall τ(pandas `corr(method="kendall")`, p값 없음, 동결 기대값 1.00), 격차(Public − OOF)의 중앙값과 범위(동결 기대값 중앙값 약 +0.00125, 범위 +0.00113~+0.00143).
- **그림 4A**: OOF 대 Public 산점도 하나만(기울기 그림 금지, #212).
  참조선은 `y = x + 격차 중앙값` 점선 하나, 각 점에 짧은 이름표.
- 시간순 증분 표: 제출 실행을 제출 실행의 시작 시각 순으로 놓고 인접 쌍의 ΔOOF, ΔPublic, 방향 일치 여부를 서술 통계로 싣는다.
  결론 문장은 "제출된 실행들에서 OOF 개선과 Public 개선이 같은 방향이었다"(관찰 표본 한정)까지만 허용한다.
- 선택 편향은 별도 구획 없이 이 구획 안에서 바로 잇는다.
  **그림 4B**: 제출 10건과 미제출 32건의 OOF 분포 스트립 비교.
  본문에 제출 표본의 OOF 분위수 요약 한 줄과, 선택 규칙이 통계 모형이 아니라 사람의 판단(champion 계보의 유망 실행 제출)이었다는 명시 문장.
- 주변부: 단일 시드 exp001(Public 0.96450)은 그림 밖 각주 한 줄, `c2171fa9`(full refit, NO_OOF)는 Public 존재 확인 한 줄, 앙상블 전이는 §5에서 다룬다.
- **금지 목록(구현·검토 공통)**: 미제출 실행의 Public 예측·보간·추정 열, 격차의 시간 추세 주장, "OOF 개선은 Public 개선으로 이어진다" 류의 일반화, 신뢰구간·부트스트랩·p값 등 추론 통계, 선택 편향 보정 모형, ADR 눈금의 Public 차이 적용.

### §5 앙상블 구획 (7건)

- **그림 5**: `auc_oof`(nested OOF)를 가진 앙상블 6건의 점 그림.
  단일 모델 최고 OOF를 세로 참조선으로 겹친다.
- 시드 안정성 분석은 적용 불가임을 명시한다(#210).
- Public을 가진 앙상블 3건(OOF 짝 보유)의 전이는 §4와 같은 방식의 서술 통계 표로만 싣는다.
- full refit 제출 `c2171fa9`는 Public 존재 확인 한 줄로만 다룬다.
- 8월 18일 앙상블 3건의 git 태그 부재는 기록 격차로 한 줄 표시하고, 앙상블 구획에서는 커밋 기반 판별을 쓰지 않는다(#209).

### §6 민감도 분석 (P3 32 vs P1 42)

새 그림 없이 결론 차이만 한 표로 보고한다(#210, #212).
세 검사를 다음과 같이 구현한다.

1. **순위 역전**: 각 구성에서 대표의 `auc_oof`와 비대표 재실행들의 `auc_oof` 차이의 최대 절대값을 구하고, 그 차이로 P3 순위가 바뀌는 구성이 있는지 본다.
2. **시간순 최고선 모양**: P1 42건으로 그린 최고선의 갱신 구성 목록과 P3 32건(시간순)으로 그린 갱신 구성 목록을 비교한다.
3. **동률·경계 판정**: P3 인접 순위 쌍 31개의 Δ를 ADR 3구간으로 분류한 결과가, 대표 대신 각 구성의 다른 실행 값을 썼을 때 달라지는 쌍이 있는지 본다.

하나라도 차이가 있으면 해당 행을 표본 선택 편향으로 표시하고, 없으면 "대표 선정이 결론을 바꾸지 않음" 한 줄로 확인한다.
민감도 분석 전용의 새 지표는 만들지 않는다.

### §7 다음 실험 권고 표

머리말에 다음을 싣는다.

- ADR 0001과의 경계 세 문장(#213 자구 유지): 다음 실험 권고는 채택 판정이 아니며 champion·풀 장부를 변경하지 않는다. 권고는 전이 표시를 쓸 수 있지만, 채택 판정은 여전히 Public을 쓰지 못한다. 권고 규칙이 ADR 0001의 문턱 숫자를 빌리거나 새 상수를 두더라도 그 의미는 다음 실험 우선순위로 한정된다.
- §4 고정 경고문의 계승 문장.
- 다양성 소관 위임 문장: 다양성 목적 변형 실험의 우선순위는 단일 모델 행이 아니라 앙상블 대표 행의 확장(풀 확충)에 싣는다.

**확정 표**: 행은 P3 대표 32개 구성 + 앙상블 대표 1행.
열은 구성 | OOF | 시드 안정성 | 전이 표시 | 근거 요약 | 권고.

- OOF 열은 소수 다섯 자리.
- 시드 안정성 열은 strict면 시드 범위 값, LEGACY_FORMAT이면 "지표 없음", 앙상블 행이면 "적용 불가".
- 전이 표시 열은 구성 단위로 계산한다: 그 구성의 P1 실행 중 `public_auc` 보유 실행이 없으면 미제출, 있으면 그 실행이 §4의 역전 쌍에 하나라도 속할 때 역전 관찰, 아니면 전이 일치.
- 근거 요약 열은 발동 규칙과 근거 값으로 자동 생성한다.
  형식: `{규칙 이름}; OOF {값}; 결함 {목록 또는 없음}; {전이 표시}`.
  후보권 밖 구성의 증거 결함은 권고를 바꾸지 않고 이 열에 표기만 한다.

**단일 모델 권고 규칙**(#213, 첫 일치 적용, 코드가 자동 계산):

- 전제: 확장 후보권 = 시드 평균본 OOF AUC ≥ champion `oof_auc`(champion.yaml) − 0.001.
  증거 결함 = LEGACY_FORMAT, dirty 대표 예외, 시드 범위 ≥ 0.0002 중 하나 이상.
- 규칙 1: 후보권이고 결함 있음 → 재검증.
- 규칙 2: 후보권이고 결함 없음 → 확장.
- 규칙 3: 후보권 밖이고 `config`가 풀 장부 구성원 → 보류.
- 규칙 4: 그 외 → 중단.

**앙상블 대표 행**: `auc_oof`를 가진 완료 앙상블 실행 중 시작 시각이 가장 최근인 실행 1건(동결 시점 `86d87d91`).
nested OOF가 champion 시드 평균본 OOF 대비 +0.00002 이상이면 확장, 미만이면 보류.
재검증·중단은 앙상블 행에 적용하지 않는다.

**정렬**: 권고 등급 순(확장 → 재검증 → 보류 → 중단)으로 묶고, 확장 안에서는 전이 일치를 앞세운 뒤 OOF 내림차순, 나머지 등급 안에서는 OOF 내림차순.
앙상블 행은 같은 규칙으로 함께 정렬한다.

**계열 롤업 표**: 확정 표 아래에 둔다.
열은 모델 계열(`model.kind`) | 대표 구성 수 | 계열 최고 OOF(구성 이름) | champion 대비 격차 | 계열 최고 갱신 여부 | 전이 표시 요약 | 계열 권고.

- 계열 권고는 계열 내 대표 구성 권고 중 최선(확장 > 재검증 > 보류 > 중단)으로 롤업한다.
- 계열 최고 갱신 여부는 "계열에서 가장 최근에 시작한 대표 실행이 계열 최고 OOF인가"로 정의하고, 기술 통계일 뿐 권고 규칙의 입력이 아님을 표 아래에 명시한다.
- 전이 표시 요약은 계열 내 값의 건수(예: 일치 2, 미제출 3)로 쓴다.

검증 셀 V4를 이 구획 끝에 둔다.
