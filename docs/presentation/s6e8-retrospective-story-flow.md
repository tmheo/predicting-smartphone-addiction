# 2시간 사내 대회 회고 이야기 흐름 설계서

이 문서는 기계학습 비전문가인 사내 동료를 위한 S6E8 대회 회고의 화면 단위 이야기 흐름을 정한다.
실제 발표 화면 디자인과 발표 대본이 아니라, 후속 발표 자료 제작자가 화면을 만들 때 따라야 할 순서와 역할을 담는다.

## 중심 메시지

최종 14위는 비밀 모델 하나가 아니라 검증 가능한 작은 실험, 서로 다르게 틀리는 예측, 여러 실행 장소를 한 검수 절차로 묶은 실험 실행 체계를 조립한 결과였다.
우승권과의 남은 차이는 더 강한 단일 모델을 더 빨리 찾는 탐색 역량이었다.

## 전체 시간 구성

| 구간 | 시간 | 내용 |
|---|---:|---|
| 전반 본문 | 42분 | 14위 결과와 오늘 이야기, 문제 이해, 믿을 수 있는 실험 만들기 |
| 전반 예비 시간 | 3분 | 청중 참여나 개념 설명이 길어질 때 사용 |
| 휴식 | 10분 | 전반의 세 질문과 후반 예고를 화면에 남김 |
| 후반 본문 | 42분 | 탐색과 확장, 조립과 교훈 |
| 후반 예비 시간 | 3분 | 사례 설명이 길어질 때 사용 |
| 질의응답 | 20분 | 본문 마지막 질문에서 자연스럽게 이어감 |

## 화면 작성 원칙

- 한 화면에는 핵심 주장 하나만 둔다.
- 시각 자료는 그 주장을 증명하거나 이해시키는 역할만 한다.
- 일반 OOF, nested OOF, Public과 Private은 서로 다른 측정 경계로 표시하고 한 점수 계보선으로 잇지 않는다.
- 일반 OOF는 파랑 원, nested OOF는 청록 네모, Public은 호박 마름모, Private은 보라 별로 표시한다.
- 판정은 색만으로 나타내지 않고 초록 원 `채택`, 빨강 네모 `중단`, 노랑 삼각형 `미채택` 또는 `근거 더 보기`를 문장과 함께 쓴다.
- 화면 안에는 측정 종류, 확대 눈금, 축 양끝, 점수와 비용의 적용 범위, 판정 관문을 남긴다.
- 긴 소수, 실행 식별자와 상세 출처는 발표자 메모나 부록 후보로 분리한다.
- `fold`, `ROC AUC`, `OOF`, `OOF AUC`, `nested OOF`, `ensemble`, `missingness augmentation`은 처음 한 번 뜻을 풀고 이후에는 같은 표기를 반복한다.

## 1막: 14위 결과와 오늘 이야기

### 화면 01: Private 0.97109, 최종 14위에서 시작합니다

- **시간:** 0:00부터 2분 동안 다룬다.
- **핵심 주장:** 청중이 이미 아는 14위를 반전으로 숨기지 않고 오늘 이야기의 출발점으로 삼는다.
- **시각 자료:** 공식 결과 표에서 14위를 크게 표시하고, 오른쪽 가장자리에는 Public 0.97135와 Private 0.97109를 서로 다른 표식으로 둔다.
- **발표자 요점:** 오늘은 성적 자체보다 그 성적이 만들어진 방식을 설명한다고 약속한다.
- **다음 화면:** "같은 12개 변수로 어떻게 여기까지 왔을까요?"라고 묻는다.

### 화면 02: 검증 가능한 작은 실험을 조립한 결과였습니다

- **시간:** 2:00부터 3분 동안 다룬다.
- **핵심 주장:** 비밀 모델 하나가 아니라 작은 실험, 서로 다른 오차, 실험 실행 체계를 조립해 14위에 도달했다.
- **시각 자료:** 작은 실험, 서로 다르게 틀리는 예측, 실험 실행 체계의 세 조각이 14위로 모이는 길 지도를 사용한다.
- **발표자 요점:** 전후반에서 반복할 세 축을 청중에게 길 안내판처럼 먼저 건넨다.
- **다음 화면:** "먼저 우리가 풀었던 문제와 점수부터 같은 그림으로 맞추겠습니다."라고 말한다.

## 2막: 문제 이해

### 화면 03: 12개 생활 습관 변수로 중독 위험의 순서를 예측했습니다

- **시간:** 5:00부터 3분 동안 다룬다.
- **핵심 주장:** 이 대회는 한 문턱으로 정답을 맞히는 문제가 아니라 사람들의 위험 순서를 만드는 문제였다.
- **시각 자료:** 한 사람의 12개 입력이 위험도 막대로 바뀌고, 여러 사람이 위험도 순서로 놓이는 한 방향 자료 흐름을 보여 준다.
- **발표자 요점:** 모델 구조보다 입력과 예측 결과의 의미를 먼저 맞춘다.
- **다음 화면:** "그렇다면 좋은 순서인지 무엇으로 판단했을까요?"라고 묻는다.

### 화면 04: ROC AUC는 순서 전체를 봅니다

- **시간:** 8:00부터 3분 동안 다룬다.
- **핵심 주장:** ROC AUC는 정답 문턱 하나의 정확도가 아니라 위험 순서 전체를 평가한다.
- **시각 자료:** 0.5부터 1.0까지의 작은 기준 막대와 네 사람의 두 위험 순서를 함께 보여 준다.
- **발표자 요점:** 0.5는 무작위 순서, 1.0은 완전한 순서라는 전체 맥락만 먼저 준다.
- **다음 화면:** "두 예측 순서 가운데 어느 쪽이 더 낫다고 느껴지나요?"라고 묻는다.

### 화면 05: 청중 참여 1에서 더 좋은 위험 순서를 고릅니다

- **시간:** 11:00부터 2분 동안 다룬다.
- **핵심 주장:** 청중이 A와 B 가운데 더 좋은 위험 순서를 직접 고른다.
- **시각 자료:** 실제 중독 여부가 표시된 네 사람과 위험 순서 A, B를 보여 주되 정답 수치는 가린다.
- **발표자 요점:** 손들기나 짧은 구두 투표로 선택만 받고 계산은 요구하지 않는다.
- **다음 화면:** "왜 B가 더 낫다고 느꼈는지 네 쌍으로 확인해 보겠습니다."라고 말한다.

### 화면 06: B는 네 쌍 모두에서 중독 한 명을 더 위에 놓았습니다

- **시간:** 13:00부터 3분 동안 다룬다.
- **핵심 주장:** B가 중독 한 명과 비중독 한 명으로 만들 수 있는 네 쌍 모두를 올바른 순서로 놓았다.
- **시각 자료:** 네 쌍을 차례로 공개하고 A는 3쌍, B는 4쌍을 올바르게 놓았다고 표시한다.
- **발표자 요점:** ROC AUC는 임의로 고른 중독 한 명에게 비중독 한 명보다 높은 위험도를 준 비율이라고 설명한다.
- **다음 화면:** "평가 기준을 알았으니 같은 숫자를 모델에게 어떻게 보여 줬는지 보겠습니다."라고 말한다.

### 화면 07: 같은 숫자에도 두 관점이 있습니다

- **시간:** 16:00부터 2분 30초 동안 다룬다.
- **핵심 주장:** 같은 숫자는 연속적인 크기와 정확한 값 범주라는 두 관점으로 볼 수 있다.
- **시각 자료:** 하나의 숫자를 연속 눈금으로 보는 렌즈와 정확값 범주로 보는 렌즈를 나란히 둔다.
- **발표자 요점:** 12개 변수를 늘린 것이 아니라 같은 변수를 여러 관점으로 표현했다고 설명한다.
- **다음 화면:** "둘 중 하나를 고르는 대신 함께 보여 주면 어땠을까요?"라고 묻는다.

### 화면 08: 두 관점을 함께 쓰자 OOF AUC가 +0.00329 올랐습니다

- **시간:** 18:30부터 2분 30초 동안 다룬다.
- **핵심 주장:** 수치와 정확값 범주를 함께 쓴 단일 구성이 더 좋은 자체 검증 성적을 냈다.
- **시각 자료:** 일반 OOF 파랑 원만 쓰는 확대 눈금 전후 비교에 축 양끝과 `AUC 차이 +0.00329`를 적는다.
- **발표자 요점:** 이 수치는 단일 구성 내부 비교이며 Public이나 Private 점수와 이어지는 값이 아니라고 제한한다.
- **다음 화면:** "그렇다면 모든 숫자를 범주로만 바꾸면 더 좋아질까요?"라고 묻는다.

### 화면 09: 전부 범주로만 쓰자 AUC 차이 -0.00417이었습니다

- **시간:** 21:00부터 2분 동안 다룬다.
- **핵심 주장:** 숫자의 크기를 버리고 범주만 쓰면 성능이 오히려 나빠졌다.
- **시각 자료:** 수치만, 범주만, 둘 다의 세 렌즈를 보여 주고 범주만 행에는 빨강 네모 `중단`을 표시한다.
- **발표자 요점:** 정답은 표현 하나가 아니라 서로 보완하는 관점을 함께 보존하는 것이었다고 회수한다.
- **다음 화면:** "하지만 숫자가 올랐다는 사실만으로 실험을 믿어도 될까요?"라고 묻는다.

## 3막: 믿을 수 있는 실험 만들기

### 화면 10: 모든 실험은 같은 다섯 fold에서 비교했습니다

- **시간:** 23:00부터 2분 동안 다룬다.
- **핵심 주장:** 모든 실험은 결과를 보기 전에 고정한 같은 다섯 fold에서 비교했다.
- **시각 자료:** 자료를 다섯 묶음으로 나눈 뒤 자물쇠가 닫히는 흐름을 보여 준다.
- **발표자 요점:** 결과를 보기 전에 자료를 같은 다섯 묶음으로 나눴고 그 묶음 하나를 fold라고 부른다고 설명한다.
- **다음 화면:** "각 행이 자기 정답을 보지 않은 예측을 받게 하려면 어떻게 해야 할까요?"라고 묻는다.

### 화면 11: OOF는 자기 정답을 보지 않은 모델의 예측입니다

- **시간:** 25:00부터 2분 동안 다룬다.
- **핵심 주장:** 각 학습 행은 자기 정답으로 학습하지 않은 모델에서 예측 하나를 받았다.
- **시각 자료:** 다섯 fold 가운데 하나씩 검증으로 비우고 네 묶음에서 학습한 예측을 원래 행 순서로 이어 붙인다.
- **발표자 요점:** 예측값인 OOF와 이를 ROC AUC로 채점한 OOF AUC를 구분한다.
- **다음 화면:** "예측을 합치는 규칙까지 같은 자료에서 고르면 여전히 답을 엿볼 수 있습니다."라고 말한다.

### 화면 12: nested OOF는 바깥 fold를 봉인합니다

- **시간:** 27:00부터 3분 동안 다룬다.
- **핵심 주장:** 바깥 fold를 봉인한 채 안쪽 fold에서 구성원과 결합 방식을 고른 뒤 봉인한 fold에서 평가했다.
- **시각 자료:** 다섯 검사실 가운데 한 곳을 봉인하고 나머지 네 곳에서 조합을 고른 뒤 봉인을 열어 평가하는 장면을 사용한다.
- **발표자 요점:** 다섯 검사실 비유는 이 화면에서만 한 번 쓰고 곧바로 실제 바깥 fold와 안쪽 fold 흐름으로 돌아온다.
- **다음 화면:** "이제 혼자 잘하는 예측과 팀에 도움이 되는 예측을 따로 물을 수 있습니다."라고 말한다.

### 화면 13: 개인전 점수와 ensemble 기여는 다른 질문입니다

- **시간:** 30:00부터 2분 동안 다룬다.
- **핵심 주장:** 단독 점수가 높은지와 ensemble에 들어왔을 때 전체 결과를 높이는지는 별도의 판단이다.
- **시각 자료:** `혼자 잘하는가`와 `함께할 때 돕는가`라는 두 검수대를 나란히 두고 일반 OOF 파랑 원과 nested OOF 청록 네모를 분리한다.
- **발표자 요점:** ensemble은 여러 예측을 합치되 개인전 점수와 팀 기여를 따로 보는 것이라고 처음 설명한다.
- **다음 화면:** "그 판단 절차를 실제 결과 하나에 적용해 보겠습니다."라고 말한다.

### 화면 14: 청중 참여 2에서 +0.0000469만 보고 결정합니다

- **시간:** 32:00부터 1분 30초 동안 다룬다.
- **핵심 주장:** 전체 nested OOF AUC 차이 하나만으로는 채택 여부를 정할 수 없다.
- **시각 자료:** 청록 네모의 `+0.0000469`와 `채택`, `중단`, `근거 더 보기` 세 선택을 보여 주고 반복 근거는 가린다.
- **발표자 요점:** 첫 답은 수치가 작아서가 아니라 선택과 평가 절차의 근거가 없기 때문에 `근거 더 보기`라고 설명한다.
- **다음 화면:** "한 번의 전체 숫자 외에 어떤 근거가 더 필요할까요?"라고 묻는다.

### 화면 15: 바깥 fold 다섯 곳에서 모두 같은 방향이었습니다

- **시간:** 33:30부터 1분 30초 동안 다룬다.
- **핵심 주장:** 전체 점수뿐 아니라 바깥 fold 다섯 곳에서 모두 양의 방향을 보였다.
- **시각 자료:** 청록 네모 다섯 개를 한 줄로 공개하고 각 fold의 방향이 모두 양수라고 표시한다.
- **발표자 요점:** 반복 근거를 공개하되 결과를 보기 전에 채택 조건을 정했는지 다시 묻는다.
- **다음 화면:** "이 반복 결과를 보기 전에 채택 조건도 정해 두었을까요?"라고 묻는다.

### 화면 16: 사전에 고정한 관문을 통과해 채택했습니다

- **시간:** 35:00부터 2분 동안 다룬다.
- **핵심 주장:** missingness augmentation은 점수의 부호가 아니라 사전에 고정한 관문을 통과했기 때문에 채택했다.
- **시각 자료:** 점추정, 5/5 반복 근거, 사전 관문, 초록 원 `채택`의 네 열을 보여 주고 색은 마지막 결론에만 쓴다.
- **발표자 요점:** missingness augmentation은 관측값 일부를 추가로 가린 복제본으로 값이 비어도 견디게 한 방법이라고 설명한다.
- **다음 화면:** "같은 판단을 여러 실행 장소에서 반복하려면 공통 레시피와 검수대가 필요했습니다."라고 말한다.

## Confluence 게시 경계

이 Markdown 파일을 Confluence 게시 원본으로 사용한다.
5막을 하위 페이지로 나누지 않고 전체 이야기 흐름을 하나의 Confluence 페이지로 게시한다.
페이지 안의 제목 계층으로 5막과 35개 화면을 탐색하며, 부록이 확정될 때만 별도 하위 페이지를 만든다.
HTML 시제품은 화면 흐름을 검토하기 위한 임시 도구이며 공유 문서의 원본이 아니다.
Confluence 게시 위치와 제목을 정한 뒤 `workpulse confluence page publish --markdown-file`로 새 페이지를 만들거나 기존 페이지를 갱신한다.
실제 게시 작업은 대상 공간, 상위 페이지와 제목을 사용자가 지정한 뒤 수행한다.
