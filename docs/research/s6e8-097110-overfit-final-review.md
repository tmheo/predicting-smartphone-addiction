# S6E8 0.97110 초과 과적합 주장 최종 검토

이 문서는 GitHub 이슈 [독립 근거를 종합해 최종 검토서와 저장소 적용 판단을 확정한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/251)의 결정 기록이다.
검토 대상은 사용자가 직접 고른 [지정 노트북의 고정 판본](https://www.kaggle.com/code/raykkretzschmar/why-every-s6e8-notebook-above-0-97110-overfits?scriptVersionId=343453035)이며, 공개 판본 번호는 22이고 실행 판본 식별자는 `343453035`다.

## 최종 판정

지정 노트북은 공개 점수로 마지막 미세 보정 방향을 고르는 위험을 보여 주는 사례로는 신뢰할 만하다.
작성자가 공개 점수 최고라고 기록한 학생 가중치 `-0.08`은 교사 단독보다 OOF AUC가 `0.00009056` 낮았고, OOF 최고 방향인 `+0.12`와 반대였다.
고정 입력을 사용한 별도 구현에서도 이 방향 역전과 마지막 제출 파일이 재현됐으므로, `-0.08` 보정 파일을 공개 점수만으로 최종 제출 후보에 넣지 않는 판단은 강하게 지지된다.

반면 `0.97110`은 과적합 여부를 가르는 통계적 경계가 아니다.
지정 노트북은 경계 전후 모집단을 비교하지 않았고, 모든 초과 노트북의 선택 절차와 동일 예측 파일의 비공개 결과를 조사하지 않았다.
따라서 “0.97110을 넘는 모든 S6E8 노트북은 과적합”이라는 보편 명제는 입증되지 않았으며, 이 점수를 저장소의 검증 문턱이나 제출 선택 경계로 사용해서는 안 된다.

모의 공개 선택 실험은 반복 조회한 공개 점수에서 작은 겉보기 이득과 선택 불안정이 생길 수 있다는 기제를 보여 준다.
그러나 비교 기준까지 완전히 분리한 대조에서는 공개 선택과 개발 선택의 모의 비공개 차이가 평균 `-0.00000040`, 중앙값 `0`이었고 부호도 한쪽으로 모이지 않았다.
따라서 선택 편향의 위험은 받아들이되, 원 실험의 손실 크기나 모든 고득점 방법의 일반화 실패까지 받아들이지는 않는다.

## 종합 근거

### 고정 판본과 실행 재료

[지정 노트북의 고정 판본과 실행 재료](s6e8-097110-overfit-notebook-artifact.md)는 공개 판본 22, 실행 판본 `343453035`, 실제 입력 판본과 주요 파일의 SHA-256을 고정했다.
Kaggle 공개 원본은 Apache License 2.0 대상으로 다루지만, Naji OOF 및 시험 예측 자료의 사용 조건은 `Unknown`이다.
이 때문에 검토에 필요한 판본, 해시와 집계 수치는 기록하되 Naji 입력과 그 파생 그림 및 저장 실행 자산은 재배포하지 않는다.

### 셀별 주장과 실제 계산

[지정 노트북 코드·차트·본문 전수 대조](s6e8-097110-overfit-cell-audit.md)는 글 7개와 코드 5개를 저장 결과에 모두 연결했다.
OOF 곡선, 모의 공개 선택과 Season 6 집계는 코드가 실제로 계산하지만, 네 공개 점수와 세 제출 참조는 조회 결과가 아니라 직접 적은 상수다.
학생 배열에는 행 식별자, 학습 코드, fold 식별자와 “15개 검증 조각 모두 개선”을 확인할 값이 없어 해당 주장은 검증할 수 없다.

### 별도 구현의 독립 재현

[S6E8 0.97110 초과 과적합 노트북 독립 재현](s6e8-097110-independent-reproduction.md)은 입력 해시와 가능한 행 결속을 확인한 뒤 원문 코드를 복사하지 않은 별도 구현으로 핵심 결과를 다시 계산했다.
OOF 곡선, 원 모의 실험, Season 6 막대와 마지막 296,302행 제출 파일은 재현됐고, 제출 파일의 SHA-256은 저장 파일과 같은 `66781f9298c0b695f68669e18403fc230cfea2a7d9f0d93a3d91bacdd2c6d06d`였다.
다만 학생 OOF와 시험 배열에는 식별자가 없어 그 순서가 공식 행 순서라는 설명을 신뢰해야 하며, 공개 점수와 제출 참조는 독립 재현 대상이 아니다.

### 보편 명제 검증

[S6E8 0.97110 초과 과적합 보편 명제 검증](s6e8-097110-overfit-claim-validity.md)은 점수 경계와 선택 절차를 분리했다.
공개 점수 선택 사실, 선택 편향 위험과 사용하지 않은 라벨에서의 일반화 실패는 서로 다른 판정 대상이다.
높은 공개 점수만으로 방법을 고른 과정이나 비공개 실패를 역추론할 수 없으므로, 실무 규칙은 점수 경계가 아니라 선택 절차에 붙여야 한다.

## 저장소 적용 판단

### 검증 판단

기존의 커밋된 5-fold OOF AUC와 동일 조건 비교를 유지한다.
가중치, 방향, 구성원 또는 후처리를 OOF 전체에서 골랐다면 같은 OOF 점수를 완전히 독립된 채택 근거로 과장하지 않는다.
앙상블 선택과 가중치 학습은 현재 [실험 채택 판정 계약](../adr/0001-experiment-adoption-contract.md)의 nested OOF처럼 선택과 평가를 바깥 fold에서 분리한다.

외부 예측을 검증하거나 재사용할 때는 입력 판본, 내용 해시, 행 식별자와 순서를 확인한다.
길이만 같은 식별자 없는 배열은 행 결속이 입증된 것으로 보지 않는다.
공개 점수와 제출 참조를 기록할 때는 해당 CSV의 SHA-256과 제출 식별자를 함께 묶고, 작성자가 직접 적은 기록과 API로 조회한 사실을 구분한다.

### 실험 판단

`0.97110`을 스크리닝, 확정 재검증, 후보 풀 진입 또는 앙상블 채택 문턱에 추가하지 않는다.
[실험 채택 판정 계약](../adr/0001-experiment-adoption-contract.md)은 공개 점수를 모든 계열의 채택 근거에서 이미 제외하고 있으므로 계약 변경은 필요 없다.

지정 노트북의 `-0.08` 보정 파일은 재사용 가능한 실험 후보로 채택하지 않는다.
학생 신호 자체를 다시 판단하려면 학습 코드, fold 식별자, 행 식별자, 15개 검증 조각 결과와 사용 조건을 먼저 확보하고 저장소의 공통 fold에서 다시 평가한다.
이 근거가 없으면 학생 신호의 OOF 이득이나 다양성 가치를 저장소 실험의 사실로 가져오지 않는다.

### 제출 판단

마일스톤 제출은 CV와 공개 점수가 같은 방향인지 확인하는 건전성 점검으로만 유지한다.
공개 점수의 역전은 검증 근거를 다시 확인하라는 신호이지, 공개 점수 쪽으로 방향이나 가중치를 바꾸라는 신호가 아니다.
공개 점수를 본 뒤 후보를 추가하거나 결합 비율을 바꿨다면 그 후보는 사용하지 않은 라벨 또는 분리된 OOF 절차에서 다시 검증하기 전까지 최종 제출 후보가 아니다.

최종 제출은 OOF 근거와 예측 다양성으로 고르고, `0.97110` 초과 여부나 공개 상단의 근소한 순위 차이를 방어 목표로 삼지 않는다.
지정 노트북의 제출 `55584395`로 지칭된 `-0.08` 파일은 공개 점수 선택의 진단 사례로만 보존하고 최종 제출 후보에서는 제외한다.

## 남은 불확실성과 재검토 조건

S6E8 마감 뒤 비공개 순위가 공개되면 최종 선택된 제출들의 공개 및 비공개 이전성을 사후 확인할 수 있다.
그러나 제출 `55584395`가 최종 채점 대상으로 선택되지 않으면 이 파일의 실제 비공개 성능은 계속 알 수 없고, 최종 순위만으로 선택되지 않은 모든 공개 노트북 산출물을 검사할 수도 없다.

보편 명제를 다시 검토하려면 `0.97110` 초과 노트북과 정확한 예측 파일의 모집단, 공개 점수 조회를 포함한 선택 절차, 같은 파일의 비공개 또는 독립 라벨 결과와 사전에 정한 과적합 기준이 필요하다.
이 전수 감사는 현재 지도의 범위 밖이며, 그 근거가 새로 확보되기 전에는 결론을 `입증되지 않음`으로 유지한다.

Naji 입력의 사용 조건이 명확해지고 학생 신호의 완전한 학습 및 행 계보가 공개되면 재배포 가능성과 실험 후보 자격을 별도로 다시 판단할 수 있다.
그 전에는 현재 문서의 집계 결과와 해시만 검토 근거로 사용한다.
