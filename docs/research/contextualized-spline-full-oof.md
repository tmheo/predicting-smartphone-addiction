# Contextualized spline M0 전체 OOF 판정

이 문서는 GitHub 이슈 [P3 재개: contextualized spline M0의 전체 OOF·nested 결합 기여 결정](https://github.com/tmheo/predicting-smartphone-addiction/issues/171)의 전체 OOF 실행과 채택 판정을 기록한다.

## 결론

`exp085_contextual_spline_m0`의 3시드 평균 OOF AUC는 `0.9681422751`이다.
현재 champion `exp081_lookup_fold_initialization_avg3`의 `0.9691957618`보다 `-0.0010534867` 낮고 세 시드와 다섯 fold에서 한 번도 이기지 못해 champion 교체는 기각한다.

후보는 champion 대비 `-0.01` 진입 하한을 넘었고 최근접 구성원과의 스피어만 상관이 `0.9770420238`로 중복 기준 `0.998`보다 낮아 다양성 조건을 통과했다.
22개 구성원의 균등 순위 평균에 더한 참고 변화도 `+0.0000705984`였다.
따라서 MLflow run `e84d97e875754af1b073b399db2a0616`을 23번째 후보 풀 구성원으로 등록하고 champion은 유지한다.

| fold | AUC |
| --- | ---: |

| 1 | 0.9685747586 |
| 2 | 0.9685395061 |

seed 42 전체 5-fold 스크리닝은 OOF `0.9662304597`로 champion 교체 조건을 놓쳤다.
그러나 champion 대비 `-0.01` 하한과 최근접 스피어만 `0.97152` 조건을 통과해 seed 43과 44를 포함한 확정 재검증으로 넘어갔다.
확정 실행의 seed 42 결과가 스크리닝보다 `-0.0001070604` 낮았지만 다양성 진입 판정은 3시드 평균본으로 다시 수행했다.

## 다양성 판정

확정 실행의 진입 하한은 champion `0.9691957618`에서 `0.01`을 뺀 `0.9591957618`이다.
후보 OOF `0.9681422751`은 이 하한보다 `0.0089465133` 높다.
후보와 가장 가까운 구성원은 champion run `d55d1cd49c194eb8bf7b5128e548df81`이고 스피어만 상관은 `0.9770420238`이다.

기존 22개 구성원의 균등 순위 평균 OOF는 `0.9688447112`였다.
후보를 같은 가중치로 더한 참고 OOF는 `0.9689153097`이며 변화는 `+0.0000705984`다.
이 수치는 진입 조건이 아니라 참고값이고, 실제 진입 근거는 성능 하한과 중복 조건의 동시 통과다.

## 실행과 복구 근거

실행 커밋은 `5381f1a2e515c0aa751193cd66023c6f89df77b8`이고 설정은 `configs/exp085_contextual_spline_m0.yaml`이다.
입력 묶음 SHA-256은 `aed1e28a858358545c005b3d4cc0d835bd262f8b1fbc12ae2d9dea4325e9d124`다.
확정 실행은 Vast.ai RTX A4000 한 장과 고정 이미지 `nvcr.io/nvidia/pytorch@sha256:38ed2ecb2c16d10677006d73fb0a150855d6ec81db8fc66e800b5ae92741007e`에서 수행했다.
원격 run은 `0ffc31f2cc004ea9848709c6a7a28805`이고 반입한 로컬 run은 `e84d97e875754af1b073b399db2a0616`이다.

결과 묶음 SHA-256은 `cecfed7f3f3dcd3ed3504952b895d3f3bb8458085a0838825ad31b4baa543090`이고, 내부 bundle SHA-256은 `598c0567bd0fd5ce90393ea47589db7a31d3d6d5e707d44155c5015706e7f816`이다.
결과 회수 뒤 내부 manifest의 모든 파일과 바깥 묶음의 해시를 다시 검증했다.

초기 확정 시도에서는 상태 확인용 SSH 단절을 제어 스크립트가 치명적 오류로 처리해 완료된 13개 fold의 원격 복구 자료를 회수하기 전에 인스턴스를 삭제했다.
재실행에서는 상태 확인과 입력 전송을 재시도하고 완료 fold 복구 자료를 별도 로컬 묶음으로 주기적으로 내려받았다.
최종 실행의 15개 fold와 결과 묶음을 모두 회수한 뒤 이 작업의 Vast.ai 계산 자원, 별도 저장 공간과 종료 예약이 없음을 확인했다.

## 전체 자료 재학습 길이

확정 실행의 fold별 최적 epoch는 seed 42에서 `[11, 10, 11, 9, 11]`, seed 43에서 `[10, 10, 9, 7, 11]`, seed 44에서 `[10, 10, 9, 9, 9]`다.
시드별 중앙값에 전체 자료 비율 `1.25`를 곱해 사사오입한 재학습 길이는 각각 `14`, `13`, `11` epoch다.
이 값을 `artifacts/full-refit-plan.yaml`에 기록하고, contextualized spline 모델에 검증 자료 없는 고정 epoch 재학습 경로를 추가했다.

## 후속 경계

이 이슈가 처음 열릴 때는 당시 16개 후보 풀에 M0를 더한 nested OOF 재평가까지 범위에 들어 있었다.
이후 [지도: 버린 후보 재검토와 공개 스택 재현으로 public 0.97100](https://github.com/tmheo/predicting-smartphone-addiction/issues/172)이 여러 재개·재현 트랙을 한꺼번에 반영하도록 [보강 풀의 nested 재평가와 결합 전략 재선정](https://github.com/tmheo/predicting-smartphone-addiction/issues/187)으로 통합했다.
따라서 이 문서에서는 M0의 champion·다양성 판정과 후보 풀 등록을 확정하고, 23개 이상 보강 풀의 nested 재평가는 통합 티켓에 넘긴다.
