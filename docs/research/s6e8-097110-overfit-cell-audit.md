# 지정 노트북 코드·차트·본문 전수 대조

이 문서는 GitHub 이슈 [코드·차트·본문의 주장과 근거를 전수 연결한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/248)의 조사 결과다.
검토 대상은 [지정 노트북의 고정 판본과 실행 재료](s6e8-097110-overfit-notebook-artifact.md)가 확정한 공개 판본 22와 실행 판본 `343453035`다.

## 판정

공개 원본의 12개 셀은 글 7개와 코드 5개로 구성되며, 저장 실행 결과에는 다섯 코드 셀의 문자열 출력과 표시 결과를 합쳐 표 4개, 차트 2개와 `submission.csv`가 남아 있다.
실행 기록에는 코드 예외가 없고, 저장 표·차트·문자열은 공개 원본에 적힌 계산과 상수에서 만들어진 결과와 일치한다.
따라서 공개 원본과 저장 실행 결과 사이에서 수치가 바뀌거나 다른 코드를 실행한 흔적은 찾지 못했다.

다만 코드가 직접 계산한 사실과 본문이 외부 기록 또는 작성자의 설명으로 가져온 사실은 명확히 분리해야 한다.
OOF에서 학생 가중치 `-0.08`이 교사 단독보다 `0.00009056` 낮고 `+0.12`가 `0.00005267` 높은 결과는 코드가 계산하지만, 네 제출의 공개 점수와 제출 참조는 코드에 직접 적어 둔 상수다.
이 상수가 정확하다는 조건에서는 공개 순위표로 고른 마지막 보정 방향이 OOF와 반대라는 좁은 진단이 성립한다.
그러나 학생 모형의 15개 검증 조각, 개별 제출 참조와 공개 점수의 결속, `0.97110` 경계, 고득점 노트북 전체의 과적합은 노트북 자체가 입증하지 않는다.

표제는 모든 `0.97110` 초과 노트북을 확률적으로 분류하는 것처럼 읽히지만, 본문은 높은 점수 자체가 아니라 공개 점수를 본 뒤 고른 마지막 미세 보정을 진단 대상으로 좁힌다.
본문의 좁은 판정 단위는 증거와 맞지만 표제의 보편 범위는 맞지 않는다.
이 구분은 [0.97110 초과 과적합 보편 명제 검증](s6e8-097110-overfit-claim-validity.md)의 결론과도 일치한다.

## 표와 차트 전수 대조

### 첫째 표와 첫째 차트

첫째 표는 학생 가중치 `-0.12`, `-0.08`, `0`, `+0.12`의 OOF AUC와 교사 대비 변화량을 새로 계산하고, 코드에 직접 적은 공개 점수 `0.97114`, `0.97115`, `0.97113`, `0.97103`과 나란히 놓는다.
표의 네 OOF 값 `0.96994702`, `0.97000865`, `0.97009921`, `0.97015188`과 변화량은 코드의 51점 곡선에서 해당 가중치를 고른 값과 일치한다.
첫째 차트의 세로축은 공개 점수가 아니라 OOF AUC 변화량이며, 네 공개 점수는 해당 OOF 점 옆의 글자로만 표시된다.
따라서 차트는 두 점수 곡선을 직접 비교한 그림이 아니라 OOF 곡선 위에 작성자의 공개 점수 기록을 주석으로 붙인 그림이다.
저장 그림의 곡선, 네 점, 주석, 축과 제목은 코드와 일치한다.

제출 참조 `55584411`, `55584395`, `55584375`와 Naji 산출물의 공개 점수는 외부 조회 결과가 아니라 `public_ledger` 상수다.
고정 실행에 현재 연결된 Kaggle 제출 객체는 제출 ID `55622435`와 공개 점수 `0.97115`이므로, 저장 실행이 만든 파일과 본문이 가리키는 이전 제출 `55584395`를 같은 제출로 간주할 수 없다.
[0.97110 초과 과적합 보편 명제 검증](s6e8-097110-overfit-claim-validity.md)은 고정 판본의 제출 파일과 별도 재계산 파일이 바이트 단위로 일치함을 확인했지만, 제3자가 제출 `55584395`의 파일 내용과 점수를 다시 조회할 수 있는 계보는 노트북에 없다.

### 둘째 표

둘째 표는 10개 분할 각각의 선택 가중치, 전체 OOF 최적 가중치 대비 공개 부분 이득과 나머지 행 변화량을 보여 준다.
선택 가중치는 `+0.05` 3회, `+0.10` 2회, `+0.15` 5회이며 전체 OOF의 0.05 간격 최적값 `+0.10`과 다른 선택은 8회다.
저장 표의 10개 행과 네 요약 문자열은 코드가 고정 난수 `940813`으로 만든 값과 서로 맞는다.

그러나 `oracle_idx`는 공개 부분과 나머지 행을 모두 포함한 전체 OOF AUC로 고른다.
그러므로 `unseen_private_delta`의 나머지 행은 각 회차의 공개 부분 가중치 선택에는 쓰이지 않았지만 비교 기준 가중치 선택에는 쓰였다.
학생 신호 개발도 이미 전체 OOF 구조에 의존하므로 이 표는 완전히 분리된 검증 자료에서의 일반화 검사가 아니다.

각 회차의 나머지 행은 632,109개로, 실제 S6E8 비공개 부분 약 237,042개보다 2.67배 크다.
10개 분할은 같은 훈련 행을 반복 사용하므로 서로 독립인 10회 실험도 아니다.
이 표는 작은 후보 집합에서도 공개 부분에 맞춘 선택이 달라질 수 있다는 기제를 보여 주지만, 실제 공개 순위표의 손실 크기나 모든 고득점 노트북의 과적합률을 추정하지 않는다.

### 셋째 표와 둘째 차트

셋째 표는 S6E1부터 S6E7까지 팀 수, 공개·비공개 전체 순위의 스피어만 상관, 공개 상위 10팀의 비공개 상위 10 잔존 수, 공개 1위의 비공개 순위와 공개 상위 10팀 중 최악의 비공개 순위를 보여 준다.
잔존 수 `8, 0, 6, 5, 8, 0, 0`, 전체 70자리 중 27자리, S6E2·S6E6·S6E7 전멸과 S6E7 공개 1위의 비공개 440위는 입력 자료와 코드가 만든 표에 일치한다.
둘째 차트는 잔존 수 한 열만 막대로 옮겼으며 제목, 축, 기준선과 막대 높이가 저장 표와 일치한다.

입력 자료 설명은 공개 열이 팀의 최고 공개 제출을, 비공개 열이 팀이 최종 선택한 제출을 나타낸다고 밝힌다.
두 제출 식별자가 다른 비율은 전체 팀의 16.1%이고 각 에피소드 공개 상위 300팀에서는 29%부터 55%지만, 노트북 코드는 이 팀들을 거르지 않는다.
따라서 표와 차트는 동일 예측 파일의 공개·비공개 이전성만이 아니라 팀의 제출 선택과 표본 변화가 합쳐진 사후 순위 변동을 측정한다.
S6E7은 시간상 가장 최근 에피소드지만 S6E8과 같은 ROC AUC 에피소드는 S6E2, S6E3, S6E5이므로 통계적으로 가장 가까운 대조군이라는 근거는 없다.

### 넷째 표와 제출 파일

넷째 표는 마지막 셀이 만든 제출 파일의 첫 5행을 보여 주며, 저장 CSV의 머리 5행과 일치한다.
코드는 Naji 시험 예측의 `id`를 그대로 사용하고 최종 예측이 유한하며 모두 서로 다른지만 확인한다.
공식 시험 자료의 식별자 집합이나 순서와 같은지, 학생 시험 배열이 같은 행 순서인지, 목표 열 이름과 행 수가 공식 제출 형식과 같은지는 확인하지 않는다.

OOF 교사 예측은 `id`로 훈련 자료에 다시 맞추지만 학생 OOF 배열과 시험 배열에는 행 식별자가 없고 길이만 확인한다.
학생 배열이 같은 길이로 뒤섞여도 OOF 검사는 통과하며, 시험 배열이 뒤섞이면 마지막 셀의 세 검증문도 통과할 수 있다.
현재 고정 입력에서는 저장 제출 파일이 정상 생성됐지만 코드 자체는 입력 계보와 행 결속을 강제하지 않는다.

## 코드의 무결성 공백

- `locate`는 이름이 같은 첫 파일을 고르고 파일 해시나 입력 판본을 확인하지 않는다.
- Naji OOF만 `id`로 훈련 자료에 다시 맞추며, 학생 OOF와 시험 배열은 위치로만 결합한다.
- 학생 자료에는 최종 배열과 짧은 설명만 있고 학습 코드, fold 식별자, 15개 검증 조각과 행 식별자가 없다.
- 네 공개 점수와 세 숫자형 제출 참조는 실행 중 조회하거나 파일 해시와 결속하지 않는다.
- 마지막 셀은 공식 시험 식별자, 공식 제출 형식과 학생 시험 배열의 행 결속을 확인하지 않는다.
- 공개 원본은 패키지 판본을 출력하지 않지만, 고정 판본 조사는 실행 컨테이너 다이제스트로 이 공백을 별도 보완했다.

이 공백은 고정 입력에서 저장 출력이 틀렸다는 뜻이 아니다.
다른 입력이나 새 실행에서 같은 의미의 결과를 강제할 장치가 공개 원본에 없다는 뜻이다.

## 후속 재현과 최종 검토에 넘길 경계

[핵심 수치와 차트를 현재 자료로 독립 재현한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/249)는 저장 출력의 수치 일치만 확인해서는 충분하지 않다.
고정 해시와 명시적 경로를 사용하고, 다음 네 경계를 별도로 보고해야 한다.

1. 학생 배열의 행 식별자 부재를 신뢰 전제로 명시하고, 길이 일치와 행 결속을 같은 것으로 취급하지 않는다.
2. 모의 공개 실험은 저장 코드 그대로의 재현과, 비교 기준도 분리한 대조 계산을 구분한다.
3. Season 6 그림은 원 코드의 팀 단위 집계와 가능한 같은 제출 비교를 구분한다.
4. 네 공개 점수와 제출 참조는 계산 결과가 아니라 작성자 기록으로 표시한다.

새 결정 티켓은 만들지 않는다.
발견한 공백은 이미 열려 있는 독립 재현과 최종 종합 티켓의 질문 안에서 판정할 수 있으며, 공개 원본과 저장 실행 결과 사이의 직접 불일치는 발견되지 않아 별도 최소 반증 실험도 필요하지 않다.

최종 검토에서 유지할 좁은 결론은 명확하다.
공개 점수로 마지막 보정 방향을 고른 제출 `55584395`는 OOF가 반대 방향을 지지하므로 공개 점수만으로 비공개 후보에 채택하지 않는다.
반면 `0.97110`이나 높은 공개 점수 자체를 다른 노트북과 예측 파일의 과적합 판정 규칙으로 사용하지 않는다.
