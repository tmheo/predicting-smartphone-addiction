# Fold 실행 관측 계약 인수 기록

## 결론

이슈 355의 판본화 관측 산출물, 고정 MLflow 요약, 워커 사건 전달, 복구 의미, 오류 계약과 실행 기록 묶음 왕복을 구현하고 검증했다.
관측 기능을 켠 전체 원격 실행은 끈 실행보다 5.469초, 1.930% 짧았고 두 실행의 OOF AUC는 `0.9673938549131327`로 정확히 같았다.
초기 구현에서 발견한 사건 기록 지연 p99 상한 위반은 단일 비동기 기록기로 수정했고, 수정본의 Vast.ai 재측정값은 606ns로 50,000ns 상한의 1.212%였다.

## 구현 범위

- 구현 기준 커밋은 `8016f088721872d2edc00c55e261cf9844c493bf`다.
- 사건 기록 지연 수정 커밋은 `c90af19505ff70e4e39ec922aa3bb43fa6f4dc9d`다.
- `observability/fold_execution.jsonl.gz`는 `metadata`, `timing`, `resource`, `summary` 행을 스키마 판본 1로 기록한다.
- 시간 요약은 고정 작업 이름, 겹친 구간의 합집합, 분류되지 않은 시간, 복구 확인과 기록을 포함한다.
- 자원 요약은 2초 간격의 프로세스 트리 CPU와 GPU 표본, 누락률, 장치별 유휴 시간과 모든 장치의 동시 유휴 시간을 포함한다.
- 시드 병렬 워커는 직렬화 가능한 사건을 부모에 전달하며 MLflow에 직접 접근하지 않는다.
- 시간 사건과 관측 산출물 보존 실패는 실행 실패로 처리하고 자원 표본 수집 실패는 누락 표본으로 남겨 실행을 계속한다.
- 실행 기록 묶음은 관측 원본, 원본 SHA-256과 고정 MLflow 지표 이력을 내보내고 검증 후 반입한다.

## 자동 검사

전체 검사 470개가 통과했다.
관측 전용 검사 12개는 다음 경로를 직접 검증한다.

- 정상 실행과 모델 학습 실패의 부모 및 하위 사건을 검증한다.
- 부분 복구와 완전 복구에서 재사용 결과와 생략 사건을 검증한다.
- 순차 실행과 시드 병렬 실행의 결과 일치, 워커 식별자 전달과 부모 기록을 검증한다.
- GPU 없음, 프로세스 트리 CPU 측정 대체, 자원 표본 수집 실패와 누락률을 검증한다.
- 관측 원본 보존 실패가 치명적이고 자원 표본 실패는 치명적이지 않은 계약을 검증한다.
- 판본, 고정 작업 이름, 구간 합집합, 분류되지 않은 시간, 자원 집계와 안정된 MLflow 지표 이름을 검증한다.
- 내보내기와 반입에서 관측 원본 바이트와 SHA-256이 정확히 보존되고 변조 및 중복 반입이 거부되는지 검증한다.

작은 결정적 LightGBM 실행에서도 관측 기능을 켠 실행과 끈 실행의 OOF, 시험 자료 예측, 중요도, fold AUC와 복구 근거를 바이트 수준의 부동소수점 값까지 정확히 비교했다.
이 검사는 `deterministic=true`, `force_row_wise=true`, `n_jobs=1` 조건을 사용하므로 관측 여부만을 독립 변수로 고정한다.

## 전체 원격 실행

고정 이미지는 `nvcr.io/nvidia/pytorch@sha256:a411b86de9ac003ce5db43894ea7920718512bc02c51a521157c0899aac75631`이다.
관측 기능을 켠 실행의 원본 실행 식별자는 `ef0443f16db44c87abff92338f524810`이고 실행 기록 묶음 SHA-256은 `29ed709ecd7cf467ab0001dfd27029139c636722d230db1033bb310ead62885c`다.
관측 기능을 끈 실행의 원본 실행 식별자는 `2687c4d6f0fe4d49917713600aa228ce`이고 실행 기록 묶음 SHA-256은 `3b4dd76135ebcd7acbc37bc1810506e490e4448d8434dd209d6c05aaba8bfbac`다.
관측 기능을 켠 실행은 277.934초, 끈 실행은 283.403초였으므로 경과 시간 차이는 -1.930%로 1% 상한을 통과했다.
독립 기준 반복 실행 `off-b`는 274.370초였고 세 실행의 OOF AUC는 모두 `0.9673938549131327`로 정확히 같았다.

원격 LightGBM 실행 자체는 독립 반복 사이에도 마지막 비트가 일정하지 않았다.
관측 켜짐과 `off-a`의 OOF 최대 절대 차이는 `4.3021142204224816e-13`이고 `off-a`와 `off-b`의 기준 반복 차이는 `8.296419107267639e-13`이다.
관측 켜짐과 `off-a`의 시험 자료 예측 최대 절대 차이는 `1.1507461650239748e-13`이고 기준 반복 차이는 `3.2096547641913276e-13`이다.
관측 켜짐과 `off-a`의 중요도 gain 최대 절대 차이는 `7.0366997718811035`이고 기준 반복 차이는 `10.741000175476074`다.
따라서 원격 차이는 관측 기능 영향보다 작은 기준 실행 자체의 비결정성으로 판정했고, 정확한 동일성 조건은 앞의 결정적 LightGBM 검사로 확인했다.

완주한 관측 원본에는 시간 사건 95개와 자원 표본 131개가 들어 있다.
시간 사건 상한은 105개이며 자원 표본의 가중 관측 구간은 270.585초, 평균 간격은 약 2.066초, 누락률은 0이었다.
계측 CPU 사용량은 평균 0.000543개 코어, 계측 메모리 상한은 570,544바이트로 각각의 상한을 통과했다.
원격 모델은 CPU LightGBM이어서 GPU 사용률은 0이었고, 이 결과는 GPU 장치가 보이지만 모델이 CPU 경로를 쓰는 대체 실행을 기록한다.

## 기록 지연 수정과 재검증

첫 완주 산출물은 사건 기록 지연 p99가 66,140ns여서 50,000ns 상한을 넘었다.
시간 사건을 호출 스레드에서 압축 파일에 직접 쓰던 구조를 단일 비동기 기록기 대기열로 바꾸고, 종료 전에 대기열을 모두 비운 뒤 요약을 쓰도록 수정했다.
기록 실패는 다음 호출이나 종료 처리에서 반드시 치명적 오류로 드러난다.

수정본은 Vast.ai 인스턴스 `48340635`의 RTX 3090에서 CPU 부하 작업 10개와 시간 사건 2,000개로 다시 검증했다.
기록 지연 p99는 606ns, 계측 CPU 사용량은 평균 0.005712개 코어, 계측 메모리 상한은 3,448,732바이트였고 세 항목이 모두 상한을 통과했다.
재검증 관측 원본 SHA-256은 `0ff67bd5c53ebcf7f4eb455189bbd2eb70d11ca6ac238a51237a6b31fd5b1f6a`다.
회수 결과 묶음 SHA-256은 `878b1bbafc3a3507d38402e14f9a23889e42fe5b78154ca5167288c6081472ec`다.

## 중단 실행 보존

Vast.ai 인스턴스 `48337603`의 느린 호스트 실행은 비용 상한을 지키기 위해 다섯 fold 중 세 fold가 끝난 뒤 중단했다.
MLflow 상태는 `KILLED`이고 실행 식별자는 `0a6d01b3f0f4450bb0d91fbda67a2c13`다.
중단 산출물은 완료한 세 fold 복구 지점, 시간 사건 62개, 자원 표본 281개와 마지막 `summary` 행을 보존했다.
중단 관측 원본 SHA-256은 `8ef348cd7e5023eb67669ecd9857027bef2e83a4addc63c0950922308142bdf7`다.
회수 결과 묶음 SHA-256은 `bceed240e9f3a447c879f972f2532e8923066d36de24176644de25989e3b20fe`이고 조사 묶음 SHA-256은 `9bb914c51ce6c363801866aa82eecac2daf6dc451a6d481388fd0ca58765d0f1`다.

## 실행 기록 묶음 반입

관측 켜짐 묶음은 주 작업공간 MLflow 실행 `4b17ad35020a4155bfd4c47263f768ca`로 반입했다.
반입된 `observability/fold_execution.jsonl.gz` SHA-256은 원본 태그와 같은 `90c4c4e3d96b92246fceb642264fb34bba939dbf749261df4943c6067ee73deb`다.
관측 끄기 기준 묶음은 주 작업공간 MLflow 실행 `856a1f5003914423ab5d455a89b5b274`로 반입했다.

같은 관측 묶음의 두 번째 반입은 기존 실행 식별자를 알려 주며 거부됐다.

## 비용과 정리

이슈 355의 Vast.ai 청구 비용은 인스턴스별로 0.037, 0.032, 0.077, 0.000, 0.111, 0.010달러이며 합계는 0.267달러다.
계획한 누적 상한 0.250달러보다 0.017달러 초과했으며, 입력 검사 재시도, 고정 이미지 내려받기와 삭제 반영 지연이 포함됐다.
Runpod는 사용 가능한 크레딧이 없어 자원을 만들지 않았고 비용도 발생하지 않았다.
이슈 355의 Vast.ai 인스턴스와 저장 공간은 모두 삭제했으며 계정 목록에서 부재를 확인했다.
동시에 실행 중이던 다른 이슈의 자원은 이 작업의 범위가 아니므로 건드리지 않았다.

세부 전송 해시, 호스트 실패, 회수 자료와 삭제 확인은 무시 파일인 `run-logs/issue355-fold-observability/ledger.md`와 같은 디렉터리의 원본 자료에 보존했다.
