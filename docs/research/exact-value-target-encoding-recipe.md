## 원문별 근거

### As a Beginner, What's the First Thing You Check in a Tabular Competition?

원문: [Kaggle 디스커션 733495](https://www.kaggle.com/competitions/playground-series-s6e8/discussion/733495)

Mayank Garg의 본문은 초보자가 탐색, 기준 모델, 피처 설계, 검증, 조정 중 어디에 먼저 시간을 써야 하는지 묻는다.
정확값 타깃 인코딩의 구현 세부는 Georgy Mamarin의 [댓글](https://www.kaggle.com/competitions/playground-series-s6e8/discussion/733495#3510030)과 [정정 댓글](https://www.kaggle.com/competitions/playground-series-s6e8/discussion/733495#3510644)에 있다.

Georgy Mamarin은 같은 모델과 같은 5-fold 분할에서 OOF로 변화를 측정했다고 설명한다.
그는 각 컬럼을 수치량으로 취급하는 대신 정확한 값으로 타깃 인코딩하면 OOF AUC가 +0.0032 개선됐다고 정정했다.
또 데이터가 생성되고 반올림되어 격자 위에 놓였으며 정확값 인코딩이 그 격자를 포착한다고 설명했다.

이 댓글은 데이터에 이미 존재하는 반올림 격자를 근거로 들 뿐, 새 반올림 단계나 문자열 변환 코드를 제시하지 않는다.
원 수치 컬럼 유지 여부, 평활, 최소 빈도, NaN 처리도 설명하지 않는다.
5-fold는 실험 성능을 재는 OOF 검증으로 명시되지만, 그 안에서 인코딩 값을 어떻게 계산했는지는 이 스레드만으로 알 수 없다.

### My finding on the data and some questions

원문: [Kaggle 디스커션 733730](https://www.kaggle.com/competitions/playground-series-s6e8/discussion/733730)

xuanxuan496의 본문은 `daily_screen_time_hours`와 다른 시간 특성 사이에서 관찰한 경계를 어떻게 피처로 만들지 묻는다.
정확값 타깃 인코딩과 누수 경고는 Georgy Mamarin의 [댓글](https://www.kaggle.com/competitions/playground-series-s6e8/discussion/733730#3510375)에 있다.

Georgy Mamarin은 LightGBM 기준 모델의 용량을 높인 뒤 각 컬럼을 정확한 값으로 타깃 인코딩했을 때 +0.0032가 추가됐다고 보고한다.
그는 OMID BAGHCHEH SARAEI의 아이디어이며 tomasa2가 독립 측정했고 tamerlanomralinov도 사용했다고 출처 맥락을 설명한다.

누수 방지 지침은 직접적이다.
인코딩은 각 학습 fold 안에서 적합하고 전체 학습 데이터로 적합해서는 안 되며, 그렇게 하면 검증 점수만 크게 뛰고 실제 개선은 없다고 경고한다.
다만 학습 fold 내부의 각 학습 행 값도 별도 내부 OOF로 만드는지, 학습 fold 전체 평균표를 그대로 쓰는지는 설명하지 않는다.

이 댓글은 정확값 키를 만드는 구체적인 문자열 변환이나 반올림, 원 수치 컬럼 병행 여부, 평활, 최소 빈도, NaN 처리를 말하지 않는다.
또 모든 수치가 5-fold OOF인지 여부는 댓글의 다른 피처 측정에는 명시되어 있지만, 정확값 인코딩을 위한 내부 분할 수는 제시하지 않는다.

### Decoding the Synthetic Generator: 0.9689+ via Stringified Target Encoding and Rank Averaging

원문: [Kaggle 디스커션 734063](https://www.kaggle.com/competitions/playground-series-s6e8/discussion/734063)

작성자는 E散人chloeprice다.
작성자 본문은 세 스레드 가운데 키 생성과 평균표 분할을 가장 구체적으로 설명한다.

작성자는 모든 연속 수치 변수에 `.astype(str)`를 적용하고, 각 고유 부동소수 값을 서로 다른 범주로 취급했다고 썼다.
이어 이 문자열 범주를 타깃 평균값으로 변환해 모델이 연속 분할 대신 값별 경험 확률을 조회하게 한다고 설명했다.
원 수치 특성을 사용하는 대신 이 방법을 썼다는 서술은 교체를 강하게 시사한다.
그러나 실제 모델 입력 컬럼 목록을 제시하지 않아, 원 수치 컬럼을 완전히 제거했는지 인코딩 컬럼과 함께 넣었는지는 확정할 수 없다.

작성자는 누수를 엄격히 막고 평균표를 정확하게 만들기 위해 10-fold 층화 교차 검증 안에서 OOF 타깃 인코딩을 계산했다고 썼다.
5-fold 대신 10-fold를 쓰면 각 OOF 평균표가 데이터의 90%를 사용하므로 분포 꼬리의 희소한 격자점 확률을 더 안정적으로 추정할 수 있다는 이유도 제시했다.
그러나 뒤이어 설명한 LightGBM과 XGBoost 학습 및 순위 평균이 같은 10-fold 모델 검증의 결과인지는 명시하지 않았다.

작성자 본인의 [유일한 댓글](https://www.kaggle.com/competitions/playground-series-s6e8/discussion/734063#3510950)은 다른 디스커션의 차트를 보고 수치 특성을 모두 문자열 범주로 바꾸는 발상을 얻었다는 배경 설명이다.
구현 세부를 추가하지는 않는다.

본문은 추가 반올림, 평활, 최소 빈도, 보지 못한 키의 대체값, NaN 처리를 설명하지 않는다.

## 구현 전에 남은 결정 질문

1. 최종 모델 성능을 재는 바깥쪽 분할과 10-fold 평균표 생성을 어떻게 중첩할 것인가.
   원문은 전체 학습 데이터로 평균표를 만들지 말라고 하지만, 바깥쪽 학습 구간 안에서 다시 10-fold OOF 값을 만드는 완전한 중첩 절차까지는 설명하지 않는다.
2. 검증 또는 시험 데이터에서 처음 보는 정확값 키를 어떤 값으로 대체할 것인가.
   전체 양성률, 해당 컬럼 평균, 인접 격자점 등 어느 방식도 원문에 제시되지 않았다.
3. 희귀 키에 평활이나 최소 빈도 기준을 둘 것인가.
   10-fold로 평균표 표본을 늘린다는 원칙만 확인됐으며, 희귀 키 처리 규칙은 새로 결정해야 한다.
4. NaN을 하나의 정확값 범주로 만들 것인가, 트리 모델이 처리할 원 결측으로 남길 것인가.
   문자열화 단계에서 생길 수 있는 동작을 의도된 설계로 간주할 근거가 없다.
5. 기존 범주형 컬럼까지 타깃 인코딩할 것인가.
   733495와 733730은 각 컬럼이라고 표현하지만, 734063의 구체적 문자열화 절차는 모든 연속 수치 변수만 대상으로 적는다.

## 조사 결론

세 스레드가 공동으로 뒷받침하는 최소 레시피는 격자형 수치의 정확값을 별도 범주로 보고 값별 타깃 평균을 만들며, 그 평균은 전체 학습 데이터가 아니라 학습 fold 안에서 계산하는 것이다.
문자열 키는 734063의 `.astype(str)`로 확인된다.
추가 반올림, 평활, 최소 빈도, NaN, 보지 못한 키 대체는 원문에 없으므로 구현자가 임의로 원 레시피의 일부라고 주장해서는 안 된다.
원 수치 컬럼 교체는 강하게 시사되지만 병행 여부를 확정할 입력 목록은 없다.
10-fold는 평균표가 90%의 행을 사용하게 하는 근거로는 확인되지만, 모델 검증 전체의 분할 수로는 확정되지 않는다.
