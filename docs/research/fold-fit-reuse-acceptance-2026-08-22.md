# 내용 기반 fold-fit 재사용 결과 저장소 인수 기록

## 결론

이슈 357의 내용 기반 fold-fit 재사용 결과 저장소를 구현하고 기능, 정확성, 복구, 원격 전송과 성능 완료 조건을 검증했다.
재사용 미적중 독립 실행의 청구 대상 전체 시간은 406.906초로 역사 기준 401초보다 1.473% 길어 5% 허용 범위를 통과했다.
모든 항목이 적중한 독립 LightGBM 실행의 교차 검증 내부 시간은 282.936초에서 67.833초로 76.025% 줄어 45% 기준을 통과했다.
같은 적중 실행의 청구 대상 전체 시간은 406.906초에서 194.264초로 52.258% 줄어 25% 기준을 통과했다.
재사용 비활성, 미적중과 적중 실행의 OOF, 시험 자료 예측, 중요도, 제출 자료, AUC, 피처 목록, 결정적 학습 의미 자료와 폴드 복구 자료는 정확히 같았다.

## 구현

- 구현 커밋은 `ca2df32d9464e32e53df4ff2d2b6926e8f61243d`, `3b8b1aceaafbc60602391e242601df7e81539ea6`, `e2a28f86b8a20d8a689538a399cb6573998b368b`다.
- 일곱 fold-fit 제공자는 선언 입력과 출력, 타깃 참조 여부, 의미 있는 설정, 외부 파일과 CPU 또는 CUDA 실행 방식을 내용 정체성으로 제공한다.
- 내용 키는 입력 파일과 값, 행 정체성, 시드, 폴드, 제공자 선언, Git 커밋, 의존성 잠금과 설치 판본, Python과 운영체제 실행 환경을 포함한다.
- `run-cache/fold-fit/v1/` 항목은 `manifest.json`, `train.parquet`, `test.parquet`와 파일 및 값 SHA-256으로 구성한 불변 디렉터리다.
- 항목별 파일 잠금, 같은 파일시스템의 임시 디렉터리, 파일과 디렉터리 동기화, 원자적 이름 변경과 읽기 전용 확정을 구현했다.
- 진짜 미적중만 새로 계산하며 손상된 예상 키, 사용할 수 없는 명시적 저장소, 지원하지 않는 파일시스템과 묶음 손상은 계산으로 숨기지 않고 실패한다.
- 실행 중단 뒤 남은 임시 디렉터리는 최종 항목으로 간주하지 않고 다음 작성자가 제거한 뒤 복구한다.
- 반입 묶음은 모든 항목을 먼저 검증한 뒤 하나씩 게시하며, 내보내기 묶음은 실행 근거가 참조한 키만 포함한다.
- 다섯 폴드 복구 자료를 모두 먼저 검증한 뒤 미완료 폴드의 제공자만 재사용 저장소를 조회한다.
- 기본 실행은 재사용을 켜고 `--no-fold-fit-reuse`로 명시적으로 끌 수 있다.
- 실행별 `fold_feature_reuse.json`은 각 시드, 폴드와 제공자의 `generated`, `hit`, `unused` 상태, 내용 키와 manifest 해시를 기록한다.
- LightGBM의 명시적 결정을 보존하면서 기본 결정성을 켜 반복 실행의 예측과 중요도를 정확히 같게 만들었다.

## 자동 검사와 환경 관문

- 제공자, 입력, 타깃, 행, 환경과 실행 방식 변화에 따른 적중과 미적중을 검사했다.
- 동시 요청의 단일 계산, 쓰기 중단, 남은 임시 디렉터리, 손상된 최종 항목, 사용할 수 없는 저장소와 지원하지 않는 파일시스템을 검사했다.
- 묶음 반입과 내보내기, 복구 선검증 순서, 명시적 비활성화, 실행 근거 연결과 정확한 LightGBM 반복 결과를 검사했다.
- 최종 구현 커밋의 격리 환경 관문은 비공개 입력 검사, 검사 489개 수집, 원격 Python 계약 검사 4개와 전체 검사 489개를 통과했다.
- 고정 이미지 `nvcr.io/nvidia/pytorch@sha256:a411b86de9ac003ce5db43894ea7920718512bc02c51a521157c0899aac75631`의 Python 관문도 통과했다.

## 성능 판정

- 역사 LightGBM 기준의 청구 대상 전체 시간은 401초이고 5% 허용 상한은 421.05초다.
- 독립 미적중의 406.906초는 기준보다 1.473% 길어 허용 상한을 통과했다.
- 독립 전부 적중의 내부 시간 67.833초는 독립 미적중 282.936초보다 76.025% 짧아 45% 기준을 통과했다.
- 독립 전부 적중의 전체 시간 194.264초는 독립 미적중 406.906초보다 52.258% 짧아 25% 기준을 통과했다.
- 독립 전부 적중의 전체 시간은 역사 기준과 비교해도 51.555% 짧다.
- 재사용 미적중 내부 시간은 비활성 대조보다 0.405% 짧아 저장소 사용 자체가 정상 계산 시간을 늘리지 않았다.

## 실패 시도와 비용

- 첫 구현은 생성 직후 결과를 다시 읽는 비용과 행 식별자 전체를 manifest에 넣은 크기 문제를 드러내 수정했다.
- 두 번째 구현은 내부 미적중 시간이 역사 기준의 5%를 2.214초 넘었고 LightGBM 병렬 실행의 미세한 비결정성을 드러내 수정했다.
- 세 번째 구현은 결과 정확성과 내부 시간 기준을 통과했지만 SSH 키 준비 지연과 공급자 망의 의존성 내려받기 지연 때문에 전체 시간 비교가 유효하지 않았다.
- 재사용 묶음을 입력에 직접 넣은 독립 적중 시도는 238MB 입력 전송만으로 전체 시간 상한을 넘게 되어 모델 실행 전에 중단했다.
- 최종 독립 비교는 같은 의존성 내려받기 저장소를 두 실행에 공정하게 제공하고, fold-fit 저장소는 미적중 실행이 처음 채우도록 분리했다.
- 최종 적중 첫 시도는 SSH 인증 준비만으로 최근 실측 하한을 더한 전체 시간 상한을 넘게 되어 입력 없이 중단했다.
- Vast.ai 청구 내역의 이슈 357 인스턴스 열 개와 작업 전용 저장소 한 개 비용 합계는 0.532달러다.
- 실제 비용은 예약한 0.450달러보다 0.082달러 초과했다.
- 구현 결함을 찾은 세 차례 원격 수정, 느린 결과 회수와 SSH 인증 준비 지연이 비용 초과의 주원인이다.

## 정리

- 이슈 357에서 만든 Vast.ai 인스턴스 열 개를 모두 삭제했다.
- 최종 비교용 작업 전용 저장소도 삭제했고 계정의 별도 저장 공간이 0개임을 확인했다.
- 다른 이슈의 `issue339-pool-rereview-vast-attempt6` 인스턴스는 건드리지 않았다.
- 비활성 대조, 독립 미적중과 독립 적중 실행 묶음을 주 작업공간 MLflow에 반입하고 필수 산출물과 해시 태그를 다시 조회했다.
- 세부 전송 해시, 상태 변화와 중단 근거는 무시 파일인 `run-logs/issue357-fold-fit-reuse/ledger.md`와 같은 디렉터리의 원본 자료에 보존했다.

## 상위 이슈 인계

이 문서는 이슈 357의 구현과 LightGBM 재사용 단계 인수 근거다.
상위 이슈 352의 최종 완료에는 최종 명세대로 구현 전후 커밋을 독립 인스턴스에서 순서를 뒤집어 실행한 쌍 비교와 표 합성곱망 기준을 포함한 `docs/research/fold-execution-acceleration-acceptance.json`이 별도로 필요하다.
