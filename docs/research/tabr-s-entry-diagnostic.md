# TabR-S 진입 진단

이 문서는 GitHub 이슈 [#142](https://github.com/tmheo/predicting-smartphone-addiction/issues/142)의 구현과 Vast.ai fold 0 진입 진단 결과를 기록한다.

## 결론

TabR-S는 fold 0 seed 42에서 AUC `0.9419956232`를 기록했다.
같은 fold의 champion AUC `0.9685285491`보다 `0.0265329259` 낮아 허용 폭 `0.01`을 넘었다.
시간, 메모리, 예측 무결성과 후보 저장소 격리는 모두 통과했지만 성능 문턱에서 탈락했다.
이슈 규칙에 따라 배치 축소 재측정, seed 42 5-fold, 중복·표준 순위 평균 기여 측정과 3시드 확정 재검증은 실행하지 않는다.
champion과 후보 풀은 바꾸지 않는다.

## 구현

`src/pipeline/tabr_s.py`에 공식 TabR-S의 선형 encoder, 라벨 encoder, 검색 기반 문맥 결합과 한 블록 predictor를 별도 구현했다.
기준 구현은 `yandex-research/tabular-dl-tabr`의 MIT 판본 커밋 `17baa9082506f8e7a0f8d11bb1e08212926a1507`이다.
`TabRSAdapter`와 `MODEL_REGISTRY`의 `tabr_s` 항목을 통해 기존 실행 계약에 연결했다.
설정 `configs/exp082_tabr_s.yaml`은 champion과 같은 33개 특성, 문맥 96개, 두 epoch, 첫 epoch 뒤 문맥 고정, seed 고정 검증 행 8,192개와 permutation 반복 1회를 사용한다.
검증 행과 라벨은 후보 저장소에 들어가지 않으며 학습 query는 자기 행을 검색 결과에서 제외한다.

첫 실행 판본은 프로젝트 로컬 환경과 같은 NumPy `2.5.2`를 설치했지만 NGC PyTorch가 NumPy 배열을 읽지 못해 모델 학습 전에 중단됐다.
실패 결과 묶음을 회수하고 새 작업 식별자와 경로를 사용해 NumPy `1.26.4`로 고정했으며, PyTorch 배열 변환을 사전 검사에 추가한 두 번째 판본에서 진단을 완료했다.
두 번째 입력 묶음 SHA-256은 `973d5518f5a8060869eda15139df417955139bfa1a5b33083fbcb3845e5c6240`이다.
학습 자료 SHA-256은 `f4669147311c76eb03496061a852af283efcf0f12cf5c19274e775def81edd9c`이고 fold 자료 SHA-256은 `5f5d09e9356f227ecb4a063270b175bb5cae20afb25636c563db185e18a155c4`다.

검증 예측과 테스트 예측은 모두 행 수, 순서와 유한성 검사를 통과했다.

## 판정과 자원 정리

fold 시간은 4시간 한도, 장치 메모리는 90% 한도, 5-fold 예상 시간은 20시간 한도를 모두 통과했으므로 배치 축소 조건은 발생하지 않았다.
fold AUC가 champion보다 0.01 넘게 낮아 성능 중단 조건이 발생했다.
두 Vast.ai 인스턴스와 별도 저장 공간이 계정 목록에서 사라졌고 GitHub 보조 종료 예약도 빈 배열로 되돌렸다.
첫 SSH 제어 실패를 포함한 총비용은 약 `$0.115793`이다.
