# Public 0.97129 `OVERFITTING TRAP` 노트북 검토

이 문서는 GitHub 이슈 [Public 0.97129 overfitting trap 노트북의 독립 신호와 확장 스택 가치를 판정한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/466)의 조사 결과다.
조사 대상은 najiama의 [`OVERFITTING TRAP - Do Not Copy-Educational Only` 고정 판본](https://www.kaggle.com/code/najiama/overfitting-trap-do-not-copy-educational-only?scriptVersionId=345402813)이다.

## 결론

Public `0.97129`는 새 모형, 새 단일 구성원, OOF와 시험 예측의 새 쌍이 아니다.
고정 판본이 실제로 하는 일은 AnthonyTherrien의 저장 `submission.csv`에 90%, 출처와 생성법이 설명되지 않은 `najiama/s6e8-psa/submission.csv`에 10%를 주어 행 위치대로 더하는 것뿐이다.

Anthony 제출도 독립 신경망 출력이 아니다.
Anthony 판본의 최종 출력은 외부 제출 두 장을 `2.9:0.1`로 섞고 자체 신경망을 `0.0001`만 보탠 뒤 정규화한 2단계 산출물이다.
이를 0.97129 파일까지 펼치면 실제 비중은 Anthony vault `sub1` 86.9971001%, `sub2` 2.9999000%, Anthony 신경망 0.0029999%, 설명 없는 Naji 제출 10%다.
따라서 0.97129는 기반 모형 관점에서 적어도 3단계인 공개 제출 재조합물이다.

고정 자료에서는 296,302개 시험 행의 식별자, 순서, 유일성과 유한값이 모두 맞고 목표값을 직접 읽는 고전적인 자료 누출도 없다.
그러나 최종 노트북 코드는 두 입력의 식별자가 같은지 검사하지 않고 pandas 기본 행 번호에 기대어 값을 더하므로, 둘째 파일이 재정렬되면 조용히 다른 행끼리 섞인다.
현재 산출물이 맞는 것은 입력 파일이 우연히가 아니라 실제로 같은 순서를 가졌기 때문이지 코드가 안전성을 보장했기 때문은 아니다.

더 중요한 위험은 Public 순위표를 반복 검증 자료로 사용한 적응형 과적합이다.
본문은 여러 혼합 방향, 가중치, 마스킹, 미세 재정렬 결과를 Public 점수로 비교한 뒤 마지막 90:10 조합을 내놓으며, 저자도 OOF 검증과 새 학습 논리가 전혀 없다고 명시한다.
이는 비공개 점수를 이미 확인한 일반화 실패의 증명은 아니지만, Public 표본에 대한 반복 선택 편향이 큰 산출물이라는 판정에는 충분하다.

이 파일에서 `0.97128` 대비 `+0.00001`의 Public 증가는 [넓힌 확장 스택을 nested OOF 사다리로 재판정한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/455)의 판정과 비교할 수 있는 독립 증거가 아니다.
Public 변화량과 nested OOF 교체 문턱은 서로 다른 평가량이므로 수치 문턱에도 직접 대입하지 않는다.
새로 편입할 수 있는 OOF와 시험 예측 쌍은 0개이며, 313구성원 장부에 증분을 만들거나 nested OOF 사다리를 다시 돌릴 가치가 없다.
이 노트북은 Public 순위표 추종의 교육용 사례로만 기록하고 확장 스택 입력에서는 제외한다.

## 산식과 행 일치 재현

공식 Kaggle 출력으로 받은 두 입력과 최종 파일을 독립적으로 읽어 다음을 확인했다.

- 세 파일 모두 `id`, `addicted_label` 두 열과 자료행 296,302개를 가진다.
- 식별자는 모두 `691369`부터 `987670`까지 같은 순서이며, 집합과 순서가 대회 `sample_submission.csv`와 정확히 같다.
- 식별자 중복, 결측값, 무한값은 없다.
- 최종 예측값 범위는 `1.3232168446428331e-05`부터 `0.9999908868800474`까지다.
- 다시 계산한 `0.9 * Anthony + 0.1 * Naji`와 저장 최종값의 최대 절대 차이는 부동소수점 반올림 범위인 `1.11e-16`이다.
- 최종값과 Anthony 입력의 피어슨 상관은 `0.9999687346`, 스피어만 순위 상관은 `0.9999648145`다.

따라서 Public `0.97129`를 만드는 직접 산식과 현재 행 정렬은 재현된다.
반면 코드에는 `id` 동일성, 행 수, 열 이름, 결측과 유한값을 확인하는 단언이 없다.
`df_blend = df1.copy()` 뒤 두 pandas Series를 기본 행 번호로 더하므로 둘째 입력의 행 순서가 달라져도 오류가 나지 않는다.

## OOF, 분할과 독립 신호 판정

대상 노트북은 학습 자료와 목표값을 읽지 않으며 OOF 파일을 만들지도 읽지도 않는다.
두 활성 입력은 시험 제출 파일뿐이고 대응 OOF가 없다.
따라서 커뮤니티 고정 5분할, `artifacts/folds.parquet`, 원본 학습행 순서 또는 fold별 누출 여부를 대조할 대상 자체가 없다.

Anthony 실행 기록은 LightGBM 5분할 OOF `0.962660`, 별도 검증 `0.961714`, 신경망 최고 별도 검증 `0.961451`을 남긴다.
그러나 자체 신경망의 최종 실효 비중은 0.0029999%뿐이고 나머지 99.9970001%는 OOF가 없는 외부 제출과 Naji 제출이다.
이 수치는 Anthony 혼합이나 최종 0.97129 혼합을 검증하지 않는다.

새 구성원 판정은 다음과 같다.

| 질문 | 판정 |
| --- | --- |
| 새 단일 모형인가 | 아니오 |
| 새 기반 모형 OOF와 시험 예측 쌍인가 | 아니오 |
| 고정 5분할 근거가 있는가 | 아니오 |
| 직접 공개 제출 혼합인가 | 예 |
| 2단계 산출물인가 | 예, 최종 기준으로는 적어도 3단계 |
| 행 정렬이 현재 파일에서 맞는가 | 예 |
| 코드가 행 정렬을 검증하는가 | 아니오 |
| 고전적인 목표값 누출이 보이는가 | 대상 노트북에는 없음 |
| Public 점수 적응 선택이 있는가 | 예 |
| 독립 신호를 입증하는가 | 아니오 |

## Public 과적합 기제

Public 순위표는 시험 자료 일부의 숨은 목표값으로 계산된다.
같은 참가자가 여러 후보의 점수를 반복해서 보고 혼합 방향, 원천과 가중치를 바꾸면 그 일부가 사실상 검증 자료로 바뀐다.

고정 본문은 logit 혼합, 순위 혼합, 불확실 구간 마스킹, 음수 가중치, 동률 해소, 거꾸로 미세 정렬, 두 공개 제출 혼합을 차례로 Public 점수에 맞춰 비교한다.
마지막 90:10 가중치도 OOF나 사전 고정 기준이 아니라 Public `0.97129` 결과로 제시된다.
이는 후보 수가 늘수록 우연히 Public 부분에 잘 맞는 조합을 고르게 되는 다중 비교와 선택 편향이다.

Public `0.97129`만으로 비공개 점수가 나빠진다고 확정할 수는 없다.
다만 [0.97110 과적합 주장 검토](s6e8-097110-overfit-claim-validity.md)가 정리했듯 Public 경계를 넘었다는 사실 자체보다 후보를 Public 점수로 고른 생성 과정이 위험의 핵심이다.
이번 노트북은 저자가 그 과정을 직접 서술하고 코드로 남겼으므로 적응형 Public 과적합 위험은 이전의 일반적인 경고보다 더 직접적이다.

## 이용 조건과 재현성

[Kaggle 공개 노트북 사용 조건](../agents/kaggle-public-notebook-licensing.md)과 고정 페이지의 표시를 따라 대상 및 Anthony 공개 노트북 소스는 Apache License 2.0으로 다룬다.
코드를 복사하거나 수정해 배포한다면 판본과 출처, 원래 고지, 변경 사실을 남겨야 한다.

이 허가는 노트북 입력과 출력의 이용 조건을 대신하지 않는다.
Naji `s6e8-psa` v4는 `Unknown`이고, Anthony vault v7의 MIT 표시는 원 제출 파일별 권리와 출처를 완결하지 않는다.
원 입력과 최종 제출 파일은 저장소에 복사하거나 다시 배포하지 않는다.

프로젝트의 공개 예측 배열 사용 한정 규칙은 이용 조건이 불명확한 배열도 확장 스택 결합 입력으로만 사용할 수 있게 한다.
그러나 같은 규칙이 행 검증과 2단계 산출물 제외를 유지하며, [외부 구성원 장부](external-member-ledger.md)는 OOF 없는 제출 전용 자료와 2단계 스택을 편입하지 않는다.
따라서 이용 조건만 완화해도 이번 산출물은 자격을 얻지 못한다.

비트 단위 원본 재취득은 고정 판본이 현재로 유지되는 동안 가능하다.
그러나 Naji 활성 입력의 생성 코드와 상류 원 예측, Anthony vault 두 파일의 정확한 원 판본, 두 혼합의 대응 OOF가 없어 방법 수준 재현은 불가능하다.
재현되는 것은 이미 만들어진 시험 제출 두 장의 산술 혼합뿐이다.

## 넓힌 확장 스택 판정 기준과 이번 결정

[넓힌 확장 스택 nested OOF 사다리 재판정](extended-stack-ladder-2.md)은 `ablate_new_nhtquyn` 313구성원을 `shrunk_rank_logit_logistic`으로 결합해 nested OOF `0.9703509`, 가중 OOF `0.9712170`, 이전 판 대비 `+0.0000633`, 바깥쪽 분할 5/5 양수를 얻었다.
그 판정은 각 외부 열에 학습행 OOF와 시험 예측이 함께 있어야 같은 바깥쪽 분할 안에서 메타 모형을 적합할 수 있다는 전제에 선다.

이번 0.97129 파일은 시험 열 하나만 추가할 수 있고 대응 OOF 열이 없다.
그 시험 열도 새 기반 신호가 아니라 장부가 제외하는 외부 제출 재조합 및 2단계 산출물이다.
기존 45개 공개 노트북 출력물이 `+4.3e-05`를 기여했다는 묶음 절제 결과는 OOF와 시험 예측 쌍을 가진 기반 출력물에 대한 결과이므로 이번 파일에 외삽할 수 없다.

Public `0.97128`에서 `0.97129`로 오른 `0.00001`은 사다리 교체 문턱 `+0.00002`와 비교하지 않는다.
전자는 숨은 시험 일부를 반복 조회해 선택한 점수 차이고, 후자는 결과 확인 전에 고정한 nested OOF 차이다.
더구나 [공개 OOF 라이브러리 확장 스택 지도](https://github.com/tmheo/predicting-smartphone-addiction/issues/441)는 Anthony `0.97128` 계열을 이미 출처 없는 제출 CSV 재게시 또는 혼합으로 분류해 근거에서 제외했다.
0.97129는 그 제외된 기준 파일에 설명 없는 제출을 10% 더한 것이므로 결론을 바꿀 새 증거가 없다.

최종 결정은 다음과 같다.

1. 외부 구성원 장부에 새 통과 구성원으로 추가하지 않는다.
2. 313구성원 확장 스택의 nested OOF 사다리를 다시 실행하지 않는다.
3. 0.97129 파일이나 두 상류 제출 파일을 저장소, 후보 풀, 최종 제출 산출물에 넣지 않는다.
4. Public 점수 적응 선택의 교육용 사례와 출처 감식 기록으로만 보존한다.
5. 후속 검토는 상류 기반 모형별 학습 코드, 고정 5분할 OOF, 같은 순서의 시험 예측, 식별자, 원 판본과 이용 조건이 함께 공개될 때만 연다.
6. 자료가 공개되더라도 최종 혼합물이 아니라 독립 기반 모형만 장부 후보로 재검토한다.

## 남은 한계

Naji `s6e8-psa/submission.csv`의 원 예측과 생성 코드는 공개되지 않아 10% 신호가 기존 장부의 어느 구성원과 중복되는지 정량 확정하지 못했다.
높은 최종 상관만으로 그 파일이 Anthony 입력의 복사본이라고 주장하지 않는다.

Anthony vault v7의 두 외부 파일도 원 저자와 판본 매핑이 없으므로 구체적인 상류 계보는 멈춘다.
이 불확실성은 편입을 보류하는 근거를 약하게 하지 않는다.
독립성, OOF, 분할 근거가 없다는 확인 가능한 사실만으로도 장부와 사다리 기준에서 탈락하기 때문이다.

비공개 순위표가 아직 공개되지 않아 이 정확한 제출의 실제 비공개 AUC와 순위 변동은 알 수 없다.
따라서 이 문서는 실제 비공개 성능 저하를 단정하지 않고, 생성 과정의 Public 적응 과적합 위험과 프로젝트 편입 자격만 판정한다.
