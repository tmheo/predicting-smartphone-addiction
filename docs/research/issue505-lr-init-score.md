# 정확값 선형 OOF 로짓을 LightGBM 초기 점수로 주는 잔차 대조

이 문서는 GitHub 이슈 [#505](https://github.com/tmheo/predicting-smartphone-addiction/issues/505)의 구현과 판정 결과를 기록한다.
후보는 이슈가 결과를 보기 전에 고정한 한 좌표이며, 내부 분할 수, 로지스틱 규제 강도, LightGBM 설정과 피처는 결과를 본 뒤 바꾸지 않았다.

## 결론

- 후보 `exp209_issue505_lgb_lr_onehot_init`(exp110 + 정확값 one-hot L2 로지스틱 회귀의 내부 OOF 로짓 초기 점수)은 같은 커밋 `74984a0`의 exp110 기준을 seed 42에서 전체 OOF `+0.0008826`, 분할 5/5로 앞섰다.
- 3시드 평균본 OOF는 `0.9681041`(seed 42 `0.9680126`, 43 `0.9680066`, 44 `0.9680048`)로, 기록된 exp110 3시드 평균본 `0.9673323`보다 `+0.0007718`이고 시드별 개선 3/3이다.
- 계열 2 사전 조건은 통과했다. 진입 하한 `0.9593676`을 넘고, 후보 풀 최근접 구성원은 exp110이 아니라 `exp135_xgb_hpo_trial30`(스피어만 `0.99189` < `0.998`)이라 중복이 아니다.
- 후보 풀 판정(candidate-pool-v2, 핵심 결합 3개)은 포함 풀이 제외 풀보다 nested OOF `+0.0000060`(분할 4/5, 동등 대역 안이라 경계 기여)으로 통과해 run `8b4111a9`를 후보 풀에 등록했다(105개 → 106개).
  champion과 최종 제출 두 장은 바꾸지 않았다.
- 실패 시 후속 연속 탐색(규제 강도, 내부 분할 수, `lin_pred` 일반 입력, 적응형 구간, 다른 LightGBM 설정)은 하지 않는다.
  다른 구성원에 같은 방식을 적용하는 것은 이 이슈의 범위 밖이며 독립 근거와 새 이슈가 필요하다.

## 구현

- `src/pipeline/initial_score.py`: 바깥쪽 분할 실행이 소유하는 새 계약 `OuterFoldInitialScoreProvider`와 생성기 `nested_logistic_onehot`.
  바깥쪽 학습 부분(목표값 포함)과 검증 부분·시험 frame(목표값 없음)을 따로 받는다.
  학습 부분 행의 초기 로짓은 그 부분 안에서만 만든 `inner_splits`(10) 층화 OOF 예측이고, 검증과 시험 행의 초기 로짓은 학습 부분 전체로 맞춘 회귀의 예측이다.
  검증이나 시험 frame에 목표값 열이 있으면 거부하고, 학습 부분과 검증 부분의 행이 겹쳐도 거부한다.
  기존 `original_proxy_lightgbm`과 `known_original_rule`의 합성 목표값 거부 규약은 그대로다.
- 인코딩과 적합은 `logistic_onehot` adapter(exp058 계열)를 그대로 재사용한다.
  확률은 기존 `probabilities_to_logits`와 같은 `1e-6` 자르기로 유한한 `float64` 로짓이 된다.
- CV 실행(`cv_seed_execution`), 진입 진단(`entry_diagnostic`), 전체 자료 재학습(`refit`)이 같은 dispatch 함수(`seed_level_scores`, `fold_scores`, `full_data_scores`)를 쓴다.
  자료 전체 계약은 시드마다 한 번 계산해 분할 인덱스로 자르고, 바깥쪽 분할 계약은 분할 안에서 새로 계산한다.
  전체 자료 재학습은 전체 학습 행의 내부 OOF 초기 점수와 전체 학습 자료로 맞춘 시험 초기 점수를 같은 계약으로 만든다.
- 실행은 `initial_score_evidence.json`에 시드·분할별 내부 OOF AUC, 검증 1단 AUC, 초기 로짓 범위, 로짓 해시, 적합 반복 수와 인코딩 열 수를 남기고 MLflow 태그 `sha256.initial_score_evidence`로 고정한다.
- 후보 설정 `configs/exp209_issue505_lgb_lr_onehot_init.yaml`은 `exp110_lgb_kitopl_no_te`의 피처 계획과 LightGBM 설정을 그대로 두고 `initial_score` 블록만 더했다.
  로지스틱 회귀 좌표는 exp058과 같다(`C=100`, L2, `lbfgs`, `max_iter=3000`, `onehot_max_card=5000`).
  입력은 raw 12열이고 플라시보 잡음 열은 초기 점수 회귀에 넣지 않았다(플라시보는 2단 LightGBM의 카나리아로만 존재한다).
  로지스틱 예측은 초기 점수로만 쓰이고 LightGBM 입력 열로 들어가지 않는다.
- 누출 경계 검사는 `tests/test_initial_score_nested.py`(목표값 열 거부, 행 겹침 거부, 학습 행 로짓이 표본 내 예측과 다름, 두 계약의 dispatch, 전체 자료 경로)다.
- 판정 기록은 `scripts/judge_issue505_pair.py`가 만든다.

## 실행

로컬 14코어 CPU에서 순차 실행했다.
모든 정식 실행은 깨끗한 커밋 `74984a0`, 같은 입력(`train` `f4669147…`, `folds` `5f5d09e9…`)이다.

| 실행 | run_id | 시드 | OOF AUC | 소요 |
| --- | --- | --- | ---: | ---: |
| exp110 기준 재실행 | `3f2aad15` | 42 | 0.9671301 | 10분 |
| exp209 스크리닝 | `70d0b082` | 42 | 0.9680126 | 6분 |
| exp209 확정 | `8b4111a9` | 42, 43, 44 | 0.9681041 | 20분 |

- 기준 동일성: 로컬 기준 재실행은 기록된 exp110 스크리닝(run `cfdebf37`, 커밋 `f07383e`) 0.9671295와 `+5.2e-07` 차이, 스피어만 `0.99991`이다.
  같은 조건이 재현되므로 짝비교는 로컬 재실행을 기준으로 한다.
- 초기 점수 계산은 분할당 약 25초(내부 10분할 + 전체 적합 11회)이고, 초기 점수를 받은 LightGBM은 기준보다 빨리 조기 종료해 시드당 실행 시간이 기준(10분)보다 짧았다(6분).
- 첫 스크리닝 시도(run `0611e5fe`)와 첫 기준 재실행 시도(run `b74d790f`)는 각각 비커밋 파일과 이전 커밋의 fold 복구 디렉터리 때문에 실행 전에 실패했고 판정에 쓰지 않았다.

## 1단 계보

시드 42의 분할별 기록이다(`initial_score_evidence.json`, 해시 `717270df…`).
검증 1단 AUC는 학습 부분 전체로 맞춘 회귀의 검증 예측을 진단용으로만 채점한 값이고, 어떤 적합에도 검증 목표값은 들어가지 않는다.

| 분할 | 내부 OOF AUC(학습 부분) | 검증 1단 AUC | 학습 로짓 범위 | 검증 로짓 범위 | 전체 적합 반복 | 인코딩 열 |
| ---: | ---: | ---: | --- | --- | ---: | ---: |
| 0 | 0.95961 | 0.95887 | [-11.98, 13.82] | [-10.19, 13.82] | 161 | 5413 |
| 1 | 0.95951 | 0.95938 | [-12.40, 13.82] | [-10.07, 13.82] | 150 | 5414 |
| 2 | 0.95928 | 0.96010 | [-10.29, 13.82] | [-12.01, 13.82] | 190 | 5412 |
| 3 | 0.95928 | 0.96028 | [-11.34, 13.82] | [-9.65, 13.82] | 174 | 5412 |
| 4 | 0.95955 | 0.95932 | [-12.54, 13.82] | [-9.18, 13.82] | 184 | 5412 |

- 검증 1단 AUC 0.9589~0.9603은 exp058의 3시드 OOF 0.9597과 같은 수준이라 1단이 누출 없이 exp058과 같은 모형임을 뒷받침한다.
- 로짓 상한 13.82는 `1e-6` 자르기의 값이다. 정확값 one-hot이 확률 1에 붙는 행이 있어 상한에 닿았고, 하한은 -9~-13 사이다.
- 시드 43, 44는 내부 분할만 달라 내부 OOF AUC가 0.9593~0.9596 범위에서 조금씩 다르고, 검증 1단 AUC는 학습 부분 전체 적합이 시드와 무관하므로 같다.

## 3시드 확정

후보 run `8b4111a9`.

| | 기록된 exp110 확정(run `ae829ae3`) | exp209 확정 | 차이 |
| --- | ---: | ---: | ---: |
| 시드 평균본 OOF | 0.9673323 | 0.9681041 | +0.0007718 |
| seed 42 | 0.9671295 | 0.9680126 | +0.0008831 |
| seed 43 | 0.9670911 | 0.9680066 | +0.0009154 |
| seed 44 | 0.9671377 | 0.9680048 | +0.0008671 |

기록된 exp110 확정은 커밋 `f07383e`라 정식 짝비교가 아닌 참고 기록이다.
시드 42의 정식 짝비교(+0.0008826)와 같은 규모다.
시드 평균본 분할별 AUC는 0.9674335, 0.9681164, 0.9682671, 0.9686404, 0.9680639다.

계열 2 사전 조건:

- 진입 하한: 0.9681041 ≥ champion 0.9693676 − 0.01 = 0.9593676, 통과.
- 중복 게이트: 최근접 `exp135_xgb_hpo_trial30`(run `119b9c4e`) 스피어만 0.99189 < 0.998, 통과.
  상위 5개는 exp135 0.99189, exp208 0.99171, exp027 0.98958, exp070 0.98892, exp025 0.98854다.
- 따라서 원자 교체가 아니라 현재 풀의 세 핵심 결합 방식으로 포함 및 제외 nested OOF를 비교한다.

- 주 조건 `포함 AUC − 제외 AUC > 0`을 통과해 판정 상태는 `adopted`, 결정은 `admit`이다.
- 차이 +0.0000060은 성능 동등 대역 상한 `+0.0000277` 이내라 경계 기여로 표시했고, 분할 승수 4/5는 경고 기록이다.
  경계 기여는 등록을 막지 않으며 다음 후보 풀 일괄 재심사의 우선 확인 대상으로 남는다.
- 단독 OOF 개선(+0.00077)에 비해 풀 기여가 작은 것은, 풀이 이미 목표 평균 인코딩을 쓰는 트리 구성원과 exp058 자체를 갖고 있어 정확값 목표 효과의 대부분이 결합 단계에서 이미 반영되어 있기 때문으로 읽힌다.
- `pipeline.pool --admit`으로 run `8b4111a9`를 `artifacts/pool.yaml`에 등록했다(106개).
  전체 자료 재학습 계획과 최종 제출 두 장은 이 문서가 바꾸지 않는다.
  재학습 산출물 관문은 구성원 항목 단위이므로 등록된 신규 구성원만 재학습하면 된다.
