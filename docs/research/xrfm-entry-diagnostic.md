# xRFM fold 0 진입 진단

이 문서는 GitHub 이슈 198의 재귀 특성 커널 머신 xRFM(exp123)을 fold 0, seed 42에서
champion exp081의 동등 단계 기준 실행과 짝비교한 결과다.
주목표는 champion 교체가 아니라 다양성 진입(상관 0.98 미만 새 계열) 후보로
정식 재검증에 진입할 근거가 있는지 판단하는 것이다.

## 결론

진입 관문 미달로 닫는다.

| 조건 | 결과 | 판정 |
| --- | ---: | --- |
| exp123 AUC가 A4000 기준 exp081 AUC에서 0.01 이내 | `0.9390760150 < 0.9585566249` | 미달 |
| 공통 진입 진단 무결성 검사(행 수·순서·유한성·assertion) | 전체 통과 | 통과 |
| 시간 관문(5-fold 예상 `2,156초` <= 24 GPU시간) | 통과 | 통과 |
| 메모리 관문 | 통과(최고 예약 `97.0%`, 모델별 상한 없음) | 통과 |

기준 대비 `-0.0294806100`으로 새 모델 계열 진입 하한 `-0.01`에 크게 미달한다.
이 격차는 zero-shot·검색 계열의 과거 탈락 폭(TabICLv2 `-0.027`, TabR-S `-0.0265`)과 비슷하다.
자료 전체를 학습하는 계열이므로 그 실패들의 반증은 아니었으나, 결과적으로 같은 수준에서 탈락했다.
이슈 192의 조사 결론대로 ModernNCA 재고는 새 근거가 생길 때만 가능하며, 이 결과는 새 근거가 아니다.

## 실행 결과

| 실행 | fold 0 AUC | 기준 대비 | 총 진단 시간 |
| --- | ---: | ---: | ---: |
| exp081 A4000 기준 | `0.9685566249` | 기준 | `2,124.93초` |
| exp123 xRFM | `0.9390760150` | `-0.0294806100` | `433.83초` |

- xRFM의 seed 42 5-fold 예상 시간은 `2,156.21초`, 약 `0.60 GPU시간`으로 지금까지 진단한 계열 중 가장 빠르다.
- 검증 fold 하위 그룹 AUC는 결측 없는 행 `0.9474893544`(53,828행), 결측 있는 행 `0.9333968204`(84,446행)다.
- 위약 열 `placebo_noise`를 포함한 33열 permutation 중요도는 전부 유한값으로 저장됐다.

## 동등 단계 기준과 GPU 차이

저장된 exp081 fold 0, seed 42 AUC는 `0.9684993007887643`(Runpod A40 생성)이다.
Vast.ai RTX A4000 재실행 AUC는 `0.9685566249248589`로 `+0.0000573241` 달랐고,
다른 GPU 종류에서만 허용되는 명시 허용 범위 `0.0002` 안에서 기준으로 채택됐다.
이 값은 이슈 177의 다른 A4000 장비 재실행 값과 완전히 같아 같은 GPU 종류의 재현성을 다시 확인했다.

## 구조와 무결성

xRFM은 AGOP 기반 특성 학습 커널과 나무형 분할을 결합한 재귀 특성 커널 머신이다
(ICLR 2026, https://arxiv.org/abs/2508.10053).
공식 `xrfm` 패키지 0.4.5(MIT, https://github.com/dmbeaglehole/xRFM)를 사용했다.

adapter(`src/pipeline/xrfm_fold.py`)는 다음 규율을 지킨다.

- 전처리(결측 중앙값 대치, 결측 지시열, 표준화, 범주 one-hot 어휘)는 outer 학습 fold에서만 맞춘다.
- xRFM이 요구하는 튜닝 검증 자료는 outer 학습 fold 안에서 seed 고정 층화 분할(10%)로 떼어낸다.
  outer 검증 fold의 행과 라벨은 학습과 튜닝에 쓰지 않는다.
- champion exp081의 33열 피처 계획을 그대로 공유하고 model 블록만 다르다(`--allow-model-diff kind params fit`).
- 정확값 목표 인코딩과 빈도 인코딩은 없다.
- 중요도는 검증 fold의 seed 고정 1,000행 permutation AUC 하락이다.

실행 설정은 다음과 같다.

- 인코딩 뒤 입력 74열(숫자 30열의 값·결측 지시 + 범주 3열의 one-hot·unknown·missing).
- 커널 `l2_high_dim`, 대역폭 10.0, 정칙화 1e-3, RFM 반복 5회, 나무 1그루.
- `max_leaf_size` 요청 60,000이 A4000 16GB 메모리 배율로 37,273으로 조정돼 leaf 16개가 만들어졌다.
- 학습 시간 379.5초, 검증 예측 4.0초, 테스트 예측 8.5초.

### 1차 실패와 tuning_metric 확정

1차 실행은 `tuning_metric=auc`로 시작했으나, 나무 분할 뒤 일부 leaf의 검증 부분집합에
한 클래스만 남아 AUC가 정의되지 않았고 leaf 최적 가중치가 `None`이 되며 중단됐다
(`AttributeError: 'NoneType' object has no attribute 'to'`).
상류 기본값이자 한 클래스에서도 정의되는 `brier`로 바꿔 2차에서 완주했고,
adapter는 한 클래스에서 미정의인 지표를 거부하도록 검증을 추가했다(커밋 `b146f3d`).

## 원격 실행과 비용

세 작업 모두 Vast.ai RTX A4000 16,376MiB 한 장과 `nvcr.io/nvidia/pytorch:26.01-py3` 이미지를 사용했고,
venv는 `uv.lock`으로 잠긴 판본만 설치했다(PyTorch `2.13.0+cu130`).
기준 실행 커밋은 `130ddb1`, challenger 커밋은 `b146f3d`이며
`pyproject.toml`·`uv.lock`·folds·피처 계획·의존성 판본이 같아 짝비교 정체성 검사를 통과했다.

| --- | --- | --- | ---: | ---: |
| exp081 기준 | `48096700` | 09:20-10:40 | `$0.09459` | 약 `$0.126` |
| 1차 실패(auc 지표) | `48105792` | 11:24-11:47 | `$0.08393` | 약 `$0.032` |

이 티켓 귀속 계산 비용 추정 합계는 약 `$0.195`다.
집계 시점에 Vast.ai 청구 목록이 아직 게시되지 않아 시간·단가 기준 추정이며,
동시에 다른 이슈의 원격 작업이 실행 중이라 계정 잔액 차감액은 단독 비용으로 쓸 수 없다.

세 결과 묶음(SHA-256 `b19ddb3b...`, `8b402a6e...`, `9810ba26...`)은 원격 해시와 대조해
기본 `main` 작업 폴더의 `run-logs/vast-issue198/`에 보존했다.
진입 진단은 MLflow 실행을 만들지 않으므로 main MLflow 반입 대상은 없다.
세 인스턴스와 GitHub Actions 종료 예약은 회수 뒤 삭제했고 계정 목록 부재를 확인했다.
이 티켓은 별도 저장 공간을 만들지 않았다.
