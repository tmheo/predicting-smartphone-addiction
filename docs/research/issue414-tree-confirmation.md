# 고정 반복 수 트리 변형 18개 확정 실행 결과

이 문서는 GitHub 이슈 [#414](https://github.com/tmheo/predicting-smartphone-addiction/issues/414)의 외부 CPU 실행, 중앙 MLflow 반입, 자원 정리 근거를 기록한다.
판정과 후보 풀 변경은 후속 이슈 [#415](https://github.com/tmheo/predicting-smartphone-addiction/issues/415)의 범위이므로 이 문서에서는 수행하지 않는다.

## 동결 입력

18개 설정은 이슈 [#413](https://github.com/tmheo/predicting-smartphone-addiction/issues/413)에서 고정한 여섯 기준 구성원의 20%, 40%, 60% 반복 수 변형이다.
모든 실행은 커밋 `a899c3d33cf1dd92262b23d89dae10cd0f7890b2`, 확정 단계, 난수 42·43·44, 고정 5분할을 사용했다.
훈련 자료, 시험 자료와 분할 파일의 SHA-256은 각각 `f4669147311c76eb03496061a852af283efcf0f12cf5c19274e775def81edd9c`, `8b462dd47fe8165cd0b082bf33b56523c5811453070af48b9f86b2eb928de49e`, `5f5d09e9356f227ecb4a063270b175bb5cae20afb25636c563db185e18a155c4`다.

## 실행 배분

Kaggle CPU 동시 실행 한도는 실제 커널을 밀어 넣어 측정했다.
다섯 커널은 동시에 실행됐고 여섯 번째는 계정의 배치 CPU 세션 상한 5개 오류로 거부됐다.
따라서 exp162, exp163, exp164, exp168, exp171을 Kaggle CPU에 배정하고 나머지 13개를 Vast.ai CPU에 배정했다.

Vast.ai 첫 인스턴스는 유효 CPU 48개를 여섯 실행 줄로 나눠 시작했다.
실측 속도로 8시간 상한을 넘길 위험이 확인된 exp165와 exp167은 각각 유효 CPU 64개 전용 인스턴스로 옮겼고, exp166은 exp165 뒤 같은 전용 인스턴스에서 실행했다.
주 인스턴스의 후속 6개 설정도 상한을 넘길 위험이 있어 exp160·161, exp170·173, exp175·176을 세 인스턴스의 두 실행 줄로 분산했다.
주 인스턴스에는 exp159, exp169, exp172, exp174만 남겼으며 분산한 후속 설정은 이름을 정확히 고정한 감시 절차로 중복 실행을 막았다.

## 실행 제어 복구

원격 실행 제어부는 `pipeline.run`이 같은 실행 식별자를 시작과 종료에 한 번씩 출력하는 동작을 서로 다른 두 실행으로 잘못 판독했다.
모델 프로세스는 종료 코드 0으로 15개 적합과 MLflow 기록을 모두 마쳤지만 제어부만 실패로 기록해 자동 묶음 내보내기를 건너뛰었다.
복구 절차는 로그의 실행 식별자를 순서를 보존해 중복 제거하고 원격 MLflow의 완료 실행을 `pipeline.bundle export`로 내보냈다.
회수한 모든 묶음은 중앙의 `pipeline.bundle import`가 입력 해시, 출처 커밋, 깨끗한 Git 상태와 OOF 재채점을 다시 검증했다.
따라서 제어부의 실패 표시는 실험 실패로 세지 않으며 중앙 반입 관문을 통과한 실행만 최종 결과에 포함한다.

## 결과와 반입 검증

결과 원본은 `artifacts/issue414-tree-confirm-results.yaml`에 기록한다.
각 실행은 중앙 MLflow의 완료 상태, 확정 단계, 난수 3개, 깨끗한 동결 커밋, 입력 해시 3개, 실행 환경 태그, 반입 묶음 해시와 `fixed_count` 진단 15개를 독립 재조회한다.
18개 실행과 270개 진단이 모두 이 검사를 통과했고 누락이나 제외 실행은 없다.

반복 수 20%, 40%, 60% 순서의 OOF AUC는 다음과 같다.

| 기준 구성원 | 20% | 40% | 60% |
| --- | ---: | ---: | ---: |
| XGBoost HPO | `0.96678206` | `0.96775965` | `0.96811074` |
| XGBoost 목표값 인코딩 제외 | `0.95942858` | `0.96329027` | `0.96427693` |
| LightGBM AG25 | `0.96790519` | `0.96837376` | `0.96855894` |
| LightGBM 목표값 인코딩 제외 | `0.96508843` | `0.96647455` | `0.96697227` |
| CatBoost 목표값 인코딩 제외 | `0.96708738` | `0.96769519` | `0.96794124` |
| CatBoost 정확값 범주 복제 | `0.96766111` | `0.96819028` | `0.96840241` |

단일 OOF AUC 최고점은 exp167 LightGBM AG25 60%의 `0.96855894`다.
이 순위는 기술적 실행 결과일 뿐이며 후보 풀 채택이나 반복 수 선택을 뜻하지 않는다.

## 자원과 비용

Kaggle 실행은 GPU를 사용하지 않았다.
Vast.ai 계산 자원과 이슈 전용 저장 공간은 결과 회수 뒤 모두 삭제하고 계정 전체 목록 부재를 다시 확인한다.
최종 계정 조회에서 이슈 414 인스턴스와 저장 공간은 모두 0개였다.

| 인스턴스 | 역할 | 청구액 |
| ---: | --- | ---: |
| `48655392` | exp159·169·172·174 주 실행 | `$0.568` |
| `48659713` | exp167 전용 | `$0.366` |
| `48661238` | exp165·166 전용 | `$0.249` |
| `48665679` | exp160·161 분산 | `$0.236` |
| `48665708` | exp170·173 분산 | `$0.152` |
| `48665730` | exp175·176 분산 | `$0.230` |

계산, 임시 저장 공간과 전송을 합친 Vast.ai 청구 합계는 `$1.801`이다.
준비 단계에서 삭제한 인스턴스 `48665602`에는 청구가 발생하지 않았다.

주 실행의 공식 결과 압축은 실행 중인 제어 셸이 분산 실행용으로 바뀐 같은 로컬 스크립트의 뒷부분을 다시 읽으면서 구문 위치가 어긋나 보존하지 못했다.
다만 네 최종 묶음은 그 전에 각각 직접 회수해 원격과 로컬 SHA-256 일치, 중앙 반입 재채점과 15개 진단을 통과했다.
나머지 전용 및 분산 인스턴스의 공식 결과 압축은 완료 수와 파일별 해시 검사를 통과했다.
제어 스크립트의 자동 종료 처리도 주 인스턴스를 삭제했고 계정 전체 목록 부재를 별도로 재확인했다.

## 인계

이 결과만으로 후보 풀, champion 또는 전체 자료 재학습 계획을 바꾸지 않는다.
후속 이슈 #415는 이 문서와 결과 원본의 유효한 18개 OOF를 동결 입력으로 사용해 일괄 nested 선택 절차를 수행한다.
