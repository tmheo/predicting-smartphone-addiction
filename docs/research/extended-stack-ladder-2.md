# 넓힌 확장 스택 nested OOF 사다리 재판정 (이슈 #455)

## 결론

현재 두 번째 장(자체 35 + 외부 207 = 242구성원, nested `0.9702876`)에 판본 2 장부의 신규 191개를 **전부** 더한 433구성원은 `shrunk_rank_logit_logistic`로 nested `0.9702939`(`+0.0000063`, 분할 3/5)라 교체 문턱(`+0.00002` 이상, 5/5 양수)에 미달이다.
신규 가운데 nhtquyn 고전 확률 모델 120개만 뺀 **313구성원(`ablate_new_nhtquyn`)은 nested `0.9703509`, 가중 OOF `0.9712170`으로 현재 판 대비 `+0.0000633`, 분할 5/5 양수(최소 `+2.1e-05`)**로 문턱을 넘는다.
문턱을 넘은 구성은 이것 하나뿐이라 선택 규칙(가장 높은 nested, 잡음 바닥 안이면 적은 구성원)은 발동하지 않았고, **교체 후보는 own35 + ext207 + 신규 71 = 313구성원, `shrunk_rank_logit_logistic`이다.**

폭을 내는 것은 공개 노트북 출력물 45개(`+4.3e-05`)와 najiama 재게시 5개(`+2.4e-05`)이고, nhtquyn 120개가 `-5.7e-05`로 그 폭을 상쇄해 "신규 전체"가 제자리였다.
라이선스 미확인(`license_unknown`) 64개를 빼면 `-5.8e-05`로 현재 판보다도 낮아지므로, 넓힐 값어치는 사용 한정 규칙(지도 #451의 2026-08-27 결정)에 기대고 있다.
사다리와 문턱은 결과 확인 전에 고정했고 결과를 본 뒤 바꾸지 않았다.

## 현재 판 재현

`own35_ext207` × `shrunk_rank_logit_logistic` = nested `0.9702876097776773`, 가중 `0.9711559`.
#443의 `ablate_te_leak`(MLflow 실행 `4f2466f8`의 `auc_oof`)과 차이 `0.0`, 분할별 AUC 5개도 전부 차이 `0.0`이다.
`rank_logit_logistic`도 `0.9702760`으로 #443 값과 차이 `0.0`이다.
도구, 자료, 열 순서가 #443 시점과 비트 단위로 같으므로 아래 값들은 그대로 문턱에 댈 수 있다.

## 읽히는 사실

- #386의 폭 곡선(`증분 ≈ 1.73e-05 × k^0.62`)이 외부 207 → 398에 예측한 값은 약 `+0.0002`인데 실측은 `+6.3e-06`이다.
  곡선은 "같은 품질의 구성원"을 전제하는데, 신규 191개의 3분의 2(nhtquyn 120)가 AUC 0.85~0.93의 약한 모델이라 전제가 깨졌다.
  nhtquyn을 뺀 71개(207 → 278)에 대한 곡선 예측은 약 `+0.00009`이고 실측 `+0.0000633`이 그 근처다.
- 최선 전략은 14구성 전부 `shrunk_rank_logit_logistic`이고 2위는 `rank_logit_logistic`이며, 두 전략의 절제 부호는 전부 같다.
  #337·#443의 "구성원 수가 늘어도 전략 순위가 뒤집히지 않는다"가 433개에서도 성립한다.
- λ는 모든 구성의 모든 바깥쪽 분할에서 1이라 시험 예측은 rank_logit_logistic과 순위가 같다(#444와 같음).

## 실행 비용과 사고

- 작업 28개(14구성 × 2전략)의 합계 계산 시간은 14.3시간이고, 4스레드·3작업 동시 기준으로 433열 shrunk 74분, 242열 shrunk 36분, 313~432열 shrunk 절제 40~59분, rank_logit_logistic 4~14분이다.
- 400열대 shrunk 작업은 로지스틱 적합 구간에서 작업당 10~16GB까지 올라간다.
  동시 작업을 5개로 올렸을 때 48GB 기계가 두 번 재시작됐다(JetsamEvent `vm-compressor-space-shortage` 뒤 watchdog timeout 커널 패닉).
  **이 기계에서는 동시 3개가 상한**이며, 이후 여유율 15% 미만이면 가장 최근 작업을 죽이는 감시(`run-logs/issue455/memwatch.sh`)를 같이 돌렸고 발동은 없었다.
  코어 14개 가운데 3~5개만 쓰는 셈이라 병목은 CPU가 아니라 메모리다.
- 드라이버는 tmux 세션에서 띄워야 Claude 세션 종료에 견디고, 드라이버만 바꿔 띄울 때는 tmux 세션이 아니라 드라이버 프로세스에만 신호를 보내야 작업자가 살아남는다.

## 한계

- nested OOF는 결합기의 일반화를 재지만 외부 구성원 상류의 분할 준수는 저자 근거에 의존한다.
  선택 구성의 외부 278개는 저자 서술 152, 공개 코드 98, 형제 코드 13, 분할 벡터 12, 없음 3이고, 그 가운데 신규 71개는 공개 코드 37, 형제 코드 12, 저자 서술 16, 분할 벡터 3, 없음 3이다.
  `fold_evidence_none` 3개(masayakawamata cat_str, shamanthakreddymallu lgb_fe·lr)는 근거가 없으나 기여가 `+6e-06`이라 판정을 바꾸지 않는다.
- 선택 구성은 `license_unknown` 부류 64개(노트북 출력물 45, hboyang150 11, najiama 재게시 5, beicicc other 3; 라이선스 값으로는 unknown 61 + other 3)를 포함한다.
  나머지 214개는 CC0 203, CC BY 4.0 6, Apache 2.0 5다.
  사용 한정 규칙에 따라 결합 입력으로만 쓰고 배열은 재배포하지 않으며, CC BY 4.0·Apache 2.0 구성원의 저작자 표기는 조립 manifest가 유지한다.
- `shrunk_rank_logit_logistic`의 λ는 fold마다 격자에서 고르므로 재실행 사이에 `7e-06`쯤 흔들릴 수 있다(#386 관찰).
  이번 재현 검사는 `0.0` 차이로 맞았다.
- 잡음 바닥 `5.7e-06` 안의 절제 차이(masaya, beicicc other, paiky6, near_duplicate 9개)는 부호를 읽지 않는다.
- Public 점수는 판정에 쓰지 않았다.
  참고로 현재 두 장의 nested-Public 오프셋 약 `+0.00105`를 더하면 `0.9714` 자리다.
