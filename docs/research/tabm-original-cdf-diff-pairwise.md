# TabM 원본 프록시 CDF 차이 5열 짝비교

## 결론

원본 프록시 CDF 차이 5열을 더한 `exp140_tabm_orig_cdf_diff`는 직접 기준인 `exp137_tabm_recon_widths`보다 3시드 평균 OOF AUC가 `+0.00017428` 높았다.
세 시드와 시드 평균 예측의 다섯 분할이 모두 개선되어 이 묶음을 `실신호`로 판정했다.
후보는 기존 `exp137`과 스피어만 상관 `0.99946630`으로 중복 문턱 `0.998`을 넘었고 단독 OOF AUC는 더 높았다.
그러나 현재 32개 후보 풀의 원자 교체 중첩 OOF는 `-0.000001402`, 외부 분할 2/5였고 후보 포함·제외 중첩 OOF도 `-0.000006815`, 외부 분할 3/5였다.
두 후보 풀 판정이 모두 기각되어 `exp137`을 유지하고 전체 자료 재학습 계획도 바꾸지 않았다.

## 구현과 비교 규율

후보 설정은 `exp137_tabm_recon_widths`의 TabM 모델 설정과 기존 피처를 그대로 사용하고 `original_cdf_diff` 제공자만 추가했다.
추가한 열은 `daily_screen_time_hours_orig_cdf_diff`, `weekend_screen_time_orig_cdf_diff`, `social_media_hours_orig_cdf_diff`, `notifications_per_day_orig_cdf_diff`, `app_opens_per_day_orig_cdf_diff`다.
KDE 로그 밀도비 3열은 열지 않았다.
CDF 차이 제공자는 목표값을 사용하지 않으며 외부 원본 프록시 분포와 현재 자료의 경험적 누적분포 차이만 계산한다.
구성 차이 시험은 두 설정의 차이가 이름과 `features.providers.original_cdf_diff`뿐임을 고정한다.
자동 비교 명령은 의도적인 피처 추가로 분할 실행 관찰 산출물 해시가 달라져 거부했으므로, 자료·분할·모델 계약과 fold 피처 재사용 해시를 확인한 뒤 반입된 OOF를 식별자와 분할 순서로 직접 맞춰 다시 계산했다.

## 짝지은 OOF 결과

| 단계 | 시드 | 후보 OOF | 기준 OOF | 변화 | 분할 승수 |
| --- | --- | ---: | ---: | ---: | ---: |
| 선별 | 42 | 0.9684474233 | 0.9682870233 | +0.0001604000 | 5/5 |
| 확인 | 42, 43, 44 평균 | 0.9685589470 | 0.9683846688 | +0.0001742782 | 5/5 |

확인 실행의 시드별 변화는 시드 42 `+0.00016040`, 시드 43 `+0.00019015`, 시드 44 `+0.00013941`로 3/3이 양수였다.
평균 개선폭이 `+0.0002`보다 작은 경계 구간이므로 시드 평균 예측의 분할 승수 3/5 이상이 필요했고 실제로 5/5를 충족했다.
확인 실행의 시드 42 기준과 후보 예측은 별도 선별 실행과 모든 행에서 정확히 일치했다.
확인 대조군의 3시드 평균 예측은 후보 풀에 있던 `exp137` 실행과 모든 행에서 정확히 일치했다.

## 보조 중요도

확인 실행의 플라시보 평균 중요도는 `0.0000354663`이었다.
`daily_screen_time_hours_orig_cdf_diff`의 평균 중요도는 `0.0001459880`이었다.
`weekend_screen_time_orig_cdf_diff`의 평균 중요도는 `0.0001267011`이었다.
`social_media_hours_orig_cdf_diff`의 평균 중요도는 `0.0002614996`이었다.
`notifications_per_day_orig_cdf_diff`의 평균 중요도는 `0.0003723037`이었다.
`app_opens_per_day_orig_cdf_diff`의 평균 중요도는 `0.0002510486`이었다.
다섯 열 모두 15/15 시드·분할 칸에서 플라시보 평균보다 높았지만 중요도는 실신호와 후보 풀 판정의 관문으로 사용하지 않았다.

## 후보 풀 판정

판정 원본은 SHA-256 `8221c5f334ff19482a6e86c205fe2272b3c3a4bf0c0393e4123899cf43776423`인 32개 후보 풀이었다.
후보 OOF AUC `0.96855895`는 champion 기준 진입 하한 `0.95933973`을 통과했다.
후보와 최근접 `exp137`의 스피어만 상관은 `0.99946630`이고 후보의 단독 OOF AUC가 `+0.00017428` 높았다.
원자 교체 대조에서 기존 풀의 최고 `shrunk_rank_logit_logistic`은 `0.9697423948`, 교체 풀의 같은 전략은 `0.9697409932`로 변화가 `-0.0000014016`이었다.
원자 교체의 외부 분할 변화는 2/5만 양수여서 `candidate-pool-v1` 판정은 기각됐다.
포함·제외 대조에서는 기존 풀의 최고 `shrunk_rank_logit_logistic` `0.9697423948`에 비해 후보 포함 풀의 최고 `missing_interaction_rank_logit`이 `0.9697355802`로 `-0.0000068146` 낮았다.
포함·제외 대조는 외부 분할 3/5가 양수였지만 전체 중첩 OOF가 음수라 양의 한계 기여를 확인하지 못했다.
따라서 단독 OOF 개선만으로 후보 풀을 바꾸지 않고 기존 `exp137`을 유지했다.

## 재학습 계획과 원격 정리

후보 풀을 바꾸지 않았으므로 전체 자료 재학습 계획도 `exp137`과 시드별 예산 18, 16, 16을 유지했다.
선별과 확인 실행은 고정 커밋 `83f97123a2e7c6bdf0dcdbe152db1461f34e41ca`, 같은 입력 해시, 같은 5분할과 같은 컨테이너 이미지에서 실행했다.
확인 결과 묶음은 원격과 로컬 SHA-256 `8c504a445df9a76b852de603334c7d569156d367ace50b1027b95c96db3ada42`가 일치했고 내부 산출물 목록 검증도 통과했다.
결과를 기본 MLflow 저장소에 반입하고 필수 산출물을 다시 조회한 뒤 Vast.ai 인스턴스를 삭제했다.
삭제 뒤 대상 인스턴스, 작업용 저장 공간과 이 작업의 종료 예약이 모두 없음을 확인했다.
선별 비용은 0.480달러, 확인 비용은 0.832달러로 Vast.ai 총비용은 1.312달러였다.
처음부터 끝까지 Runpod 자원은 만들지 않았다.
