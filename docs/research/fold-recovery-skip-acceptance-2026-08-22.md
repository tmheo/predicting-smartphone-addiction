# 완료 폴드 계산 생략 인수 기록

## 결론

이슈 356의 전체 복구 선검증, 완료 폴드 계산 생략, 부분 복구 계산 범위와 기존 결과 보존을 구현하고 검증했다.
네 폴드 복구의 교차 검증 내부 경과 시간은 2,041.106초에서 406.042초로 80.107% 줄어 15% 기준을 통과했다.
제공자 생성부터 유효 결과 완성까지의 전체 시간은 2,578.331초에서 733.619초로 71.547% 줄어 10% 기준을 통과했다.
완전 복구의 파이프라인 경과 시간은 3.078초이고 관측기 종료 시점은 3.781초여서 30초 기준을 통과했다.
정상 실행, 네 폴드 복구와 완전 복구의 OOF, 시험 자료 예측, 중요도, AUC와 결정적 학습 의미 자료는 정확히 같았다.

## 구현

- 구현 기준 커밋은 `b6b1bf66ef5053d6b57eaf7a4112cb77a37643f7`이다.
- `plan.all_columns()`는 제공자를 실행하지 않고 전체 피처 선언을 반환한다.
- 한 시드의 다섯 `FoldRecovery.load()`는 폴드 순서대로 모든 계산보다 먼저 실행된다.
- 완전 복구는 초기 점수, 공통 행렬, 폴드별 제공자와 모델을 만들거나 실행하지 않는다.
- 부분 복구는 공통 행렬을 한 번 만들고 미완료 폴드마다 새 폴드 제공자 인스턴스를 만든다.
- 복구 폴드와 새 폴드는 원래 폴드 순서에서 각각 한 번만 완료 처리된다.
- 복구 실행 정체성, 원자적 기록 경계와 저장 형식은 바꾸지 않았다.

## 자동 검사와 환경 관문

- 복구 검사에는 제공자 인스턴스 재사용 금지, 정상 실행과 부분 및 완전 복구 결과 일치, 네 폴드 복구 계산 호출 수와 뒤쪽 손상 폴드의 선실패를 추가했다.

- 뒤쪽 폴드 손상 검사는 다섯 복구 자료를 모두 읽은 뒤 학습과 모든 피처 계산이 0회인 상태에서 실패하는지 확인한다.
- 관련 검사 67개와 전체 검사 475개가 로컬에서 통과했다.
- 구현 커밋의 격리 환경 관문은 비공개 입력 검사, 검사 475개 수집, 원격 Python 계약 검사 4개와 전체 검사 475개를 통과했다.

- 인스턴스 `48347306`은 AMD EPYC 7642에서 첫 폴드를 완료하지 못해 성능 부적합으로 중단하고 삭제했다.
