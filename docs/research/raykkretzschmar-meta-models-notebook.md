## 결론

[Mix the Meta-Models, Then Learn What They Miss](https://www.kaggle.com/code/raykkretzschmar/mix-the-meta-models-then-learn-what-they-miss)의 최신 공개 판본은 v21이며 `scriptVersionId`는 `342302573`이다.

따라서 사용자가 알려 준 `0.971`은 이 판본의 최종 `submission.csv`에 대응한다.

이 `0.97100`은 노트북 첫 단계의 OOF AUC `0.9697125`나 본문이 보고한 다중 분할 평균 `0.969721`과 다른 값이다.
최종 제출은 노트북이 직접 재학습한 하나의 모형이 아니다.
외부 94모형 결합, Public 점수를 본 뒤 선택한 세 제출의 순위 평균, 공개되지 않은 교사-학생 학습으로 만든 신호와 세 가지 미세 보정을 차례로 이어 붙인 결과다.

첫 단계의 선형 결합 자체는 비교적 투명하지만 저장소의 정식 개선 판정에 바로 쓸 수 있는 완전한 nested OOF는 아니다.
두 번째 단계인 교사-학생 순위 잔차는 구조적으로 새로운 단서지만 학습 코드, fold, id 정렬 OOF와 선택 전 후보 기록이 공개되지 않았다.
따라서 이 노트북의 외부 OOF, 제출 파일과 예측 신호는 현재 후보 풀이나 최종 제출에 가져오지 않는다.
새 실험 티켓도 지금 열지 않고, 검증 가능한 근거가 공개될 때 조건부로 다시 본다.

## 첫 단계: 격자 FM

### 설명의 주장

노트북은 이 자료의 수치값을 연속적인 크기보다 원본의 값을 가리키는 조회 키에 가깝다고 본다.
단일 열의 정확값 인코딩보다 열 쌍이 더 많은 정보를 가지지만 모든 정확한 값 쌍을 독립적으로 추정하면 조합 수가 너무 커진다고 설명한다.
FM은 각 `(열, 값)`에 벡터 하나를 두고 두 값 벡터의 내적으로 열 쌍 효과를 저차원화한다.

이 설명은 실제 `FM.forward` 구현과 대체로 맞는다.
구현은 값별 선형항, 표준 FM 이차 상호작용, 선택 가능한 다층 신경망 출력을 더한다.
본문이 제시한 FM 수식은 코드의 이차 상호작용과 일치한다.

### 값 어휘와 파생 표현

`build_fields`는 다음 규칙으로 각 열을 정수 식별자로 바꾼다.

- 결측값은 `0`이다.
- 출현 횟수가 15보다 작은 값은 공통 희귀 식별자 `1`이다.
- 출현 횟수가 15 이상인 정확값은 `2`부터 별도 식별자를 받는다.
- `coarse=True`이면 수치 열을 소수 첫째 자리로 반올림한 보조 격자를 추가한다.
- `derived=True`이면 `other_screen`, `sgw`, `other_frac`, `wk_other`, `notif_open`과 결측 무늬를 추가한다.

설명은 목표값을 사용하지 않는다고 말하며 이 점은 맞다.
그러나 어휘와 빈도는 outer 학습 부분이 아니라 학습 자료와 시험 자료를 합친 `both`에서 한 번 만든다.
직접적인 목표값 누출은 아니지만 검증 자료와 시험 자료의 값 분포를 학습 표현에 미리 반영하는 시험 분포 활용 전처리다.

### 학습 설정

코드는 세 구성원을 선언한다.

- `fmdeep`은 임베딩 차원 8, 깊은 층 384, 임의 값 숨김 20%, 초기화 3개를 사용한다.
- `fmpure`는 임베딩 차원 16, 깊은 층 없음, 거친 격자와 파생 표현, 임의 값 숨김 10%, 초기화 3개를 사용한다.
- `fmwide`는 임베딩 차원 32, 깊은 층 256, 거친 격자와 파생 표현, 임의 값 숨김 15%, 초기화 2개를 사용한다.

분할은 `StratifiedKFold(5, shuffle=True, random_state=42)`다.
임베딩 가중치 감쇠, 임의 값 숨김, 지수 이동 평균, 기울기 제한과 OneCycle 학습률 일정을 구현한다.
각 epoch에서 같은 outer 검증 라벨로 AUC를 재고 조기 종료하므로 보고할 검증 부분을 반복해서 보는 약한 선택 편향이 있다.

최신 공개 실행은 `RUN_TRAINING=False`다.
따라서 학습 코드는 실행되지 않고 외부 배열을 불러온다.
로그에 기록된 단독 OOF는 `fmdeep 0.96666`, `fmpure 0.96455`, `fmwide 0.96493`이다.
본문의 GPU 약 10분, CPU 약 40분이라는 시간도 이번 저장 실행으로 다시 확인되지 않았다.
CUDA 결정론 설정과 정확한 PyTorch 판본 잠금이 없어 학습을 켠 경우 비트 단위 재현성은 보장되지 않는다.

## 첫 단계: 74개 OOF와 두 선형 결합

### 외부 OOF 적재

노트북은 외부 자료에서 이름순으로 `oof_*.npy`와 대응 시험 예측을 읽어 74개 구성원을 만든다.
행 수와 배열 모양은 확인하지만 id, fold id, 파일 해시, 유한값, 정확 중복과 원 학습 계보는 확인하지 않는다.
고정 seed 42와 원래 행 순서라는 전제는 외부 README의 주장에 의존한다.
glob으로 현재 자료에 있는 모든 파일을 읽으므로 외부 자료 판본이 바뀌면 구성원 수와 순서도 바뀔 수 있다.

### 전역 선형 결합

전역 설계는 74개 외부 구성원과 FM 세 개를 합친 77개 logit을 표준화한 뒤 `C=1.0` 로지스틱 회귀를 맞춘다.
`honest` 함수는 각 meta fold의 학습 부분에서 표준화와 회귀 계수를 맞추므로 이 좁은 단계만 보면 평가 행의 목표값을 직접 보지 않는다.

### 결측 상태별 선형 결합

결측 상태별 설계는 외부 74개 logit에 다음 표현을 더해 301열을 만든다.

- 완전 관측 행과 결측 4개 이상 행의 상호작용을 추가한다.
- 구성원별 예측과 구성원 평균의 불일치를 결측 상태와 상호작용시킨다.
- 구성원 예측의 요약 통계 다섯 개를 추가한다.

이 설계에는 새 FM을 넣지 않고 `C=0.03` 로지스틱 회귀를 맞춘다.
구성원 불일치의 평균과 표준편차는 전체 OOF에서 먼저 계산하므로 엄격한 outer-fold 절차라면 각 outer 학습 부분에서 다시 맞춰야 한다.

### 두 설계의 혼합

노트북은 결측 상태별 설계의 백분위 순위 2/3과 전역 설계의 백분위 순위 1/3을 평균한다.
설명은 전역 가중치 0.30에서 0.35가 평평한 최고 구간이어서 1/3을 고정했다고 말한다.
실제 코드는 같은 전체 OOF 라벨로 0.00부터 0.70까지 0.05 간격의 곡선을 만든다.
따라서 1/3은 표현상 고정값이지만 동일 OOF를 본 선택이라는 점은 남는다.
두 meta 출력의 백분위 순위도 전체 OOF에서 한 번 계산한다.

## 다중 분할 주장의 한계

본문은 seed 42, 2026, 314159의 meta 분할에서 15개 fold 모두 개선했다고 말한다.
seed 2026과 314159 결과는 최신 실행에서 재생되지 않고 본문 숫자로만 남아 있다.

더 중요한 문제는 level-1 OOF가 고정 seed 42 fold에서 만들어졌다는 점이다.
meta 단계만 seed 2026이나 314159로 다시 나누면 어떤 meta outer 검증 행의 라벨을 해당 level-1 학습기가 이미 본 경우가 생긴다.
이는 서로 다른 fold OOF를 섞지 말라는 노트북 자신의 경고와 충돌한다.

세 분할은 같은 691,369행과 같은 목표값을 되풀이한다.
따라서 이를 세 독립 검증이라고 부를 수 없고, 반복된 개선 부호는 민감도 참고값으로만 읽어야 한다.

## 화면 시간 구간 보정

노트북은 두 결합의 혼합이 약한 화면 시간 구간만 별도 FM으로 재정렬한다.

- `daily_screen_time_hours`가 `(3, 6]`인 행을 5% 보정한다.
- `daily_screen_time_hours`가 `(6, 7.8]`인 행을 5% 보정한다.
- `daily <= 3`과 결측 4개 이상 구간은 각각 `-0.000070`, `-0.000091`로 보고 기각한다.

`band_adjust`는 구간 안의 기존 예측값 집합을 보존하면서 혼합 순서에 맞춰 다시 배치한다.
따라서 행이 다른 구간으로 이동하지 않고 전체 예측값 분포도 유지된다.
이 구현 의도와 본문 설명은 맞는다.

그러나 전체 OOF 구간을 한꺼번에 정렬하므로 outer fold 밖의 검증 예측 분포를 함께 사용한다.
구간 경계, 구간 모형, 5% 가중치와 양수인 두 구간 선택도 같은 OOF 라벨을 보고 정해졌으며 별도 nested 선택이 없다.
구간 FM 학습 코드는 현재 노트북에 없고 외부 배열만 사용한다.

이 단계는 Public 점수 `0.97099`를 보고 선택한 결합이라고 본문이 명시한다.

현재 노트북은 세 파일을 직접 읽거나 평균하지 않는다.
[Daniil Krasnov의 공개 노트북](https://www.kaggle.com/code/daniilkrasnovvv/s6e8-top-1-public-0-97099)이 만든 완성 `submission.csv`를 그대로 읽는다.
Daniil 원본 코드는 세 입력의 id 일치를 검사하지 않고 첫 파일의 id를 유지한 채 목표 열만 순위 평균한다.
현재 노트북은 완성된 Daniil 파일이 대회 시험 id와 일치하는지만 확인한다.

현재 Daniil 노트북 정보는 Rayk 노트북을 입력 노트북으로 가리키고 Rayk 노트북은 Daniil 출력을 입력으로 읽는다.
실제 성공 실행에서는 과거 판본의 고정 스냅샷이 연결됐겠지만 현재 정보만으로 정확한 선행 판본을 고정하기 어렵다.
이 순환해 보이는 현재 계보는 살아 있는 외부 노트북 연결을 재현 근거로 삼을 때의 취약성을 보여 준다.

## 8월 14일 갱신: 교사-학생 순위 잔차

### 설명의 주장

교사 모형은 원시 특성, 정확값 빈도, 결측 표시와 생성 제약 특성을 쓰는 LightGBM이다.
학생 모형은 교사의 백분위 순위를 더 부드러운 LightGBM으로 재구성한다.
최종 보정 신호는 목표값 예측이 아니라 `교사 순위 - 학생 순위`다.

본문은 각 outer fold에서 inner 교사 네 개가 outer 학습 행의 OOF 교사 목표를 만들었다고 설명한다.
학생은 이 OOF 목표와 목표값이 없는 outer 검증 행의 교사 예측을 0.5 가중치로 함께 본다고 한다.
최종 학습에서는 시험 자료가 296,302행으로 늘어나는 비율을 맞추기 위해 시험 의사 목표 가중치 `0.2450247`을 사용했다고 설명한다.

큰 잔차가 더 반복적이라는 판단에 따라 잔차의 부호를 보존한 제곱을 만들고 기준 잔차 분포에 맞춘 뒤 기본 순위에 10%를 더한다.
본문은 독립적인 120,000행 holdout 두 개로 잔차 크기와 지지 범위를 정했다고 말한다.
네 OOF 기준에서 각각 `+0.000018`, `+0.000019`, `+0.000036`, `+0.000025`를 얻고 60/60 fold가 양수였다고 보고한다.

### 실제 공개 코드와 산출물

현재 노트북에는 교사나 학생을 학습하는 코드가 없다.
가중치 `0.2450247`을 사용한 학습 코드도 없다.
노트북은 완성 예측 신호를 담은 `transductive_signals.npz`만 읽는다.

NPZ에는 다음 배열만 있다.

- `reference_contrast` 240,000개가 있다.
- `test_teacher`, `test_student`, `global_control`, `global_reconstructed`, `retrieval_signal`은 각각 296,302개다.
- `specialist_control`과 `specialist_reconstructed`는 각각 92,775개다.

학습 라벨, OOF 교사 및 학생 예측, fold id, 행 id, 학습 코드, 설정과 네 OOF 기준은 없다.
240,000개 기준값이 120,000행 holdout 두 개라는 본문 설명과 크기만 맞을 뿐 독립성이나 성능을 다시 채점할 자료는 없다.
따라서 네 기준의 개선값과 60/60 fold 주장은 공개 산출물로 검증할 수 없다.

### 최종 보정 코드

공개 코드는 시험 교사와 학생 예측을 각각 시험 자료 안에서 순위화한다.
교사-학생 잔차의 표준편차를 240,000개 기준 잔차에 맞추고 범위를 자른 뒤 부호 보존 제곱을 적용한다.
이 신호를 Public `0.97099` 기본 순위에 10% 더한다.

이 시험 분포 맞춤은 목표값을 사용하지 않는 시험 분포 활용 보정이다.
자체 정식 OOF에서 시험하려면 각 outer 검증 부분마다 같은 절차를 독립적으로 재현해야 한다.

그 뒤 다음 세 미세 보정을 적용한다.

- 주요 생성 키가 결측인 행에서 전역 재구성 신호를 1% 사용해 구간 안을 재정렬한다.
- 같은 행에 결측 전문 신호를 0.25% 사용해 다시 재정렬한다.
- `sleep_hours`가 관측된 행에는 정확 조회 신호를 0.75% 직접 섞는다.

이 세 신호의 학습 코드, OOF 배열과 선택 과정도 공개되지 않았다.
마지막에는 예측, 기본 순위와 id 순서로 동률을 풀어 모든 시험 예측을 서로 다른 엄격 순위로 바꾼다.

## 부정 결과 설명의 가치와 한계

노트북은 다음 부정 결과를 자세히 기록한다.

- 74개 logit 위의 LightGBM 2단 결합은 `0.969547`로 선형 결합보다 낮았다.
- 원시 열과 결측 무늬를 더한 LightGBM 2단 결합은 `0.969508`이었다.
- 선형 결합에 결측 표시를 추가한 결과는 `0.969655`로 차이가 없었다.
- 전역 FM을 더 강하게 만들어도 혼합 개선은 `+0.000000`이었다.
- LightGBM을 세 번째 혼합 요소로 5%에서 15% 넣은 결과는 `+0.000001`이었다.
- 전체 구성원의 임의 60% 부분집합을 반복 결합한 결과는 `0.96960`으로 전체 결합보다 낮았다.
- 결측 상태별 isotonic 보정은 `-0.000080`, 0/15 fold였다.

이 표는 무엇을 더 시도하지 말아야 하는지 설명한다는 점에서 유용하다.
다만 최신 코드로 다시 계산되는 항목은 일부뿐이고 많은 값은 본문에 저장된 보고치다.

가장 중요한 해석은 2단 모형의 용량을 키우기보다 편향이 다른 단순 선형 결합을 평균하는 편이 낫다는 것이다.
단독 성능이나 낮은 상관만으로 구성원의 결합 가치를 판단하지 말아야 한다는 설명도 타당하다.
이 두 결론은 현재 저장소의 자체 nested OOF 실험에서 더 엄격하게 이미 검증됐다.

## 검증 감사

### 비교적 신뢰할 수 있는 부분

- seed 42의 `honest` 함수는 각 meta fold의 평가 행 목표값을 직접 학습하지 않는다.
- 표준화와 로지스틱 회귀 계수는 해당 meta 학습 부분에서 맞춘다.
- 첫 단계 제출 파일은 최신 저장 실행으로 재현된다.
- 최종 파일의 해시, 행 수와 엄격 순위 불변식은 저장 실행 로그와 일치한다.
- 본문은 8월 13일 결합이 Public 점수를 본 선택임을 숨기지 않는다.

### 정식 개선 판정을 막는 부분

- 고정 level-1 OOF 위에 얹은 2단 평가이지 전체 과정을 다시 학습하는 strict end-to-end nested OOF가 아니다.
- seed 2026과 314159 meta fold는 level-1 fold와 어긋난다.
- 학습과 시험을 합친 어휘, 전체 OOF의 불일치 정규화, 전체 OOF의 백분위 순위와 전체 구간 재정렬이 outer 검증 경계 밖에서 맞춰진다.
- FM 조기 종료는 같은 outer 검증 라벨을 반복해서 본다.
- FM 구성, 결측 상태별 규제, 전역 가중치, 구간 경계, 구간 모형과 가중치를 같은 OOF 결과로 선택한다.
- 반복 fold 개선 부호는 선택에 쓴 행과 라벨에서 다시 계산한 값이지 독립 최종 검증이 아니다.
- 최종 교사-학생 단계와 세 미세 보정에는 공개 학습 코드와 id 정렬 OOF가 없다.
- `0.97099` 시작점부터 Public 점수를 보고 고른 외부 제출 세 개의 결합이다.

따라서 Public `0.97100`은 최종 파일의 역사적 성능을 말해 줄 뿐 이 저장소의 개선 판정 근거가 아니다.

## 현재 저장소와의 비교

현재 champion `exp081_lookup_fold_initialization_avg3`의 3시드 OOF AUC는 `0.9691957618114269`다.
현재 후보 풀은 16개 모두 계보, 내용 해시와 고정 fold 검사를 통과했고 외부 예측을 포함하지 않는다.

### 격자 FM

이 노트북의 FM 계열은 단독 OOF가 약 `0.9646`에서 `0.9667`이고 74개 결합 기여도 약 `+0.000006`이다.
저장소는 정확값 쌍 목표 인코딩, 정확값 one-hot 선형 모형, Lookup-Transformer와 TabM을 공통 fold에서 이미 시험했다.
FM은 Lookup보다 약하고 결합 기여도 작으므로 새 진입 진단을 열지 않는다.

### 두 선형 결합과 구간 결합

[순위 평균과 nested 선형 스태킹 비교](https://github.com/tmheo/predicting-smartphone-addiction/issues/64)는 자체 후보 16개의 순위와 logit 이중 표현 로지스틱 회귀로 nested OOF `0.969483491650`을 얻었다.
[비선형·구간별 2단 결합의 추가 가치 결정](https://github.com/tmheo/predicting-smartphone-addiction/issues/67)은 결측 구간 독립 선형 결합으로 `0.969510369267`을 얻었다.
이는 기본 선형 결합보다 `+0.000026877617`이고 5/5 fold에서 개선했다.
같은 비교에서 얕은 XGBoost 2단 결합은 `-0.000060036059`, 0/5 fold로 기각됐다.

따라서 첫 단계의 두 선형 결합 혼합, 순위 표현, 결측 구간 결합과 유연한 2단 모형의 실패는 현재 저장소에서 더 엄격하게 이미 다뤘다.

### 교사-학생 순위 잔차

교사 순위에서 더 부드러운 학생이 재구성하지 못한 부분을 분리하는 구조는 실제로 새로운 단서다.
그러나 학습 코드, fold id, id 정렬 OOF, 네 기준 예측, 선택 전 후보 목록과 미세 보정의 독립 검증이 없다.
최종 성능도 허용하지 않는 외부 제출 결합 위에서 측정됐다.
따라서 즉시 실험 티켓을 열 근거는 부족하다.

다음 조건 가운데 하나를 충족하면 조건부로 다시 본다.

- 작성자가 정확한 학습 코드, fold 계보와 id 정렬 OOF를 공개한다.
- 네 기준과 60/60 개선을 공개 산출물로 재채점할 수 있게 된다.
- 현재 실험 지도에서 새 2단 결합 구조를 추가로 탐색하기로 별도 결정한다.

재검토 시 질문은 다음과 같이 한정한다.

> 현재 후보 풀의 고정 5-fold에서 outer 학습 부분만 사용해 LightGBM 교사 OOF 목표를 inner fold로 만들고, 사전 고정한 더 부드러운 학생이 교사 순위를 재구성하지 못한 부호 보존 제곱 잔차를 생성한다.
> 검증 및 시험 행을 학생 학습에 넣지 않는 기본형과 목표값 없는 시험 분포 활용형을 분리하고, 잔차 변환과 10% 가중치를 outer 학습 부분 안에서만 고른 nested OOF로 평가한다.
> 현재 16개 이중 표현 로지스틱 결합과 결측 구간 독립 선형 결합보다 평균 AUC가 `+0.00002` 이상 높고 5개 fold 중 3개 이상 개선하는가?
> 실패하면 교사, 학생, 지수와 가중치 탐색을 확장하지 않는다.

## 최종 판단

Public `0.97100`은 실제 공개 판본의 최종 파일과 일치하는 기록이다.
그러나 그 점수를 현재 저장소가 채택할 수 있는 검증 근거로 해석하면 안 된다.

코드와 설명에서 바로 가져갈 만한 새 실험은 없다.
첫 단계 결합의 유용한 통찰은 기존 자체 nested OOF 결정에 이미 흡수됐다.
교사-학생 순위 잔차는 관찰 대상으로 남기되 검증 가능한 근거가 생기기 전에는 실행하지 않는다.
외부 OOF, 공개 제출 파일과 예측 신호도 후보 풀이나 최종 제출에 사용하지 않는다.
