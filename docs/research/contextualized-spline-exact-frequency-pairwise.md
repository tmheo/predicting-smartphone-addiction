# Contextualized Spline Transformer 정확값 빈도 8열 짝비교

## 결론

정확값 빈도 8열을 더한 `exp142_contextual_spline_exact_frequency`의 시드 42 OOF AUC는 `0.9667373768`이었다.
같은 조건의 `exp085_contextual_spline_m0`은 `0.9674029630`이므로 짝차이는 `-0.0006655863`다.
전체 OOF 비음수 선별 관문을 통과하지 못해 3시드 확인, 후보 풀 직접 교체와 포함·제외 중첩 OOF는 실행하지 않았다.
기존 `exp085_contextual_spline_m0`을 후보 풀에 유지하고 장부는 바꾸지 않는다.

## 구현과 비교 규율

후보 설정은 `exp085_contextual_spline_m0`에 `frequency_encoding` 제공자 하나만 추가했다.
추가 열은 `age_ce`, `daily_screen_time_hours_ce`, `social_media_hours_ce`, `work_study_hours_ce`, `sleep_hours_ce`, `notifications_per_day_ce`, `app_opens_per_day_ce`, `weekend_screen_time_ce`다.
모델 입력은 33열에서 41열로 늘었다.
모델 종류, 조각선형 수치 변환, 정확값 어휘, 기존 피처 제공자와 학습 조건은 같게 고정했다.
회귀 테스트는 두 설정의 허용된 차이와 실제 추가 열 집합을 함께 검사한다.

## 분할 안 개선과 전체 OOF 하락

각 분할 AUC는 해당 분할 안의 양성과 음성 순위만 비교한다.
전체 OOF AUC는 서로 다른 분할에 속한 양성과 음성의 순위까지 비교하므로 분할별 예측 척도가 어긋나면 두 결과의 방향이 달라질 수 있다.

같은 분할 안의 개선이 전체 AUC에 기여한 값은 `+0.0000408531`이었다.
서로 다른 분할 사이의 순위 손실은 `-0.0007064394`였고 합계는 실제 전체 차이 `-0.0006655863`과 일치했다.
후보 예측 평균은 기준 대비 분할 0에서 `-0.0378546317`, 분할 4에서 `+0.0184107137` 이동했다.
이 척도 이동이 분할 안의 작은 순위 개선보다 큰 분할 간 순위 손실을 만들었다.

분할 내부 로그의 `final_auc`는 각 분할에서 양수였지만 전체 OOF 채택 근거로 대신 사용할 수 없다.
이 실험은 전체 OOF를 우선하는 판정 계약이 필요한 실제 사례를 제공한다.

## 실행 무결성과 원격 정리

기준과 후보는 고정 커밋 `47675b4bf5433e5108ea1d36636c1e8abe512440`, 같은 입력 해시와 같은 5분할에서 각각 시드 42로 실행했다.
두 원격 실행은 변경 사항이 남지 않은 상태였고, 원격 실행 식별자는 기준 `b9229e09ff004ed791dafbcf40952928`, 후보 `bfda1788028246909131c166f5f76a48`이다.
결과 묶음의 원격과 로컬 SHA-256은 `afc4765746342e4f938bc566bf7af90221be88673aae1569d92939db796283c8`로 일치했고 내부 목록의 21개 파일도 모두 통과했다.
주 실행 저장소에 반입한 실행 식별자는 기준 `88315d71cab744eb917baa0d65dae7f6`, 후보 `3201b2cd8ea34a44babd0efc07001857`이며 반입 재채점과 필수 산출물 조회를 확인했다.

실행은 사용자의 지정에 따라 Vast.ai만 사용했다.
유효 실행은 장비 27960의 RTX 5070 Ti 2장, Python 3.12.3, PyTorch 2.13.0과 CUDA 13.0 잠금 환경에서 수행했다.
첫 두 준비 시도는 감시 관문의 CUDA 문자열과 GPU 줄 수 판정 결함으로 입력 전송 전에 정리됐다.
세 번째 시도는 학습 중 일시적 SSH 전송 오류를 원격 작업 종료로 잘못 판정해 결과 없이 정리됐다.
감시기가 SSH 전송 오류와 원격 명령 실패를 구분하도록 보강한 뒤 다른 호스트의 네 번째 시도에서 유효 결과를 완료했다.
