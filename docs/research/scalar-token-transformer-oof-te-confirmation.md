# 스칼라 토큰 Transformer OOF 목표 평균 3시드 확정 실행

이 문서는 GitHub 이슈 [exp133 OOF 목표 평균 축을 3시드 5개 fold OOF로 확정한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/309)의 실행과 무결성 검증을 기록한다.
대상 설정은 `configs/exp133_scalar_token_transformer_oof_te.yaml`이며 시드 42, 43, 44와 커밋된 5개 fold를 사용한다.
후보 풀 진입, champion 비교와 교체는 이 이슈 범위 밖이다.

## 결론

세 시드 예측 평균의 OOF AUC는 `0.9678155177269718`이다.
시드별 OOF AUC는 seed 42가 `0.9675945784584812`, seed 43이 `0.9669802991012456`, seed 44가 `0.9673169339531957`이다.
15개 시드와 fold 조합의 카나리아 값 상수성, 카나리아 중요도, 복구 자료 해시, 식별자, fold, 정답 대응과 AUC 독립 재채점이 모두 통과했다.
따라서 이 3시드 전체 OOF 결과를 이슈 309의 확정 자료로 남긴다.
후보 풀 진입이나 champion 판정은 하지 않는다.

원격 원본 실행 식별자는 `dbc7d202e3bd4f47beea5e2c13dae97d`이고 주 작업 폴더 MLflow에 반입한 실행 식별자는 `f16dbc88860a41f39194da2f581f057d`다.
반입 과정에서 입력 해시, 소스 커밋, 설정, 세 시드 OOF와 평균 OOF를 다시 검증했다.

## 고정 실행 계약

실행 소스 커밋은 `76ed92d415283692e6bddef0456e4c44643ed407`이고 설정 파일 SHA-256은 `af1a1049b706152faad8274cd47443eb3c1f17f20f46f78e6798f0e54eee8b10`이다.
입력 묶음 SHA-256은 `91752e68742ee993f3acecf80e7b5fb2d997fd889db8d400b29eb71c787ff1f4`다.
각 시드와 fold의 검증 예측은 식별자, fold와 정답을 로컬 원본에 정확히 대응시키고 저장 AUC를 독립적으로 다시 계산한다.
각 조합의 `placebo_noise_te`는 바깥쪽 학습 부분의 전체 목표 평균 한 값으로 고정돼야 한다.
카나리아 중요도는 `max(placebo_noise 중요도, 0)` 이하이면서 정확히 0이어야 한다.
15개 조합 중 하나라도 예측 무결성이나 카나리아 관문에 실패하면 확정 자료로 사용하지 않는다.

## 실행 전 환경 관문

유료 자원을 만들기 전에 `scripts/verify_environment_gates.sh --source-root <main>`에서 원격 Python 계약 시험 4개와 전체 시험 399개가 통과했다.
`scripts/verify_environment_gates.sh --isolated`에서도 원격 Python 계약 시험 4개와 전체 시험 399개가 통과했다.
대상 이미지 `nvcr.io/nvidia/pytorch@sha256:a411b86de9ac003ce5db43894ea7920718512bc02c51a521157c0899aac75631`의 Linux AMD64 환경 검증도 통과했다.
로컬에서 15개 시드와 fold 조합의 카나리아 값이 각 학습 부분의 전체 목표 평균 상수인지 확인했다.

원격 입력은 SSH 표준 입력으로 전송했고 전송 전후 묶음 해시와 압축 해제 뒤 파일별 해시를 확인했다.
실행 전에 작업별 SSH 호스트 키 고정, 비대화식 인증, 비용 상한과 GitHub 보조 종료 일정을 검증했다.
본 실행은 `2026-08-20T13:50:40Z`에 시작했고 원격 MLflow 실행 식별자는 `dbc7d202e3bd4f47beea5e2c13dae97d`다.

## 예측과 복구 무결성

15개 복구 manifest를 실행 정체성 해시, manifest 내용 해시와 파일별 SHA-256으로 검증했다.
각 검증 예측은 로컬 원본의 식별자 순서와 fold에 정확히 대응했고 같은 행의 정답으로 AUC를 다시 계산했다.
각 시험 예측은 296,302개 식별자의 원본 순서와 정확히 대응했다.
각 중요도 자료는 설정이 요구한 46개 특성을 중복 없이 같은 순서로 가졌고 값은 모두 유한했다.
세 시드별 OOF를 원본 691,369행 순서로 다시 조립해 위 시드별 AUC를 계산했다.
세 배열의 산술 평균을 다시 계산해 최종 OOF와 일치시키고 평균 OOF AUC를 독립 재채점했다.

첫 fold, seed 42 전체, seed 43 전체와 15개 전체 시점에 누적 복구 묶음을 로컬로 회수했다.
5개 누적 묶음 SHA-256은 `1a59e406e0f32de068e532ee73b2a8e885b90d138509831650c7680ea064bedf`이다.
10개 누적 묶음 SHA-256은 `64ae4c43930c4c707f1acbabbef5dea4b981599880664e7213f009ea744745ee`이다.

## 보조 검증 스크립트 결함과 대체 검증

원격 학습 파이프라인은 종료 코드 0으로 끝났고 원본 MLflow 실행과 이식 가능한 실행 기록 묶음도 정상적으로 만들었다.
그 다음 보조 검증 스크립트가 자료 전체 변환으로 특성 계획을 초기화하기 전에 `all_columns()`를 호출해 AssertionError가 발생했고 작업 전체 종료 코드는 1이 됐다.
이 결함은 15개 학습, 복구 지점 저장과 실행 기록 묶음 내보내기가 모두 끝난 뒤의 작업 전용 검사 코드에만 있다.
실행 중인 원격 제어 파일은 바꾸지 않았고 GPU 학습을 다시 실행하지 않았다.

회수 뒤에는 올바른 순서로 범주 정렬과 자료 전체 변환을 수행한 다음 원격 manifest에 고정된 의존성 정체성으로 15개 복구 지점을 모두 검증했다.
주 MLflow 반입기도 원본 자료 해시, 소스 커밋, 설정 파일, OOF 식별자, 세 시드 배열의 평균과 모든 저장 AUC를 별도로 검증했다.
따라서 보조 검사 코드의 종료 오류를 숨기지 않으면서도 이슈가 요구한 무결성 조건은 두 독립 경로로 확인했다.
