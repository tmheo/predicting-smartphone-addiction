# Lookup-Transformer 24회 궤적 학습 상태 확정 결과

이 문서는 GitHub 이슈 [Lookup-Transformer 24회 궤적에서 6·8·12회 후보를 확정 실행한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/430)의 구현, Vast.ai 실행, 중앙 MLflow 반입과 자원 정리 근거를 기록한다.
후보 풀 판정과 등록은 후속 이슈 [두 신경망 학습 상태 대조축을 직렬 nested OOF로 판정해 최대 2개를 등록한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/425)의 범위이므로 이 문서에서는 수행하지 않는다.

## 고정 계약

실행 커밋은 `17dc5d28467a8284e20272ad61de0e52e646bdf9`이고 확정 단계, 난수 42·43·44, 고정 5분할을 사용했다.
각 난수와 분할 조합은 24회 물리 궤적 하나만 학습하고 사전 고정한 EMA 상태 6·8·12회를 같은 궤적에서 추출했다.
상태 선택에는 검증 목표값을 사용하지 않았고 학습률 일정의 24회 지평도 줄이지 않았다.
궤적 식별 SHA-256은 `5d8805f2ddc8d7b1c8232990d6263d5d5ac968fc13fb165a0699b7f934e30010`이고 후보 집합 SHA-256은 `fb03f9960c5d248b61e318d13d3f268476fa9a4bc0ffc71944e364413db2efe1`이다.
훈련 자료, 시험 자료와 고정 분할의 SHA-256은 각각 `f4669147311c76eb03496061a852af283efcf0f12cf5c19274e775def81edd9c`, `8b462dd47fe8165cd0b082bf33b56523c5811453070af48b9f86b2eb928de49e`, `5f5d09e9356f227ecb4a063270b175bb5cae20afb25636c563db185e18a155c4`다.

## 실행 경로 보강

첫 Vast.ai 시도는 첫 24회 분할 학습을 마친 뒤 `training_state.trajectory_fit` 관측 작업이 등록되지 않은 오류로 후보 게시 전에 끝났다.
관측 작업 등록을 보강한 뒤 실제 실행 경로와 가까운 GPU 없는 종단 검사를 수행해 두 번째 게시 오류도 재현했다.
두 번째 오류는 적용 전 특징 계획을 새로 만들어 열 목록을 읽던 집계 경로였고, 실제 적용된 열 목록을 세 난수 결과에 공통으로 전달하도록 고쳤다.
별도 회귀 검사에서 작업 공간이 바뀌어도 상대 경로 결측 가중치 캐시가 이전 식별자 순서를 재사용하던 기존 오류를 확인해 절대 경로별 캐시로 분리했다.
최종 격리 환경 검사에서는 Python 검사 781개와 원격 Python 계약 검사 4개가 통과했다.

두 번째 제어 호출 당시 RTX A4000 조건을 만족하는 매물이 0개여서 유료 자원을 만들기 전에 안전하게 끝났다.
사용자의 비용 제한 해제 지시에 따라 성능과 신뢰도를 우선하는 후보군으로 넓힌 뒤 일본의 A100 SXM4 80GB를 선택했다.
Runpod은 사용하지 않았다.

## 반입과 무결성

세 실행 묶음을 모두 중앙 MLflow에 반입한 뒤 감사를 시작했다.
각 실행은 완료 상태, 깨끗한 고정 커밋, 입력 해시, 확정 단계, 세 난수, 공통 부모 궤적과 사전 고정 상태 manifest를 통과했다.
OOF를 훈련 목표값으로 다시 채점한 값은 기록 지표와 `1e-9` 이내로 일치했고 대표 OOF는 난수 42·43·44 예측 평균과 `1e-12` 이내로 일치했다.
시험 예측과 제출 파일의 식별자 순서와 값도 일치했고 특징 중요도는 비어 있지 않으며 모두 유한했다.
6·8·12회 OOF와 시험 예측의 내용 SHA-256은 각각 서로 달라 세 후보가 같은 예측을 잘못 복제하지 않았음을 확인했다.

후보 풀 SHA-256은 반입 전후 모두 `caa1b90769720a4accbe07074dbc7efe0335ab6657fea80c6839b60121dc39d3`이었다.
따라서 이 실행은 후보 풀, 전체 자료 재학습 계획과 최종 제출물을 변경하지 않았다.
기계 판독 결과는 `artifacts/issue430-lookup-training-state-results.yaml`에 기록한다.

## 자원과 비용

첫 RTX A4000 시도 `48782862`의 확정 청구액은 GPU `$0.022`, 저장 공간 `$0.003`, 내려받기 `$0.016`을 합친 `$0.041`이다.
성공한 A100 시도 `48790654`의 확정 청구액은 GPU `$1.470`, 저장 공간 `$0.021`, 송수신 `$0.000`을 합친 `$1.491`이다.
이슈 430의 Vast.ai 총비용은 `$1.532`다.

결과 반입과 감사를 마친 뒤 인스턴스 `48790654`, 이슈 전용 저장 공간과 보조 종료 예약을 모두 제거했다.
최종 재조회에서 이슈 430 계산 자원, 저장 공간과 종료 예약은 각각 0개였다.
동시에 실행 중이던 다른 작업의 인스턴스 한 개와 종료 예약 한 개는 변경하지 않고 보존했다.

## 인계

후속 이슈 425는 중앙 반입 실행 `19c87be034414b5bb7e6d562aadb73da`, `f1ff7d61ea3f4b36a7f172181afeaeb7`, `e80283046f9e4143b7031d45b800ade7`을 동결 입력으로 사용한다.
이 세 실행은 Muon RealMLP 1·2·3회 후보와 함께 총 6개 후보의 직렬 nested OOF 한계 기여를 현재 35개 풀에서 판정하고, 통과 후보만 순서대로 최대 두 개 등록하는 절차에 들어간다.
