# RealMLP 정확값 빈도 8열 짝비교

## 결론

정확값 빈도 8열을 더한 `exp141_realmlp_exact_frequency`는 직접 기준인 `exp124_realmlp_dtype_fix`보다 시드 42 OOF AUC가 `-0.00004636` 낮았다.
다섯 분할이 모두 나빠 사전 고정한 선별 문턱을 통과하지 못했다.
따라서 3시드 확인 실행을 열지 않았고 피처 묶음은 `실신호 미확인`으로 판정했다.

## 구현과 비교 규율

후보 설정은 `exp124_realmlp_dtype_fix`의 RealMLP 모델과 분할 학습 자료 전용 전처리를 그대로 사용한다.
추가한 열은 `age_ce`, `daily_screen_time_hours_ce`, `social_media_hours_ce`, `work_study_hours_ce`, `sleep_hours_ce`, `notifications_per_day_ce`, `app_opens_per_day_ce`, `weekend_screen_time_ce`다.
이 8열은 각 분할 학습 자료에서만 빈도를 학습하고 검증 자료와 시험 자료에는 고정된 대응표를 적용한다.
구성 차이 검사는 두 설정의 차이가 `features.providers.frequency_encoding` 하나뿐임을 고정한다.
결과를 보고 하위 묶음이나 다른 변환을 고르지 않았다.

## 짝지은 OOF 결과

| 단계 | 시드 | 후보 OOF | 기준 OOF | 변화 | 분할 승수 |
| --- | --- | ---: | ---: | ---: | ---: |
| 선별 | 42 | 0.9682100458 | 0.9682564071 | -0.0000463613 | 0/5 |

분할별 변화는 `[-0.00007637, -0.00007692, -0.00003026, -0.00003700, -0.00001840]`이다.
시드 42 짝차이가 0 이상일 때만 3시드 확인으로 진행한다는 규칙에 따라 추가 GPU 실행을 중단했다.

## 보조 중요도

플라시보 평균 중요도는 `0.00000235373`이었다.
`daily_screen_time_hours_ce`, `social_media_hours_ce`, `notifications_per_day_ce`, `work_study_hours_ce`는 평균 중요도가 플라시보보다 높았다.
`sleep_hours_ce`의 평균 중요도는 `-0.00000100529`였고 5개 분할 모두 플라시보보다 낮았다.
여러 열의 보조 중요도가 양수였지만 짝지은 OOF는 모든 분할에서 음수였다.
중요도는 결과 설명에만 사용하며 실신호나 채택 관문으로 사용하지 않았다.

## 후보 풀 판정

후보 풀 등록과 원자 교체에는 깨끗한 3시드 평균본과 현재 후보 풀을 동결한 `candidate-pool-v1` nested OOF 대조가 필요하다.
이번 후보는 선별을 통과하지 못해 3시드 평균본을 만들지 않았다.
따라서 현재 구성원 `exp140_realmlp_orig_cdf_diff`와의 직접 교체, 후보 포함·제외 nested OOF, 후보 풀 장부 변경은 평가하지 않았다.

## 원격 실행과 처리량 진단

모든 외부 GPU 실행은 Vast.ai만 사용했고 Runpod은 사용하지 않았다.
처음 선택한 서로 다른 RTX A4000 장비 두 대에서는 기준 실행의 epoch 시간이 각각 약 `115.5`초와 `89.9`초였다.
과거에 같은 코드 경로를 정상 완료한 장비 `144022`에서는 첫 epoch가 `20.0`초였고 이후에도 약 20초를 유지했다.
RealMLP 코드, 기준 설정, 잠금 파일, Python 패키지 판본과 첫 번째 느린 장비의 그래픽 드라이버까지 같았으므로 코드 성능 저하는 배제했다.
같은 실행의 실제 GPU 사용 상태와 epoch 시간이 장비 교체 뒤 정상화된 결과를 바탕으로 Vast.ai 장비별 실제 학습 처리량 차이로 판정했다.

유효 실행은 고정 커밋 `a6a7af726a8361188d6cb73008edcecfffadce17`, 같은 입력 해시, 같은 5분할과 같은 컨테이너 이미지에서 수행했다.
결과 묶음은 원격과 로컬 SHA-256 `520adceebdd1f8beb196a7d61d87f1a739e79764f58411c98f4686b612156e55`가 일치했고 내부 산출물 목록 검증도 통과했다.
결과를 기본 MLflow 저장소에 반입한 뒤 인스턴스를 삭제했다.
삭제 뒤 대상 인스턴스, 작업용 저장 공간과 이 작업의 종료 예약이 모두 없음을 확인했다.
