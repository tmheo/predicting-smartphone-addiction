# S6E8 Featuretools 대량 특성 실험 판정

## 결론

Featuretools를 이용한 대량 특성 실험은 남은 3일의 개선 후보로 열지 않는다.

현재 자료는 행마다 독립된 단일 표이고, 자연스러운 부모-자식 관계나 사건 시간축이 없다.
Featuretools의 주된 장점인 관계형 표 사이의 집계 특성 생성이 작동할 구조가 아니다.
수치 열의 합, 차, 곱, 비율을 대량 생성하는 방식은 이미 실패한 이 저장소의 산술 관계 및 쌍 특성 실험을 더 넓게 반복할 가능성이 높다.

정말 미련을 없애기 위한 제한 실험은 가능하지만, 최종 결합 후보 선별과 결합 모형 규제 강도 판정보다 우선순위가 낮다.

## Featuretools가 이 자료에서 실제로 만드는 것

[Featuretools 공식 저장소](https://github.com/alteryx/featuretools)는 여러 관련 표를 `EntitySet`으로 연결하고, 변환과 집계를 쌓는 Deep Feature Synthesis를 핵심 용도로 설명한다.
[공식 EntitySet 안내](https://docs.featuretools.com/en/stable/getting_started/using_entitysets.html)도 고객, 세션, 거래처럼 관계가 있는 표를 중심으로 구성되어 있다.

[Deep Feature Synthesis 공식 구현](https://github.com/alteryx/featuretools/blob/main/featuretools/synthesis/deep_feature_synthesis.py)은 표가 하나뿐이면 더 깊은 특성을 만들 수 없다는 경고와 함께 최대 깊이를 1로 낮춘다.
기본 집계 연산은 합, 표준편차, 최댓값, 최솟값, 평균, 개수, 값 종류 수, 최빈값 등이다.
기본 변환 연산은 날짜, 글자 수, 단어 수, 지리 거리 등에 치우쳐 있어 현재 열 구성에는 거의 적용되지 않는다.

따라서 현재 자료에서 대량 산술 특성을 얻으려면 덧셈, 뺄셈, 곱셈, 나눗셈 같은 연산을 직접 지정하거나 별도 연산을 작성해야 한다.
이는 Featuretools가 새로운 자료 구조를 발견하는 것이 아니라, 우리가 정한 산술 문법을 대량 전개하는 작업이다.

## 기존 실험과의 중복

이 저장소는 이미 화면 시간 관계 7개를 추가한 `exp104`에서 OOF AUC `-0.0000155`, 분할 승리 1/5로 기각했다.
근거는 [synthetic-structure-followup.md](synthetic-structure-followup.md)와 이슈 181에 기록되어 있다.

공개 해법에서 가져온 합, 비율, 로그, 상호작용 16개 묶음도 `exp126`에서 OOF AUC `-0.0000640`, 분할 승리 0/5로 기각했다.
36개 수치 쌍의 정확값 격자 목표 인코딩도 champion 대비 `-0.00037`, 조밀화 변형은 `-0.00050`이었다.

[hidden-constraint-diagnosis.md](hidden-constraint-diagnosis.md)는 9개 수치 열에 작은 유리 계수의 단항식과 합, 차, 비율, 최솟값, 최댓값을 전수 조사했지만 알려진 화면 시간 예산 외에 새 제약을 찾지 못했다.
[playground-top10-s4e7-s4e4.md](playground-top10-s4e7-s4e4.md)의 과거 대회 검토에서도 자동 특성 생성의 독립 재현이 악화됐고, 현재 S6E8의 자동 생성 및 고차 조합 음성 판정을 뒤집을 직접 근거가 없었다.

Featuretools가 생성할 단일 표 산술 특성 대부분은 이 실패 영역과 겹친다고 보는 것이 타당하다.

## 검증과 계산 위험

[Featuretools 시간 처리 안내](https://docs.featuretools.com/en/stable/getting_started/handling_time.html)의 차단 시각은 시간 순서 뒤의 정보를 막는 기능이다.
현재 무작위 층화 교차검증의 검증 행을 자동으로 격리해 주는 기능은 아니다.

범주별 평균이나 표준편차 같은 자료 기반 집계를 만들 경우 각 바깥 분할의 학습 부분에서만 값을 계산해야 한다.
전체 훈련 자료에서 먼저 만들면 검증 행의 분포가 집계값에 들어간다.
행 단위 산술 변환만 사용하면 이 문제는 없지만, 그 경우에는 기존 산술 실험과의 중복이 더 커진다.

[공식 특성 선택 안내](https://docs.featuretools.com/en/latest/guides/feature_selection.html)는 결측 비율, 단일값, 높은 상관처럼 목표값을 사용하지 않는 정리 기능을 제공한다.
많은 후보를 같은 OOF에서 반복 비교해 우연히 좋은 특성을 고르는 선택 편향은 해결하지 않는다.
공정하게 판정하려면 후보 선택 자체를 바깥 교차검증 안에 넣어야 하므로 남은 기간에 비해 계산량과 판단 잡음이 크다.

## 허용 가능한 마지막 확인의 상한

추가 확인을 하더라도 다음 한 묶음으로 고정한다.

- 단일 표와 최대 깊이 1만 사용한다.
- `id`, 목표값, 플라시보 열은 입력에서 제외한다.
- 자료에서 값을 학습하지 않는 행 단위 덧셈, 뺄셈, 곱셈, 안전한 나눗셈만 사용한다.
- 인위적인 표 관계, 범주별 집계, 시간 차단, 목표값을 이용한 후보 선택은 사용하지 않는다.
- 상수와 완전 중복 열만 제거한다.
- 기준 모형과 같은 분할, 같은 시드로 묶음 전체를 한 번만 비교한다.
- OOF AUC가 양수가 아니거나 분할 다수에서 이기지 못하면 즉시 종료한다.

이 범위에서는 Featuretools를 새 의존성으로 넣을 이유가 약하다.
기존 특성 공급자에 고정된 연산 묶음을 직접 구현하는 편이 더 단순하고 재현하기 쉽다.

## 최종 판정

대량 Featuretools 탐색은 `기각`이다.
제한된 행 단위 산술 묶음 한 번은 `가능하지만 비우선`이다.
남은 3일은 새 후보를 수백 개 만드는 일보다 이미 확보한 외부 후보의 엄격한 선별과 최종 결합 모형의 규제 강도 판정에 쓰는 편이 기대값이 높다.
