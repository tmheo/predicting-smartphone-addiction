- 지도: [35개 후보 풀을 선택 편향 없이 축소하는 기준과 최종 구성 확정](https://github.com/tmheo/predicting-smartphone-addiction/issues/338)
- 티켓: [35개 후보 풀의 제거 대조 목록과 실행 순서를 사전 고정한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/341)
- 기계 판독 장부: `artifacts/pool-rereview-precommit-2026-08-22.yaml`
- 장부 SHA-256: `978b77916e4e7bc00edd1c4f3e72186726ed8ba5ee102f0e550446c9dd89a8bf`

## 결론

실제 구성원 제거 결과를 보기 전에 후보, 영점 대조, 네 단계의 제거 대상, 조사 순서, 성능 동등 판정, 난수, 결합 전략, 중단 조건과 산출물 계약을 하나의 장부로 고정했다.
실행은 먼저 영점 대조 210건을 끝내 성능 동등 하한을 한 번만 정한 뒤, 바깥쪽 다섯 분할과 전체 OOF 최종 실행을 차례로 돈다.
기존 하한보다 넓어진 경우에만 하한을 갱신하고, 실제 제거 결과가 나온 뒤에는 어떤 규칙도 바꾸지 않는다.

장부는 동결 기준 장부의 후보 35개, 다구성원 모델 계보 묶음 9개와 정보 관점 14개를 모두 직접 싣는다.
결합 전략은 현재 기본 평가 범위 19개의 이름과 등록 순서를 직접 싣고, 정밀 전략 3개는 제외 목록으로 고정한다.
입력 파일, 선행 결정 문서와 결합 전략 구현의 내용 해시를 싣기 때문에 실행 전 입력 변화를 기계적으로 거부할 수 있다.

## 1. 실행 경계

실행 시작점은 실제 제거 대조가 아니라 영점 대조의 첫 적합이다.
그 시점부터 다음 변경을 금지한다.

- 후보와 제거 대상 집합의 추가, 삭제 또는 이름 변경.
- 단계, 정렬 열쇠, 동률 해소 또는 판정식 변경.
- 결합 전략의 추가, 삭제, 순서 또는 매개변수 변경.
- 난수, 반복 수, 분할, 중간 저장 단위 또는 산출물 필드 변경.
- 일부 결과를 본 뒤 특정 대조를 건너뛰거나 실패 전략만 빼고 계속하는 일.

허용하는 변화는 사전 고정한 산식에 따라 기존 하한보다 더 넓은 하한을 채택하는 일뿐이다.
실패한 실행은 원인을 기록한 뒤 같은 입력과 계약으로 다시 시작하거나 중간 저장에서 재개한다.

## 2. 영점 대조와 하한

현재 하한은 `-0.000027669802`다.
선택 편향 없는 재심사 절차가 기존 대역 측정과 척도가 달라졌으므로 크기 1 복제 영점 대조를 두 척도에서 다시 잰다.

| 척도 | 블록 | 블록별 복제 대조 | 합계 |
| --- | ---: | ---: | ---: |
| 전체 OOF | 1 | 35 | 35 |
| 각 바깥쪽 검증 분할의 학습 부분 | 5 | 35 | 175 |
| 합계 | 6 | 35 | 210 |

복제 원본은 동결한 후보 목록 순서대로 35개 전부다.
작은 팔은 동결한 35개 풀이고, 큰 팔은 여기에 해당 구성원의 정확 복제 열 하나를 더한 풀이다.
차이는 작은 팔 AUC에서 큰 팔 AUC를 뺀 값이다.

각 척도의 하한은 세 값의 최솟값이다.

1. 관측된 복제 제거 차이의 최솟값.
2. 짝지은 행 부트스트랩 2.5백분위의 최솟값.
3. 같은 블록의 서로 다른 복제 큰 팔 사이 AUC 차이의 최솟값.

같은 크기 차이는 서로 다른 두 큰 팔을 양방향으로 짝지어 부호 선택 여지를 없앤다.

실행 하한은 기존 하한과 두 척도 하한의 최솟값이다.
새 하한이 높게 나오면 기존 하한을 유지하므로 대역은 결과를 보고 좁아지지 않는다.
영점 대조를 모두 끝내고 산출물 내용 해시를 고정하기 전에는 실제 구성원 제거 대조를 시작하지 않는다.

짝지은 행 부트스트랩은 `BOOTSTRAP_SEED=342342`, 2,000회로 고정했다.
재표집은 각 outer fold 안에서 목표값 층을 보존하며 같은 행을 두 팔에 함께 적용한다.

## 3. 여섯 실행 블록

실행 블록 순서는 다음과 같다.

1. `outer-0`
2. `outer-1`
3. `outer-2`
4. `outer-3`
5. `outer-4`
6. `final`

바깥쪽 분할 블록은 해당 fold를 뺀 학습 부분에서만 순서, 구성원과 전략을 고른다.
뺀 fold는 선택이 끝난 뒤 고른 풀과 전략으로 예측할 때만 등장한다.
다섯 채점 예측을 이어붙여 편향 없는 절차 nested OOF AUC와 선택 안정성을 만든다.

`final`은 전체 OOF를 사용해 인수할 고정 풀을 고르는 유일한 결정 블록이다.
바깥쪽 다섯 분할 결과는 감시와 안정성 기록이며 `final`의 선택을 직접 바꾸지 않는다.

## 4. 분할마다 한 번 정하는 조사 순서

각 블록은 동결한 35개 앵커 풀에서 등록 전략 19개를 모두 평가한다.
가장 높은 AUC의 전략을 고르고, 정확히 같으면 등록 순서가 앞선 전략을 고른다.

제외 기여는 앵커 풀이 고른 전략 하나로 고정해 잰다.
제거 대상 집합을 뺀 AUC에서 빼기 전 AUC를 뺀 float64 원값이다.
이 값은 블록마다 앵커 풀에서 한 번만 계산하고 실제 제거가 일어난 뒤 다시 계산하지 않는다.
기여 영점 대역으로 같은 값처럼 묶지 않고 원값 오름차순으로 정렬한다.
제외 기여는 조사 순서에만 쓰며 제거 판정에는 쓰지 않는다.

동률 열쇠도 해당 블록의 동결한 35개 앵커 풀에서 한 번 계산한다.
동률은 다음 순서로 가른다.

1. 제거 뒤 완전히 사라지는 정보 관점 수가 적은 대상.
2. 같은 계보에서는 이전판에 가까운 대상.
3. 해당 학습 행에서 단독 OOF AUC가 낮은 대상.
4. 제거로 줄어드는 전체 자료 재학습 횟수가 큰 대상.
5. 제거 대상 config 이름 튜플의 사전순.

같은 계보에서는 동결 장부의 선행 관계 깊이가 작은 이전판부터 조사하고, 같은 깊이는 공통 동률 해소 사슬로 가른다.

교집합이 비었거나 작업 풀 전체가 사라지는 대조는 사유를 기록하고 건너뛴다.

앞 단계에서 이미 제거된 구성원은 빈 교집합으로 기록하고 건너뛴다.

## 6. 한 대조의 판정

제거 전 팔과 제거 후 팔은 각각 등록 전략 19개를 모두 다시 평가한다.
한 팔이 고른 전략을 다른 팔에 물려주지 않는다.

차이 `delta`는 제거 후 AUC에서 제거 전 AUC를 뺀 값이다.
`delta < adopted_lower`이면 제거로 성능이 대역 밖까지 내려갔으므로 유지한다.
그 밖은 제거가 개선이거나 동등 대역 안의 하락이므로 제거한다.

유지 판정에서는 작업 풀을 바꾸지 않는다.
제거 판정에서만 작업 풀을 제거 후 팔로 옮긴다.
모든 대조에서 직전 작업 풀 대비 차이와 35개 앵커 대비 누적 차이를 함께 기록한다.

## 7. 최종 풀과 경계 표시

`final` 축소 궤적의 모든 지점을 후보로 본다.
35개 앵커 대비 차이가 채택 하한 이상인 지점 중 구성원 수가 가장 작은 풀을 고른다.

같은 크기의 후보가 여러 개면 다음 순서로 가른다.

1. 35개 앵커 대비 차이가 큰 풀.
2. 전체 자료 재학습 횟수가 적은 풀.
3. 남은 config 이름 튜플의 사전순.

최종 후보 한 건에만 짝지은 행 부트스트랩 2,000회를 적용한다.
2.5백분위가 채택 하한보다 작으면 경계 후보로 표시하고 궤적상 직전 풀을 함께 넘긴다.
경계 표시는 판정을 바꾸지 않는다.

## 8. 중단 조건

다음 조건에서는 결과를 만들지 않고 실행을 멈춘다.

- 동결한 입력, 선행 결정 문서 또는 결합 전략 구현의 내용 해시가 달라짐.
- 후보, 모델 계보 묶음, 정보 관점, 결합 전략 이름이나 순서가 장부와 달라짐.
- OOF id, fold, 목표값 id가 맞지 않거나 fold 0부터 4까지를 정확히 덮지 않음.
- 예측에 결측값이나 유한하지 않은 값이 있음.
- 필요한 결합 전략 19개 중 하나라도 적합 또는 예측에 실패함.
- 결정 산출물 스키마가 빠지거나 중간 저장의 입력과 내용 해시가 달라짐.
- 같은 입력으로 다시 계산한 결정 산출물이 글자 단위로 달라짐.
- 실행 코드가 커밋되지 않았거나 작업 폴더가 깨끗하지 않음.

실패한 전략만 제외해 계속하는 복구는 금지한다.
실패 뒤 난수, 하한, 후보 또는 순서를 바꾸는 복구도 금지한다.

## 9. 산출물 계약

결정 산출물과 실행 계측을 분리한다.
중간 저장 재개는 끝난 단위를 다시 적합하지 않으므로 소요 시간과 적합 횟수가 달라도 정상이다.

| 산출물 | 경로 | 역할 |
| --- | --- | --- |
| 영점 대조 | `run-logs/pool-rereview/null-band.json` | 두 척도의 대조와 채택 하한 |
| 중간 저장 | `run-logs/pool-rereview/checkpoints/*.json` | 분할별 결정, 예측과 내용 해시 |
| 결정 | `run-logs/pool-rereview/decision.json` | 궤적, 최종 풀, 전략, 절차 점수와 안정성 |
| 실행 계측 | `run-logs/pool-rereview/telemetry.json` | 시간, 적합 수, 작업자 수, 재개와 실패 기록 |
| 내용 해시 | `run-logs/pool-rereview/manifest.sha256` | 산출물 상대 경로별 SHA-256 |

대조마다 제거 대상, 단계, 작업 풀 크기, 직전 풀 대비 차이, 판정, 앵커 대비 누적 차이, 양팔 전략, 전략 도약, fold별 차이와 음수 fold 수를 남긴다.
정렬 열쇠와 양팔의 전략별 AUC도 함께 남겨 실제 순서가 장부를 따랐는지 사후 감사할 수 있게 한다.

결정 산출물에는 시간, 적합 횟수, 작업자 수와 재개 횟수를 넣지 않는다.
같은 입력의 처음 실행과 재개 실행은 `decision.json`이 글자 단위로 같아야 한다.
실행 커밋, 작업 폴더 상태, Python 판본, 의존성 잠금 파일 해시, 운영체제, CPU 구조와 동시 실행 수를 정하는 환경 변수는 실행 정체성으로 따로 남긴다.
