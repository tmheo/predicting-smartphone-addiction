# 고정 반복 수 트리 변형 26개 확정 실행과 일괄 nested 선택 판정 결과

이 문서는 GitHub 이슈 [#419](https://github.com/tmheo/predicting-smartphone-addiction/issues/419)의 외부 CPU 실행, 중앙 MLflow 반입, 자격 필터, 일괄 nested 선택 판정, 후보 풀과 재학습 계획 반영, 자원 정리 근거를 기록한다.
결과 원본은 `artifacts/issue419-tree-confirm-results.yaml`이고 판정 기록은 `artifacts/judgments/issue419-*.yaml`이다.

## 동결 입력

26개 설정은 이슈 #413의 기준 6개 가운데 5개의 10%·5% 변형 8개(exp177~exp184)와, #413에 없던 LightGBM 후보 풀 구성원 9개의 20%·10% 변형 18개(exp185~exp202)다.
반복 수는 `artifacts/full-refit-plan.yaml`의 관측 학습 길이 15개 중앙값에 비율을 곱해 사사오입한 값이며 이슈 표의 26개 값과 전부 일치한다.
기준 설정과 비교해 이름, 조기 종료 해제, 반복 수 외에는 같다.
exp006의 역사 설정은 #71 이전 스키마라 현재 코드가 읽지 못하므로, 재학습 계획이 가리키는 동등 설정 `configs/refit/exp006_te_drop_gaming.yaml`을 exp185·exp186의 기준으로 삼았다.
모든 실행은 커밋 `446378d3f88ad0693cb7b5bba74209fcee5e2b93`(PR #420), 확정 단계, 난수 42·43·44, 고정 5분할을 사용했다.
훈련·시험 자료와 분할 파일의 SHA-256은 #414와 같고, exp023 계보가 쓰는 원본 프록시 CSV의 SHA-256은 `2194ce1946e8559f26780049c8d972857d8378104f2c9ec25ed9ec35409f1074`다.

## 실행

Vast.ai CPU 인스턴스 한 대에서 여섯 실행 줄로 병렬 실행했다.
같은 기준 구성원의 변형은 같은 줄에 두어 내용 기반 fold-fit 재사용 저장소가 피처 계산을 공유하게 했고, 실제로 10% 변형은 20% 변형 뒤에 2~4분 만에 끝났다.
원격 제어부는 로그의 실행 식별자를 순서를 보존해 중복 제거해 #414에서 드러난 중복 판독 결함을 회피했다.

세 번의 시도가 있었다.

| ---: | --- | ---: | --- | ---: |
| `48715685` | 덴마크 | 64 | 이미지 적재 뒤 `created`/`intended_status=stopped`에 머물러 시작되지 않아 삭제 | `$0.005` |

세 번째 인스턴스의 실행은 02:04 UTC에 시작해 03:31 UTC에 결과를 회수했다.
lane-d의 exp178(LightGBM AG25 10%, 1836회)이 64분으로 병목이었고 나머지 줄은 한 시간 안에 끝났다.
Vast.ai 청구 합계는 `$0.327`이며 세 인스턴스 모두 삭제와 계정 목록 부재를 확인했고 종료 예약 변수는 빈 배열로 되돌렸다.
48코어 이상 비중국 매물이 덴마크 한 곳뿐이었고 한국·일본은 32코어급만 있었다.

컨테이너가 보이는 CPU 수와 cgroup 할당량이 다른 호스트에서는 줄당 스레드를 할당량 기준으로 나눠야 한다.
이 교훈은 `run-logs/vast-issue419/input/remote_driver.py`의 `split_cpus`에 남겼다.

## 반입 검증

26개 묶음을 기본 `main` 작업 폴더의 중앙 MLflow에 반입했다.
각 실행은 완료 상태, 확정 단계, 난수 3개, 깨끗한 동결 커밋, 입력 해시 3개, `remote.provider=vast` 태그, 반입 묶음 해시와 `fixed_count` 진단 15개를 독립 재조회했다.
26개 실행과 390개 진단이 모두 통과했고 누락이나 제외 실행은 없다.

## 자격 필터

규칙은 결과 확인 전에 이슈에 고정했고 결과를 본 뒤 적용했다.

- 진입 하한 `0.9593676`(champion exp156 3시드 OOF - 0.01) 미달: 0개. 최저는 exp192(orig_proxy_residual 10%)의 `0.9598336`으로 하한 위 `4.7e-04`다.
- 기존 풀 구성원과 스피어만 `0.998` 이상: exp180(no-TE 10%)이 같은 계보의 exp168(no-TE 20%)과 `0.99866`이라 같은 계보 원자 교체 대조로 분리했다.
- 플라시보 카나리아 유효성(#33): exp201·exp202(lattice_te 계보)가 실패했다.
  격자 목표값 인코딩 `placebo_noise__age_latf_te`는 카나리아로 취급되는데 반복이 41회·20회로 적으면 그 gain(730, 124)이 `placebo_noise` 원본(172, 40)을 넘는다.
  판정 도구가 후보 적재 단계에서 거부하므로 두 변형은 실패 변형으로 목록에 남기고 제외했다.

일반 진입 후보는 23개다.

다중 후보 판정에서 도구가 등록 대상으로 적는 전체 OOF 최종 후보는 세 회차 모두 exp178(LightGBM AG25 10%)이었지만 바깥 분할 선택에서는 한 번도 과반을 얻지 못했다(0/5, 2/5, 0/5).
이슈 규칙은 "완전 중첩 선택에서 분할 과반이 같은 후보를 고른 변형"을 등록 대상으로 정하므로, 사용자 결정으로 과반 후보를 단독 진입 판정에 넣어 등록 여부를 정했다.
단독 판정의 전체 차이는 다중 후보 판정의 nested 차이와 같거나 거의 같았다(분할 선택이 이미 그 후보였기 때문이다).
#415 4회차가 3/5 과반과 다른 전체 OOF 후보의 불일치에서 등록하지 않았던 전례와는 다른 처리이며, 이 결정은 #419 코멘트와 `run-logs/vast-issue419/ledger.md`에 남겼다.

기여가 `+0.0000230`에서 `+0.0000046`으로 줄어 #386이 잰 결합 도구 잡음 바닥 `5.7e-06` 아래로 내려갔으므로, 사용자 결정으로 4회차를 마지막 회차로 고정했다.
4회차에서 과반 후보가 없었으므로 이 결정이 결과를 바꾸지는 않았다.

직렬 진입은 2건, 합계 `+0.0000276`이다.
사전 등록 기대값(2~4건, `+0.00003`~`+0.00008`)의 건수 하단이며 합계는 하단에 약간 못 미친다.

## 후보 풀과 재학습 계획

- 후보 풀은 33개에서 35개로 늘었고 SHA-256은 `caa1b90769720a4accbe07074dbc7efe0335ab6657fea80c6839b60121dc39d3`이다.
- exp197은 고정 76회 관측 15개, exp183은 고정 410회 관측 15개를 `fixed_count` 근거로 연결했고, 1.25 배수와 사사오입으로 시드별 예산은 각각 95회와 513회다.
- 전체 자료 재학습 계획은 구성원 35개, 실행 103회로 갱신했고 `pipeline.refit_plan --validate-only` 관문을 통과했다.
- 계획 파일이 바뀌어 #226의 manifest는 무효가 되지만 이는 #415 진입으로 이미 확정된 비용이다.

## 관찰

- 20% 변형의 기여는 계보마다 달랐다. 2회차에서 recon_ce 20%가 5/5로 고른 반면, 같은 규모의 다른 LightGBM 20% 변형은 3회차 이후 과반을 얻지 못했다.
- 10%·5% 변형은 exp183(CatBoost exact 10%) 하나만 통과했고, 나머지는 단독 OOF 하락이 커지는 만큼 결합 기여가 따라오지 않았다.
- 다중 후보 판정의 전체 OOF 최종 선택과 바깥 분할 과반 선택이 세 회차 연속 갈렸다. 전체 OOF 최종 선택은 후보 23개의 최댓값을 고르므로 선택 편향이 있고, 이슈 규칙이 분할 과반을 기준으로 삼은 이유가 여기서 드러났다.
