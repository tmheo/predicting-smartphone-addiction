# 확장 스택 nested OOF 사다리 판정 (이슈 #443)

## 결론

자체 35개 풀에 #442 장부 통과 외부 구성원 209개를 더한 확장 스택(244구성원)이 `shrunk_rank_logit_logistic`로 **nested OOF `0.9703167`**, 가중 OOF `0.9711834`다.
35개 풀 nested `0.9698106` 대비 `+0.0005062`이고 바깥쪽 검증 분할 5개 전부에서 양수다.
지도 #441의 등록 문턱(`+0.0001` 이상, 5/5 양수)을 넘고, 사다리 구성 가운데 nested가 가장 높다.
**두 번째 최종 제출의 구성은 own35 + ext209, 결합 전략 shrunk_rank_logit_logistic로 확정한다.**

문턱을 넘는 구성이 셋(own35+ext85, own35+ext209, ext209만)이지만 서로의 차이가 잡음 바닥 `5.7e-06`을 훨씬 넘어 "구성원이 적은 쪽" 규칙은 발동하지 않는다.
사다리와 문턱은 결과 확인 전에 고정했고 결과를 본 뒤 바꾸지 않았다.

지도가 Public 0.9713을 넘기 위해 필요하다고 본 nested 약 `0.9702`를 처음으로 넘은 구성이다.
우리와 상위권 팀 공통의 nested-LB 오프셋 약 `+0.0011`을 더하면 Public `0.9714` 자리지만, 이 값은 판정에 쓰지 않는 참고치다.

## 사다리와 규칙

사다리는 티켓이 정한 대로 결과 확인 전에 고정했다.

1. `own35`: 자체 후보 풀 35구성원만
2. `own35_ext85`: 자체 35 + #386 재현가능 85
3. `own35_ext209`: 자체 35 + #442 장부 통과 209
4. `ext209`: 장부 통과 209만(자체 풀의 한계 기여 확인)

네 구성 모두 `pipeline.ensemble`의 기본 등록 전략 19개를 전수 비교했다.
정밀 전략 3개(bagged greedy, optuna 2종)는 기본 평가 범위 밖이라 #386과 같이 뺐다.
가중 OOF는 `judgment.weighted_oof_auc`로 test 결측 패턴 구성비를 적용해 같이 남겼다.

등록 문턱은 35개 풀 nested `0.9698106`(`run-logs/issue337/ensemble-evaluation.json`) 대비 `+0.0001` 이상, 바깥쪽 검증 분할 5/5 양수다.
분할별 양수 여부는 이번 세션에서 다시 잰 own35 최선 전략의 분할 AUC와 비교했다.
문턱을 넘는 구성이 여럿이면 nested가 가장 높은 구성을 고르되, 차이가 잡음 바닥 `5.7e-06` 안이면 구성원이 적은 쪽을 고른다.

여기에 두 가지 검사를 더했다.

- 기준 재현 `repro_own32_ext85`: #386 합본 117(자체 32 + 외부 85)을 같은 열 순서로 다시 재서 `0.9700014`와 잡음 바닥 안에서 맞는지 본다.
  자체 32에는 현재 풀에 없는 `exp127_lookup_muon`(run `7124425b`)을 그때 그대로 넣었다.
- 절제 `ablate_*`: own35_ext209에서 장부 `caveats` 부류 하나씩을 뺀 해석용 구성.
  기본 두 전략(`shrunk_rank_logit_logistic`, `rank_logit_logistic`)만 잰다.

## 읽히는 사실

- 자체 35의 한계 기여는 `+0.0000900`(own35_ext209 - ext209)이고, 외부 209의 기여는 `+0.0005062`다.
  외부 폭이 점수의 대부분을 만들지만 자체 풀도 잡음 바닥의 16배만큼 더한다.
- #386 곡선(`증분 ≈ 1.73e-05 × k^0.62`)이 209개에 예측한 값은 `+0.000476`이고 실측은 `+0.000506`이다.
  #442 장부의 새 130개가 #386의 85개와 같은 품질로 폭을 넓혔다는 뜻이다.
- 최선 전략은 구성원 35, 120, 209, 244 어디서도 `shrunk_rank_logit_logistic`이고 2위는 `rank_logit_logistic`(own35_ext209에서 `0.9702987`)이다.
  #337의 "구성원 수가 늘어도 전략 순위가 뒤집히지 않는다"가 244개에서도 성립한다.
  지도의 미결 항목(250개 넘을 때 규제 강도 C와 rank-gauss 변환 추가 여부)에 대해서는, 등록된 `rank_gauss_logistic`이 own35_ext209에서 `0.9702459`로 rank_logit보다 낮아 변환 교체의 근거가 없다.
- 무학습·비음수·능형 계열은 구성원이 늘수록 오히려 내려간다(rank_mean 0.9691 → 0.9674, nnls_rank 0.9692 → 0.9685).
  약한 구성원이 많은 풀에서는 학습된 음수 가중이 필요하다는 뜻이다.
- `greedy_rank_mean`은 244구성원에서 `0.9698822`로 문턱 `0.9699106`에 못 미친다.
  구성원 선택만으로는 폭의 값어치를 못 살린다.

## 절제: 주의 사항 부류별 기여

own35_ext209에서 장부 `caveats` 부류 하나씩을 뺐다.
값은 전체 244 대비 차이다.

| 절제 | 뺀 구성원 | 남은 구성원 | shrunk | rank_logit_logistic |
| --- | ---: | ---: | ---: | ---: |
| 전체(기준) | 0 | 244 | 0.9703167 | 0.9702987 |
| float32 저장 제외 | 49 | 195 | 0.9701935 (-0.000123) | 0.9701717 (-0.000127) |
| 레시피 비공개(weak50) 제외 | 50 | 194 | 0.9702492 (-0.000068) | 0.9702327 (-0.000066) |
| TE 누출 의심 2개 제외 | 2 | 242 | 0.9702876 (-0.000029) | 0.9702760 (-0.000023) |
| 저자 서술만(author_statement) 제외 | 138 | 106 | 0.9699505 (-0.000366) | 0.9699366 (-0.000362) |

- 네 부류 모두 빼면 내려간다. 즉 전부 실제로 기여한다.
- float32 49개는 `-0.000123`으로 정밀도 손실보다 다양성 기여가 훨씬 크다.
- TE 누출 의심 2개(pub_rmlp, pub_tabm)의 기여는 `3e-05` 안팎이라, 조립 단계에서 보수적으로 빼도 판정은 그대로다.
- 가장 보수적인 경우(서술 근거 138개를 전부 못 믿는다면)에도 `0.9699505`로 문턱 `0.9699106`은 넘지만 `0.9702` 목표는 사라진다.
  폭의 약 70%가 서술 근거 구성원에서 온다.
  이 위험은 #442 장부가 이미 기록한 것이고, 라이선스와 행 순서·AUC 재채점은 전부 통과했으므로 사다리 규칙대로 전체 209를 쓴다.

## 한계

- nested OOF는 결합기의 일반화를 재지만 외부 구성원 상류의 분할 준수는 저자 근거에 의존한다(분할 벡터 9개, 코드 61개, 서술 138개).
  만약 어떤 구성원이 검증 라벨을 봤다면 nested가 낙관적일 수 있고, 절제 표가 그 위험의 크기를 보여 준다.
- `shrunk_rank_logit_logistic`의 λ는 fold마다 격자에서 고르므로 재실행 사이에 `7e-06`쯤 흔들릴 수 있다(#386 관찰).
  이번 재현 검사에서는 `1e-08` 차이로 맞았다.
- Public 점수는 판정에 쓰지 않았다.

## 후속으로 넘기는 사실

- 조립 티켓: own35 + ext209, `shrunk_rank_logit_logistic`, 전체 OOF 244열로 결합기를 학습해 시험 예측 244열에 적용한다.
  외부 209의 시험 배열은 장부 `test_path`에 있고 행 수 296,302와 id 순서는 #442에서 검증했다.
  own35 시험 예측을 CV 전용으로 넣을지 5:1 혼합판으로 넣을지, TE 누출 의심 2개를 뺄지는 조립 티켓의 결정이다.
- 지도 미결 항목 가운데 결합기 규제·rank-gauss 추가는 근거가 없어 닫아도 된다.
  regime 융합은 기본 스택이 문턱을 넘었으므로 남는 시간이 있을 때만 검토한다.
