# CNN 공개판과 exp113의 성능 격차 분석

이 문서는 [CNN 공개판과 exp113의 구성 요소·실행 동작 차이 추적](https://github.com/tmheo/predicting-smartphone-addiction/issues/270)의 조사 결과다.
조사 기준 시각은 2026-08-20 JST다.
새 GPU 실행이나 유료 자원 사용 없이 Kaggle 최신 공개 페이지와 공식 API, 내려받은 원문·실행 기록·출력, 저장소 소스·설정, 기존 MLflow 산출물을 직접 대조했다.

## 결론

공개 CNN과 `exp113_tab_cnn_m0`의 같은 행 OOF AUC 격차는 추정치가 아니라 정확히 `0.0056307996`이다.
공개판은 `0.9677056335`, exp113 3시드 평균본은 `0.9620748339`이며 다섯 분할의 격차가 모두 `+0.00537`에서 `+0.00588` 사이로 같은 방향이다.

원인은 CNN 본체의 이식 오류보다 의도적으로 바꾼 입력 계약과 학습 예산에 있다.
공개판은 원시 12열의 정확값 목표 평균·빈도 24열과 행별 파생 26열을 포함한 59열을 쓰지만, exp113은 목표 평균·빈도를 모두 빼고 champion용 복원·조성 피처를 넣은 33열을 쓴다.
두 입력은 이름이 그대로 겹치는 열이 원시 수치 9개뿐이고, 합성곱이 보는 열 순서와 이웃 관계도 크게 달라진다.
따라서 exp113은 공개 처리 경로의 재현판이 아니라 공개 신경망 본체만 현재 피처 계획 위에 올린 구조 대조다.

가장 큰 것으로 식별된 단일 차이는 정확값 목표 평균 입력이다.
저장소의 기존 같은 자료·분할 LightGBM 실행에서 원시 12열 기준 `0.9627593051`이 원시 12열과 내부 OOF 정확값 목표 평균 9열 기준 `0.9662063377`로 `+0.0034470326` 올랐다.
빈도 8열은 목표 평균·잔차 기준 seed 42에서 `+0.0001379721`이었지만 새 피처 관문을 통과하지 못했다.
이 두 수치를 단순히 더하면 관측 CNN 격차의 약 64% 규모지만, 다른 학습기와 다른 피처 기준의 수치이므로 직접 귀속값이 아니라 방향과 크기 자로만 써야 한다.

두 번째 후보는 최대 학습 길이를 100회에서 30회로 줄인 차이다.
공개판의 분할별 최고 상태는 모두 30회 이내에 있었지만, exp113의 15개 시드·분할 최고 상태는 전부 27회에서 30회에 몰렸고 15회째에서 관측 최고점까지의 검증 AUC 상승은 평균 `+0.0012249619`였다.
exp113이 30회에서 학습을 마쳤다고 볼 근거가 약하므로 이 차이는 매우 작은 폭부터 AUC `0.001`대까지 기여할 수 있지만, 기존 산출물만으로 30회 이후의 실제 이득을 정할 수는 없다.

반대로 자료, 분할, 수치 표현, 합성곱, 채널 재가중, 전역 요약, 원시 입력 우회, 손실, 탈락 규제 머리와 최적화 방법에는 격차를 설명할 이식 오류가 발견되지 않았다.
공개 모형과 자체 모형에 같은 상태를 순서대로 넣은 CPU 진단에서 학습 모드와 평가 모드 모두 출력의 최대 절댓값 차이가 `0.0`이었다.
입력 33열일 때 두 모형의 학습 가능 매개변수도 모두 `87,301`개였다.

정밀도와 추론 평균도 공개판의 우위를 설명하지 않는다.
공개 OOF는 서로 다른 예측값이 4,708개뿐이지만, 공개 동률 안을 목표값으로 가장 유리하게 정렬한 이론적 상한도 AUC `+0.0000491961`에 그쳤다.
exp113 예측을 float16으로 양자화한 직접 진단의 AUC 변화는 `-0.0000009607`이었다.
exp113은 OOF에서 세 초기화 평균을 써 개별 초기화보다 약 `+0.0020`에서 `+0.00227` 이득을 얻었으므로 평균 부족도 원인이 아니다.

따라서 현재 증거로는 약 `0.00563`을 "원본 코드보다 같은 CNN이 뒤처진다"고 읽으면 안 된다.
더 정확한 판독은 "동일한 CNN 본체가 서로 다른 59열과 33열 입력 계약, 서로 다른 학습 길이에서 평가됐다"이다.
원본 충실 재현이나 후속 짝비교를 열 가치는 있지만, 우선순위는 CNN 본체 재구현이 아니라 공개 59열 입력 묶음과 100회 학습 경계를 한 변화씩 되돌리는 데 둬야 한다.

### 입력 계약과 열 순서

공개판의 59열은 다음 세 묶음이다.

1. 원시 수치 9열이다.
2. `missing_count`와 합·비율·로그·제곱근 파생 25열이다.
3. 원시 12열 각각의 빈도와 평활 목표 평균 24열이다.

공개판의 원시 수치 열 순서는 `age`, `daily_screen_time_hours`, `social_media_hours`, `gaming_hours`, `work_study_hours`, `sleep_hours`, `notifications_per_day`, `app_opens_per_day`, `weekend_screen_time`다.
그 뒤에는 `missing_count`, `total_breakdown_hours`, `social_ratio`, `gaming_ratio`, `work_ratio`, `unaccounted_screen_time`, `unaccounted_screen_ratio`, `screen_to_sleep_ratio`, `weekend_vs_daily_ratio`, `app_opens_per_hour`, `notifications_per_hour`, `leisure_hours`, `productivity_ratio`, `entertainment_disruption_index`, `screen_intensity_per_unlock`, `notification_distraction_index`, `opens_per_notification`, `sleep_deprivation_index`, `weekly_screen_estimate`, `log_notifications`, `sqrt_notifications`, `log_app_opens`, `sqrt_app_opens`, `log_daily_screen`, `sqrt_daily_screen`, `log_leisure`가 이 순서로 붙는다.
마지막 24열은 앞의 원시 수치 9열과 `gender`, `stress_level`, `academic_work_impact` 순서로 각 열의 `<이름>_freq`, `<이름>_te`가 번갈아 붙는다.

exp113의 33열은 다음 다섯 묶음이다.

1. 원시 수치 9열과 범주 3열이다.
2. `screen_slack`, `sgw_sum`, `slack_frac`, `wk_minus_sgw`, `wk_other`, `sgw_frac` 6열이다.
3. 상시 위약 열 `placebo_noise`다.
4. 제약 복원 4열과 XGBoost 복원 5열이다.
5. 복원 행렬의 조성 5열이다.

exp113은 원시 12열 뒤에 산술 6열, `placebo_noise`, `daily_screen_time_hours_recon`, `social_media_hours_recon`, `gaming_hours_recon`, `work_study_hours_recon`을 차례로 놓는다.
마지막 10열은 `daily_screen_time_hours_xgb_recon`, `social_media_hours_xgb_recon`, `gaming_hours_xgb_recon`, `work_study_hours_xgb_recon`, `weekend_screen_time_xgb_recon`, `imp_social_frac`, `imp_work_frac`, `imp_leisure_frac`, `imp_resid_frac`, `imp_week_total` 순서다.

두 목록의 글자 그대로 같은 열은 원시 수치 9개뿐이다.
공개판의 `total_breakdown_hours`와 exp113의 `sgw_sum`, 공개판의 `unaccounted_screen_time`과 exp113의 `screen_slack`처럼 뜻이 가까운 별칭은 있지만 결측 처리와 분모 처리까지 모두 같은 것은 아니다.

이 차이는 완전연결망보다 합성곱에서 더 중요하다.
합성곱은 목록에서 가까운 다섯 위치에 공유 가중치를 적용하므로 열을 추가·제거·재배열하면 같은 모듈이라도 다른 함수를 학습한다.
[fold 0 진입 진단](tab-cnn-entry-diagnostic.md)에서 exp113 합성곱은 같은 입력·학습 설정의 매개변수 규모 일치 완전연결 대조보다 `+0.0047284574` 높았다.
이 결과는 열 이웃을 쓰는 경로가 실제 성능에 큰 영향을 줬음을 보여 주지만 공개 순서와 자체 순서 중 어느 쪽이 더 좋은지는 분리하지 않는다.

### 목표 평균과 빈도의 차이

공개판은 이름이 `cat_cols`인 목록에 원시 범주 3열만 넣지 않고 원시 12열 전부를 넣는다.
따라서 소수점 수치도 문자열 정확값 단위로 묶여 빈도와 평활 목표 평균을 받는다.
검증·시험 행은 바깥쪽 학습 분할의 통계만 받으므로 검증 목표값이 직접 들어가는 누출은 없다.

다만 공개판의 학습 행 목표 평균에는 그 행 자신의 목표값이 들어간다.
저장소의 정확값 목표 평균 제공자는 바깥쪽 학습 분할 안에서 다시 내부 OOF 값을 만들어 이 자기 포함을 막는다.
공개 동작은 학습과 검증 입력 분포를 다르게 만들므로 원본 충실 재현과 누출 교정 후보를 구분해야 한다.
이 차이의 성능 방향은 정적 분석으로 정할 수 없지만, 정확값 목표 평균 자체의 방향은 기존 누출 교정 실행에서도 강한 양수였다.

기존 1차 실행 기록의 크기 자는 다음과 같다.

| 비교 | OOF AUC 변화 | 해석 제한 |

### 전처리와 수치 표현

두 구현 모두 분위수 변환을 바깥쪽 학습 분할에만 맞추므로 검증 분포를 미리 본 차이는 없다.
공개 코드는 `subsample`을 지정하지 않지만 exp113은 `subsample=None`을 명시해 전체 학습 분할로 분위수 기준점을 만든다.
저장소 실행 환경의 scikit-learn 1.9.0 기본값은 `subsample=10000`이지만 Kaggle 공개 실행은 개별 패키지 판본을 출력하지 않았다.
따라서 공개 실행의 실제 기본값을 Docker 내용 해시만으로 단정하지 않고, 이 축은 방향 미확정 차이로 남긴다.

신경망 안의 수치 표현은 동작까지 같다.
공개 `PiecewiseLinearEmbedding`과 자체 `_PiecewiseLinearEmbedding`은 모두 실제 구간 경계를 만들지 않고 열마다 `ReLU(wx+b)` 12개를 학습한다.
주기 표현도 열마다 6개 학습 주파수·위상에서 sine과 cosine을 만들어 12차원으로 만들고, 두 표현을 붙여 공유 선형층과 Mish로 32차원화한다.

### 합성곱과 읽기 경로의 이식 진단

소스 비교만으로 끝내지 않고 공개 클래스 정의와 자체 `_TabCNN`을 CPU에서 직접 만들었다.
같은 33열 입력에서 상태 사전의 항목 수는 양쪽 모두 38개였고, 항목 순서별 모양이 모두 같았다.
공개 상태를 자체 모형에 순서대로 복사한 뒤 무작위 257행을 통과시키면 평가 모드와 학습 모드 모두 출력이 비트 단위로 같았다.
최대 절댓값 차이는 두 모드 모두 `0.0`이었다.

이 진단은 다음 구성의 실제 연산이 보존됐음을 확인한다.

- 두 번의 1차원 합성곱과 BatchNorm·Mish·탈락 규제 순서가 같다.
- 채널 재가중의 평균 풀링, `128→32→128` 선형층과 sigmoid 순서가 같다.
- 열 방향 평균·최댓값 전역 요약과 변환된 원시 입력 우회가 같다.
- `256+입력 폭→128→64→1`인 읽기 경로의 차원 규칙이 입력 폭 변화에 맞게 보존된다.
- 다섯 탈락 규제 표본의 모형 출력값을 먼저 평균하는 머리 동작이 같다.

공개 59열 모형의 매개변수는 `91,565`개이고 자체 33열 모형은 `87,301`개다.
차이 `4,264`개는 입력 열 26개가 줄면서 열별 표현과 원시 입력 우회 연결에서 줄어드는 수와 정확히 일치한다.
숨은 층 폭이나 읽기 경로가 잘못 줄어든 정황은 없다.

### 손실, 규제와 최적화

두 구현은 학습 목표값에 `y×0.99+0.5×0.01`을 적용하고 `BCEWithLogitsLoss`와 같은 식을 사용한다.
검증 손실에는 평활하지 않은 목표값을 사용하고 상태 선택은 검증 AUC를 기준으로 한다.
별도 자료 증강, 재표본추출, Mixup과 가중 손실은 양쪽 모두 없다.

AdamW의 학습률 `0.002`, 감쇠 `0.015`, 재시작 주기 15회의 코사인 학습률과 최저 학습률 `1e-6`도 같다.
학습 묶음 크기 128과 마지막 불완전 묶음 제거도 같다.
자체 구현의 `zero_grad(set_to_none=True)`와 공개 구현의 기본 `zero_grad()`는 이 격차를 설명할 구조 변화가 아니다.

### 학습 길이와 상태 선택

공개판은 최대 100회와 인내 15회를 쓴다.
공개 실행의 종료 회차는 분할 순서대로 45, 42, 29, 43, 27이고 최고 검증 상태는 30, 27, 14, 28, 11회째다.
즉 공개 59열 입력에서는 최대 길이를 30회로 줄여도 저장된 최고 상태 자체는 같았을 가능성이 높다.

exp113은 최대 30회와 인내 15회를 쓴다.
15개 시드·분할의 최고 상태는 27회 1개, 28회 2개, 29회 7개, 30회 5개다.
어느 실행도 인내 15회로 멈추지 않았고 모두 최대 길이에 닿았다.
두 번째 코사인 주기의 시작인 16회째 이후에도 상승한 결과이므로 exp113 입력 계약에서 30회 제한은 공개판과 달리 활성 제약이다.

15회째 검증 AUC에서 30회 안 관측 최고점까지의 차이는 최소 `+0.0004084362`, 최대 `+0.0024518912`, 평균 `+0.0012249619`다.
이 값은 30회 이후 이득의 추정치가 아니라 학습이 아직 움직이고 있었다는 증거다.
따라서 학습 길이는 2순위 원인이지만 기존 산출물만으로 격차 기여량을 확정하지 않는다.

### 시드와 결정론

공개판은 실행 시작에 NumPy와 PyTorch seed 42를 한 번 고정하고 다섯 분할을 연속 실행한다.
따라서 뒤 분할의 초기화와 학습 묶음 순서는 앞 분할에서 소비한 난수 상태에 의존한다.
exp113은 실행 seed와 학습 행 ID 해시에서 분할별 초기화 seed를 파생하고, 학습 순서용 생성기도 별도로 둔다.

exp113의 seed 42라는 이름은 공개판의 전역 seed 42와 같은 초기화 상태를 뜻하지 않는다.
이는 원본 비트 재현을 막는 차이지만 세 자체 초기화가 모두 `0.95980`에서 `0.96008` 사이이고, 공개판 우위가 모든 분할에서 일정하므로 우연히 나쁜 초기화 하나를 뽑은 설명은 맞지 않는다.

자체 구현은 `torch.use_deterministic_algorithms(True)`, CUBLAS 작업 공간 고정, cuDNN benchmark 비활성, TF32 차단까지 적용한다.
공개판은 cuDNN 결정론만 설정한다.
이 축은 수치 경로를 바꾸지만 기존 동등 단계의 A40 대 A4000 차이 `0.0000573241`과 비교하면 `0.00563`의 주원인으로 보기 어렵다.

### 정밀도와 추론 평균

공개판은 자동 혼합 정밀도 안에서 sigmoid를 계산해 OOF에 저장한다.
공개 OOF 691,369행의 고유 예측값은 4,708개라 동률 비율이 높다.
exp113은 모형 출력값을 float32로 올린 뒤 float64 NumPy sigmoid를 계산해 평균본 689,417개의 고유값을 남겼다.

정밀도 영향의 상한을 확인하기 위해 공개 예측값이 같은 행 안에서만 목표값을 이용해 가장 유리하게 순서를 풀었다.
이 비현실적인 상한에서도 AUC는 `0.9677056335`에서 `0.9677548296`으로 `+0.0000491961`만 올랐다.
exp113 평균 예측을 float16으로 양자화한 더 직접적인 진단은 AUC를 `0.0000009607` 낮췄다.
따라서 저장 정밀도는 관측 격차보다 두 자릿수 이상 작다.

공개 OOF는 각 행을 한 초기화·한 분할 모형이 예측한다.
exp113 OOF는 같은 행의 세 초기화 예측을 확률 공간에서 평균한다.
이 평균은 개별 초기화 대비 약 `+0.0020`에서 `+0.00227`을 이미 회복했으므로 자체판이 평균을 덜 해서 낮다는 설명은 반대다.

시험 예측도 공개판은 5개 분할 확률 평균, 자체판은 3개 초기화와 5개 분할의 15개 확률 평균이다.
공개 점수와 OOF 사이 이동량을 두 모델에 같은 상수로 적용할 수 없는 이유 중 하나지만, 자체 OOF 열세의 원인은 아니다.

후속 실행을 연다면 다음 순서가 가장 적은 실행으로 원인을 분리한다.

1. 공개 59열, 최대 100회, 공개 난수 흐름과 공개 분위수 설정을 고정한 충실 재현으로 `0.9677056335`가 재현되는지 먼저 확인한다.
2. 충실 재현에 실패하면 입력 열별 해시, 분위수 변환 표본추출, 첫 분할 초기 상태와 첫 학습 묶음 순서를 비교하고 원인 귀속을 멈춘다.
3. 충실 재현에 성공하면 공개 59열은 유지하고 학습 행 목표 평균만 내부 OOF 방식으로 바꿔 자기 포함 교정의 비용을 잰다.
4. 그다음 목표 평균·빈도 24열만 제거해 공개 행별 파생 35열의 성능을 잰다.
5. 별도 짝비교에서 exp113 33열을 유지하고 최대 길이만 30회에서 100회로 늘려 학습 예산 몫을 잰다.
6. 마지막으로 입력 순서만 고정 순열하거나 합성곱 제거 대조를 붙여 공개 열 이웃과 자체 열 이웃의 효과를 분리한다.

충실 재현은 공개 OOF에서 절대 AUC `0.0002` 안과 다섯 분할 같은 방향을 최소 수용 범위로 두는 것이 타당하다.
이 범위를 넘기면 피처 제거 결과보다 환경·난수 재현 실패를 먼저 해결해야 한다.
원본 학습 행의 자기 포함 목표 평균은 후보 풀 채택판에 그대로 쓰지 말고 원인 확인용 재현과 누출 교정판을 분리해야 한다.

## 최종 판정

현재 자료로는 RealMLP 사례와 같은 수치형 어휘 붕괴나 신경망 본체 이식 결함은 발견되지 않았다.
대신 exp113이 애초에 공개 CNN의 전체 처리 경로를 재현하지 않았다는 사실이 격차의 중심이다.
[구현·진입 진단 결정](https://github.com/tmheo/predicting-smartphone-addiction/issues/177)은 목표 평균·빈도를 빼고 champion 피처 계획을 공유하는 것을 명시했고, [3시드 확정 재검증](tab-cnn-confirmation.md)은 그 구조를 다양성 후보로 평가했다.
두 결정은 목적에 맞게 수행됐지만 공개 OOF와의 절대 성능 재현 질문에는 답하지 않는다.

원본 충실 재현 또는 단일 변화 통제 실험을 열 가치는 있다.
첫 질문은 CNN 코드를 다시 쓰는 일이 아니라 공개 59열 입력과 100회 학습을 같은 자료·분할에서 복원하면 `0.00563` 가운데 얼마가 돌아오는지 확인하는 일이다.
그 결과가 확인되기 전에는 공개 점수를 근거로 exp113의 후보 풀 판정을 뒤집거나 공개 OOF를 후보 풀에 넣지 않는다.
