# 분할 적합 8차원 잡음 제거 잠재 표현의 CatBoost·Lookup 경로 판정

이 문서는 GitHub 이슈 [#483](https://github.com/tmheo/predicting-smartphone-addiction/issues/483)의 구현과 판정 결과를 기록한다.
후보는 이슈 #476이 연 단일 고정 구현이며, 결과를 보기 전에 고정한 후보 정체성, 정보 경계, 두 소비 학습기, 진입·중단 조건과 판정 순서를 그대로 따랐다.

## 결론

- CatBoost 경로(`exp206_issue483_cat_exact_cats_dae8` = exp070 + 잠재 8열)는 2단계 진입 진단의 두 경로를 모두 충족하지 못해 기각했다.
  난수 42 짝비교 -0.0001623(분할 0/5), 최근접 구성원 exp070과 스피어만 순위 상관 0.9990이다.
- Lookup 경로(`exp207_issue483_lookup_bivariate_plr5_initavg8_dae8` = exp156 + 잠재 8열)는 2단계 경로 1(난수 42 짝비교 -0.0000286)은 미달, 경로 2는 난수 42 기준 진입 하한·중복 조건을 통과하고 자체 35개 예비 포함 nested 기여 +0.0000007(경계 기여, 분할 4/5)로 3단계에 올랐다.
  3단계에서 champion 교체는 미달(시드 평균본 -0.0000203, 시드별 0/3, 분할 0/5, 잠재 8열 순열 중요도 전부 플라시보 미달)이고, 후보 풀 진입은 3시드 평균본이 exp157(스피어만 0.99916)과 exp131(0.99833) 둘과 중복이라 일반 등록이 거부됐으며 어느 하나를 원자 교체해도 결과 풀이 중복 불변식을 만족하지 못해 판정 불가로 종료했다.
- 두 경로 모두 자체 후보 풀에 등록되지 않았으므로 외부 포함 313개 판정은 수행하지 않았다.
- champion과 후보 풀 `artifacts/pool.yaml`은 바꾸지 않았다.
- 명세대로 구조, 잡음 비율, 입력 범위와 학습 종료 규칙은 결과를 본 뒤 바꾸지 않았다.

## 구현

- `src/pipeline/denoising_autoencoder.py`: fold-fit 컬럼 제공자 `dae_latent`(산출 열 `dae8_z0`~`dae8_z7`).
  각 바깥쪽 분할의 학습 행만으로 수치 최솟값·최댓값과 범주 어휘를 맞추고, 열 단위 10% 가림 잡음과 `d -> min(256, max(64, 2d)) -> 32 -> 8` 대칭 구조를 AdamW(학습률 0.001, 가중치 감소 0.00001), 묶음 4096, 최대 100회로 학습한다.
  학습 종료 시점은 목표값을 보지 않는 고정 90:10 내부 분할의 재구성 손실(patience 10, min_delta 0)로 정하고 최선 상태를 복원한다.
  난수는 후보 실행 난수에서 역할별(내부 분할, 섞기, 잡음 마스크, 가중치 초기화)로 결정적으로 파생해 적합 계보에 기록한다.
- 명세가 정하지 않은 세부는 다음처럼 고정했다.
  수치 열 블록은 `[학습 행 눈금으로 0~1 변환한 값(결측은 0), 관측 표시]` 두 칸이고 학습 행 밖의 값은 자르지 않는다.
  범주 열 블록은 학습 행 어휘의 원-핫이며 결측과 처음 보는 값은 전부 0이다.
  수치 손실은 관측 셀의 평균제곱오차, 범주 손실은 알려진 값의 교차엔트로피이고 원래 열별 같은 비중으로 평균한다.
  내부 검증 손실은 파생 난수로 한 번 만든 고정 잡음 마스크 위에서 잰다.
- 전체 자료 재학습 경로는 `enter_full_data_fit` 신호를 받으면 내부 분할 대신 다섯 바깥쪽 분할 학습 횟수의 중앙값을 `full_data_epochs`로 요구한다.
- `pipeline.plan`은 제공자의 적합 계보(학습 횟수, 손실, 파생 난수)를 `fold_feature_reuse.json`의 `fit_evidence`로 남긴다.
  fold-fit 재사용 결과는 같은 환경의 두 소비 학습기가 공유한다.
- 판정 기록은 `scripts/diagnose_dae_latent_integrity.py`(1단계)와 `scripts/judge_issue483_pair.py`(2·3단계 짝비교)가 만든다.

## 1단계 무결성 진단

난수 42, 바깥쪽 분할 0에서 정식 피처 계획으로 자동부호화기를 두 번 맞췄다.
로컬 CPU(단일 스레드)와 Vast.ai RTX 3090(CUDA) 모두 다음 검사를 통과했다.

- 행 정렬과 분할 계보: 학습·시험 행 잠재값 인덱스가 원본과 같고 검증 행이 커밋된 `folds.parquet`(`5f5d09e9…`)과 같다.
- 유한성: 학습·시험 행 잠재값 전부 유한.
- 비퇴화: 잠재 8열의 학습·검증·시험 행 표준편차가 모두 0보다 크고 열 간 최대 절대 상관이 0.999 미만.
- 금지 입력 미사용: fit이 받은 열이 `[id] + 선언 입력 12열`뿐이고(목표값 없음) 행 식별자 집합이 바깥쪽 학습 행과 정확히 같다. 변환은 행 단위다(학습 행만 변환한 결과가 전체 변환의 학습 행과 같다).
- 반복 일치: 전처리 상태, 학습 종료 시점, 학습·시험 잠재값 해시가 두 실행에서 같다.
- 평균 입력 복원보다 나은 내부 재구성 손실.

| 환경 | 선택 학습 횟수 | 실행 횟수 | 내부 검증 손실 | 평균 입력 복원 손실 | 적합 시간 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 로컬 CPU | 51 | 61 | 0.035279 | 0.284259 | 30초 |
| Vast.ai RTX 3090 | 97 | 100 | 0.033570 | 0.284259 | 155초 |

입력 차원은 26(수치 9열 × 2 + 범주 원-핫 3 + 3 + 2), 은닉 64, 병목 32, 잠재 8이다.
두 소비 학습기의 분할 0 예측은 각 confirm 실행의 분할 0 완료로 유한성과 행 정렬을 확인했다.
근거는 `issue483-dae-latent-evidence/stage1-integrity-local-cpu.json`과 Vast 결과 묶음의 `results/stage1/dae_integrity.json`이다.

## 2·3단계 Lookup 경로

exp207 3난수 confirm은 Vast.ai RTX 3090 ×4에서 시드 병렬(GPU 3장)로 실행했다(main MLflow run `e36c7ac6`, 원격 run `c5e7f540`→v2/v3 재실행, 커밋 `5a54a1c`).

## 계산 자원과 비용

- 로컬: exp206 confirm 3난수 약 70분, exp070 난수 42 재현 약 23분, 1단계 진단 약 5분.
- Vast.ai(exp207 3난수 confirm, 4×RTX 3090 시드 병렬, 총 약 $8.6, 최종 잔액 $3.05):
  - v1 인스턴스 `48961264`(캐나다, 장비 43178, $0.70/h, 약 $2.70): 다른 사용자의 GPU 프로세스가 4장 전부에서 100%를 점유해 fold 1부터 속도가 절반 이하로 떨어졌다. fold 0 복구 자료 3개를 회수한 뒤 정리하고 장비를 제외했다.
  - v2 인스턴스 `48978653`(뉴질랜드, 장비 54514, $0.71/h, $4.62): 외부 GPU 부하 관문(프로세스 0개, 사용률 0)을 추가해 통과했고 fold 0 복구 자료로 fold 1부터 실행했다. 로컬 네트워크 단절 뒤 재개한 제어 스크립트가 중간 복구 회수 파일 이름 충돌로 중단되며 fold 4 순열 중요도 단계의 인스턴스를 정리했다(제어 결함). fold 0~3 복구 자료 12개는 회수했다.
  - v3 인스턴스 `49014350`(같은 뉴질랜드 장비, $1.32): fold 0~3 복구 자료를 반입해 fold 4만 실행하고 결과 묶음(SHA-256 `4fed3d07…`)을 회수했다. main MLflow 반입·예측 무결성 감사를 통과했고 인스턴스·저장 공간·종료 예약 부재를 확인했다.
  - 수동 종료 상한은 120회 학습을 GPU 3장에 나눠도 약 9시간이 걸려 12시간으로 잡았고, GitHub Actions 종료 예약을 안전판으로 뒀다.
  - 장부는 `run-logs/vast-issue483/ledger.md`(미추적)에 있다.
