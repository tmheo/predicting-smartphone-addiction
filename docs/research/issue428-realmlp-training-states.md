# Muon RealMLP 8회 일정 학습 상태 확정 결과

이 문서는 GitHub 이슈 [Muon RealMLP 8회 일정에서 1·2·3회 후보를 확정 실행한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/428)의 Vast.ai 실행, 복구 전용 게시, 중앙 MLflow 반입과 자원 정리 근거를 기록한다.
직렬 nested OOF 판정과 후보 풀 등록은 후속 이슈 [두 신경망 학습 상태 대조축을 직렬 nested OOF로 판정해 최대 2개를 등록한다](https://github.com/tmheo/predicting-smartphone-addiction/issues/425)의 범위이므로 이 문서에서는 수행하지 않는다.

## 고정 계약

원격 실행 커밋은 `2f5c4e832161844a9d206c53d051f07ee034b5dd`이고 확정 단계, 난수 42·43·44, 고정 5분할을 사용했다.
각 난수와 분할 조합은 `exp134_realmlp_muon`의 입력, 초기화 방식, 나머지 설정과 8회 학습률 일정 지평을 유지한 4회 물리 궤적 하나만 학습했다.
각 궤적의 두 초기화 구성원에서 사전 고정한 1·2·3회 EMA 상태를 추출했다.
상태 선택에는 검증 목표값을 사용하지 않았고 후보 순서도 결과를 보기 전에 1·2·3회로 고정했다.
궤적 식별 SHA-256은 `36c9f12c7c6281a1fbc8b409e3c663240913be0f49744f5aef60d6176b5d7b9c`이고 후보 집합 SHA-256은 `b257671049476bb6a1f9303c953ad0adc94b21c9b8a381a2e9b6ca21f14a623f`이다.
훈련 자료, 시험 자료와 고정 분할의 SHA-256은 각각 `f4669147311c76eb03496061a852af283efcf0f12cf5c19274e775def81edd9c`, `8b462dd47fe8165cd0b082bf33b56523c5811453070af48b9f86b2eb928de49e`, `5f5d09e9356f227ecb4a063270b175bb5cae20afb25636c563db185e18a155c4`다.
1·2·3회 설정 SHA-256은 차례로 `c1bd8fb69598d06de3762c3d1a09ac12cb190a78338b1109f2006ca79706e342`, `a18a7dfbc7061eacdf4b94fa3b3a1ca0de45d713d41af589e0d91c0c5330667b`, `a900d5390c81ad809dbeeb0f331fe3dc02490ba1edfd436422500b22c03fad8e`다.

## 실행 경로 보강

첫 Vast.ai 시도는 첫 번째 분할 학습을 마친 뒤 `training_state.trajectory_fit` 관측 작업이 고정 목록에 등록되지 않은 오류로 끝났다.
[관측 작업 등록과 회귀 검사](https://github.com/tmheo/predicting-smartphone-addiction/pull/436)를 본선에 합친 뒤 같은 실행 계약으로 다시 시작했다.
두 번째 시도는 난수와 분할 조합 15개를 모두 학습하고 상태 자료 45개를 남겼지만, 적용되지 않은 새 특징 계획에서 열 목록을 읽는 집계 오류로 후보 게시 전에 끝났다.
집계 수정 커밋 `e334a4f465c408171cedc9a1e557428d7caf3d03`은 이미 준비된 특징 열 목록을 집계에 전달하고 세 난수 결과를 모두 검사한다.

## GPU 없는 게시 재개

원본 결과 압축 SHA-256 `105de4ddc4c45af0cb1786c92e9ec928da0fdf1e282d37a33db4e29e5871d3df`와 원본 MLflow 데이터베이스 SHA-256 `39abbed023029a8d78136e45ca4bf0908f0067e2a6b8fb6e40d38402b5cf35f2`를 게시 전에 다시 확인했다.
원본 MLflow 데이터베이스의 부모 실행 `411f7488554541f3a8d82201647432c7`은 실패 상태로 그대로 보존했다.
별도 MLflow 복제본에서 원본 압축, 자료, 실행 커밋, 입력, 궤적, 후보 집합, 난수와 분할 좌표를 다시 확인한 뒤 기존 복구 자료만 집계했다.
게시 과정에서는 모델 생성 경로를 강제로 차단했고 15개 좌표가 모두 재사용됐으며 새 모델 학습과 새 GPU 자원 사용은 각각 0회였다.
복제본의 부모는 완료 상태로 전환하고 세 자식 실행에는 원본 부모 실패 상태, 원본 커밋 `2f5c4e832161844a9d206c53d051f07ee034b5dd`, 집계 수정 커밋 `e334a4f465c408171cedc9a1e557428d7caf3d03`, 게시 커밋 `a4055109114008f40dd4e27710da6fcc90fb070a`와 원본 자료 해시를 함께 남겼다.

## 반입과 무결성

복구 전용 실행 묶음 세 개를 모두 중앙 MLflow에 반입한 뒤 감사를 시작했다.
각 실행은 완료 상태, 고정 커밋, 입력 해시, 확정 단계, 세 난수, 공통 부모 궤적, 사전 고정 상태 manifest와 복구 전용 계보 검사를 통과했다.
OOF 재채점은 기록 지표와 `1e-9` 이내, 대표 OOF는 난수 42·43·44 예측 평균과 `1e-12` 이내인지 검사했고 이번 결과의 차이는 모두 0이었다.
시험 예측과 제출 파일의 식별자 순서와 값도 일치했고 각 후보의 특징 중요도 195행은 모두 유한했다.
1·2·3회 OOF와 시험 예측의 내용 SHA-256은 후보별로 서로 달라 같은 예측을 잘못 복제하지 않았음을 확인했다.
세 실행 묶음의 SHA-256은 차례로 `25aacbe8e4e4ee325783029d2c44a82743f68f2fc81ea42926eafa2ea8a56723`, `7876777d568183ad440901f628432fbed5c683c06e8492c9fdaef677bf08622a`, `deeb3f2f811caf7a25a1c92ad8c21748e3c5b28180d6f08078ec61e23fa52ba2`다.
