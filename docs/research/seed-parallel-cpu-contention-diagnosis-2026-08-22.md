# 3시드 3 GPU 첫 폴드 CPU 경합 진단

## 질문

Vast.ai 한 머신에서 시드 42, 43, 44를 GPU 3장에 나눠 실행할 때 폴드 사이 CPU 구간이 10분 이상 걸린 원인을 확인한다.
복구할 때 완료된 폴드 계산을 반복하던 문제와 새 폴드 계산 자체가 느려지는 문제를 구분한다.

## 환경과 방법

- 커밋: `ecea8c1a10715946620a99dce5bc109d0e3852c2`
- 설정: `configs/exp113_tab_cnn_m0.yaml`
- 자료: 실제 대회 train, test와 고정된 5폴드 파일
- 장비: RTX 5060 Ti 4장, AMD EPYC 7K62, 표시 CPU 192개, cgroup 할당량 92.16개
- GPU 사용: GPU 0, 1, 2에 실제 표 합성곱망 1회 짧은 학습을 각각 배정해 모두 통과
- 측정 대상: 시드 42, 43, 44의 폴드 0에서 실제 `ConstrainedImputeAux`와 `XgbImputeAux` fit 및 transform
- 비교 조건: 순차 기본값, 3시드 동시 기본값, 3시드 동시 실행에 작업당 CPU 30개 제한

전체 5폴드 모델 학습을 반복하지 않고 문제가 발생한 실제 첫 폴드 피처 계산 경로만 실행했다.
세 조건은 같은 인스턴스, 같은 입력, 같은 판본에서 실행했다.

## 결과

| 조건 | 세 시드 첫 폴드 벽시계 시간 | 시드별 피처 시간 | 기준 대비 |
|---|---:|---:|---:|
| 순차 기본값 | 139.54초 | 45.29초에서 46.54초 | 기준 |
| 3시드 동시 기본값 | 2,138.70초 | 2,133.82초에서 2,137.85초 | 순차 한 시드 최댓값의 45.96배 |
| 3시드 동시 CPU 30개 제한 | 70.06초 | 68.09초에서 69.47초 | 제한 없는 동시 실행보다 96.72% 단축 |

제한 없는 조건에서 각 워커는 OpenMP 작업 흐름 192개와 전체 작업 흐름 227개를 만들었다.
세 워커가 실제 CPU 할당량 92.16개를 두고 약 681개 작업 흐름으로 경쟁했다.
`ConstrainedImputeAux` fit은 시드당 약 45초였지만 `XgbImputeAux` fit은 시드당 약 2,079초에서 2,084초가 걸렸다.
따라서 35분 38.7초 지연의 거의 전부는 병렬 워커마다 머신 전체 CPU 수를 사용한 XGBoost 복원기에서 발생했다.

모든 작업 흐름을 전역으로 30개로 제한하면 `XgbImputeAux` 산출 해시는 순차 기준과 시드별로 정확히 같았다.
그러나 `ConstrainedImputeAux` 산출 해시는 달라졌다.
따라서 전역 작업 흐름 제한은 정확 동등성 규칙을 통과하지 못했다.

제품 수정은 시드 병렬 워커가 `XgbImputeAux`에 전달하는 `n_jobs`만 제한한다.
표시 CPU 수, CPU 실행 허용 집합과 cgroup v1 또는 v2 할당량 중 가장 작은 값을 동시 워커 수로 나눈다.
순차 실행과 `ConstrainedImputeAux`의 BLAS 작업 흐름 수는 바꾸지 않는다.

원격 실행에서 제한된 XGBoost 산출 해시는 시드 42, 43, 44 모두 순차 기준과 정확히 같았다.
제품 수정 뒤 로컬 실제 폴드에서 전역 제한 없이 XGBoost만 작업당 CPU 4개로 제한한 3시드 동시 실행을 추가 확인했다.
시드 42의 두 제공자 train 및 test 산출 해시는 순차 기준과 모두 정확히 같았고, 세 워커는 약 78초에 끝났다.

## 복구 문제와의 관계

복구 지연은 별개의 문제다.
현재 `execute_seed`는 모든 폴드의 복구 파일을 먼저 읽고 완료된 폴드를 판별한 뒤, 하나라도 빠진 폴드가 있을 때만 공통 피처 준비를 수행한다.
완료된 폴드는 fold-fit 제공자 계산과 모델 학습을 모두 건너뛴다.
부분 복구와 전체 복구에서 빠진 폴드 작업만 수행한다는 회귀 시험도 유지된다.

따라서 현재 결론은 다음과 같다.

- GPU 1장으로 시드를 순서대로 실행하면 이번 10분대 CPU 경합은 발생하지 않는다.
- GPU 3장 병렬 실행은 새 폴드의 XGBoost 복원기에 CPU 몫을 나눠 주어야 한다.
- 완료된 폴드를 복구하면서 CPU 피처를 다시 계산하던 이전의 약 1시간 지연은 이미 제거됐다.

## 원격 실행과 정리

첫 인스턴스 `48398380`은 계산 시작 전 cgroup 기록 경로가 v2로만 고정된 진단 프로그램 오류로 종료했다.
오류를 v1과 v2 겸용으로 고친 뒤 인스턴스 `48399094`에서 유효한 비교를 한 번 수행했다.
두 인스턴스의 잔액 감소 합계는 `$0.489485220`이었다.
유효 결과 묶음 SHA-256은 `f762652d8457f4456d52a23a3256e99404792a059f10216a14d75370dc66bf9b`이다.
두 인스턴스와 작업 전용 저장 공간이 모두 없고, 두 번째 실행의 외부 종료 일정도 제거된 것을 확인했다.
기존의 다른 작업 종료 일정은 변경하지 않았다.
