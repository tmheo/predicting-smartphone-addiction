# 이슈 388 일괄 생산 후보 선택 절차 대조

## 결론

이슈 387에서 넘긴 후보 7개 가운데 `exp144_issue387_xgb_trial6` 하나만 `candidate-pool-v1` 선택 절차 대조를 통과했다.
첫 직렬 대조의 nested OOF AUC는 기준 풀 `0.969742394795`에서 선택 절차 포함 `0.969769351339`로 `+0.000026956544` 높아졌다.
이 차이는 성능 동등 대역 상한 `+0.000027669802` 안의 경계 기여지만, 현행 계약은 엄격한 양수 차이면 등록을 허용한다.
바깥 분할 다섯 곳 모두 `exp144_issue387_xgb_trial6`과 `shrunk_rank_logit_logistic`을 골랐고 다섯 차이가 전부 양수였다.

`exp144_issue387_xgb_trial6`을 등록한 뒤 남은 후보 6개를 갱신된 33개 풀에서 다시 평가했다.
두 번째 대조는 기준 풀 `0.969769351339`에서 선택 절차 포함 `0.969764221372`로 `-0.000005129967` 낮아졌다.
양수 분할은 한 곳뿐이었고 바깥 분할별 선택 후보도 세 설정으로 갈려 추가 등록을 중단했다.
최종 후보 풀은 33개이며 실제 등록 수는 1개다.

## 판정 절차

입력 후보는 이슈 387에서 직접 진입 하한과 중복 검사를 통과한 7개로 고정했다.
후보 풀, folds, 기본 결합 방식 19개와 후보 입력 순서를 각 직렬 대조 시작 시 내용 해시로 동결했다.
전체 OOF에서 후보 포함 풀의 최선 점수를 비교한 값은 해당 직렬 단계에서 등록할 후보 하나를 정하는 참고 선택에만 썼다.
채택 판정은 바깥 분할마다 학습 부분의 OOF만으로 후보와 결합 방식을 다시 고르고, 그 결과를 검증 부분에 적용해 이어붙인 nested OOF AUC로 내렸다.
후보 하나가 통과하면 그 후보만 풀에 등록하고 남은 후보는 갱신된 풀을 다시 동결해 같은 절차를 반복했다.

첫 실행은 학습 자료를 다른 작업 트리의 파일로 연결한 심볼릭 링크가 저장소 밖 경로로 해석돼 계산 전에 거부됐다.
이 입력 검사는 의도대로 작동했으며 실패 기록 `issue388-bulk-selection-1`을 덮어쓰지 않았다.
같은 바이트의 학습 자료를 현재 작업 트리에 둔 뒤 새 판정 ID로 다시 실행했다.

## 두 번째 직렬 대조

남은 후보 6개의 전체 OOF 참고 선택은 `exp151_issue387_cat_trial3`이었다.
바깥 분할의 학습 부분은 fold 0에서 `exp151_issue387_cat_trial3`, fold 1에서 `exp153_issue387_logreg_raw_l1`, fold 2부터 4까지 `exp154_issue387_logreg_nn1_nn10_l1`을 골랐다.
이 차이는 결과를 본 뒤 하나의 고정 후보를 사후 정해 직접 포함 대조하면 안 되는 이유를 보여 준다.

전체 차이는 `-0.000005129967`이고 분할 승수는 `1/5`다.
선택 절차 전체가 양의 기여를 확인하지 못했으므로 남은 6개는 모두 미등록으로 확정했다.

## 전체 자료 재학습 계획

등록된 `exp144_issue387_xgb_trial6`의 3시드 × 5분할 적합 15개는 모두 `best_iteration=9999`에서 설정 상한에 닿았다.
원시 값은 0부터 세는 위치이므로 관측 학습 길이는 모두 `10000`이다.
시드별 중앙값 `10000`에 현행 배수 `1.25`를 적용해 재학습 예산을 시드 42, 43, 44 모두 `12500`으로 고정했다.
