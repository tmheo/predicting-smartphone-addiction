# Vast.ai 작업용 키 권한 재검증 보고서

## 배경

2026년 8월 16일 GitHub 이슈 [#143](https://github.com/tmheo/predicting-smartphone-addiction/issues/143)의 원격 실행 준비 중 기존 일상 실행 키가 SSH 공개 키 등록에는 성공하고 삭제에는 실패했다.
공식 `vastai` v1.5.4와 직접 REST 삭제가 모두 `api.ssh.key` 경로 권한 부족으로 401을 반환했다.
등록값을 웹 화면에서 삭제하고 인스턴스와 저장 공간이 0개임을 확인한 뒤 작업용 API 키 권한을 다시 구성했다.

API 키, SSH 개인 키, 실제 SSH 접속 주소와 원문 API 응답은 이 보고서에 남기지 않았다.

## 최종 권한 구성

Vast.ai [공식 권한 문서](https://docs.vast.ai/api-reference/permissions)는 SSH 공개 키 생성·수정·삭제를 `user_write` 범주에 둔다.
일상 실행 키에는 기존 다섯 범주와 `user_write` 안의 SSH 키 두 경로만 허용했다.

```json
{
  "api": {
    "misc": {},
    "user_read": {},
    "billing_read": {},
    "instance_read": {},
    "instance_write": {},
    "user_write": {
      "api.ssh.keys": {},
      "api.ssh.key": {}
    }
  }
}
```

`user_write` 전체 권한, `user_write`의 다른 경로, `billing_write`, 공급자 관리와 팀 관리 권한은 부여하지 않았다.
SSH 경로를 최상위 `*` 안에 두거나 `DELETE` 메서드를 그 경로에 직접 적는 두 구성은 삭제 권한을 주지 못했다.
경로를 `user_write` 범주 안에 제한해 넣은 구성이 등록과 삭제를 모두 통과했다.

## SSH 공개 키 왕복 검증

작업별 Ed25519 공개 키 내용을 명령줄 도구에 직접 전달했다.
등록 뒤 계정 목록에서 로컬 공개 키와 정확히 일치하는 항목이 하나뿐임을 확인했다.
같은 작업용 API 키로 SSH 공개 키 `1226868`을 삭제했고 계정 목록이 0개임을 재확인했다.
같은 공개 키를 `1226869`로 다시 등록하고 정확한 일치를 확인했다.

## 전체 수명주기 재검증

매물 `35674412`, 장비 `69161`의 RTX A4000 인스턴스 `47844037`을 공식 명령줄 도구로 만들었다.
시간당 총액은 `$0.1105185185`였고 별도 저장 공간은 만들지 않았다.
`running` 상태에서 고정 호스트 키와 작업용 개인 키를 사용한 실제 SSH 인증을 통과했다.
입력 묶음을 SSH 표준 입력으로 전송하고 양쪽 SHA-256 `8f5358b760bc07190ee464cb86aba70832c035ee489032347357be62abde3c6a`의 일치를 확인했다.
결과 묶음을 SSH 표준 출력으로 회수하고 양쪽 SHA-256 `8640ab509b12d082bf463991fb77dd4bf8b2d0c4a3be2d2de54be2f1c6d0434a`의 일치를 확인했다.

인스턴스 삭제 뒤 계정 소유 인스턴스와 저장 공간이 각각 0개임을 확인했다.
작업용 SSH 공개 키 `1226869`를 새 작업용 API 키로 삭제하고 목록이 0개임을 다시 확인했다.
GitHub 보조 종료 일정도 제거해 구성 변수의 일정이 0개가 됐다.
시작 잔액 `$15.370796682979009`와 종료 잔액 `$15.259105993379006`의 차이는 약 `$0.111691`이다.

## 판정

제한한 `user_write` SSH 경로를 포함한 새 일상 실행 키가 등록값 정확성, 삭제 권한 왕복, 실제 SSH 인증, 입력·결과 전송과 인스턴스 삭제를 모두 통과했다.
이 권한 구성을 일상 실행 키의 새 기준으로 사용한다.
